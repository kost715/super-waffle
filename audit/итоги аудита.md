# Итоги аудита Arma LifeSim (оригинал) 0.14.0

> Файл лежит в отдельной папке `audit/` вне `addons/`, `tools/`, `tests/`, `docs/` и корня релиза. Сборщик (`tools/build.py`) его не упаковывает, на PBO, архивы, тесты и мод он не влияет. Это справочник по устройству **оригинального** мода; код аддона PMC здесь упоминается только как потребитель оригинала. Поиском ошибок этот документ не занимается.

## Как читать

- **Объект аудита:** `als_main.pbo` LifeSim **0.14.0** (open beta, сборка 261022.2035), распакованный из присланного архива. Для сравнения — 0.13.0 (SHA-256 PBO `b2d00094…`).
- **Факт** = прочитано в коде (указаны функция/файл). **Гипотеза / проверить в игре** помечено отдельно. Ничего без пометки не предполагается.
- **Охват** — в таблице ниже: что прочитано построчно и что известно лишь по автоматическому индексу. Разделы, помеченные «в очереди», **не аудированы**, и утверждений о них в документе нет, кроме строк индекса.
- Автоматический индекс (скрипт регулярных выражений по исходникам): 956 функций, 37 576 строк, 1055 глобальных `ALS_*`, 145 ключей БД, 864 вызова `remoteExec`. Он эвристический и **не является доказательством**; выжимка — в приложении.
- «0.13.0»/«0.14.0» — версии оригинала, «0.6.x» — версии аддона PMC.

## 1. Архитектура мода

### 1.1 Упаковка
- Один мод `@Arma LifeSim (Open Beta!)`, один PBO `als_main` (префикс `als_main`), подпись `alephwithbet_lifesim.bikey`, папка `keys/`. Лицензия: приватные серверы для знакомых; публичные и «комьюнити»-серверы запрещены (`SERVER_GUIDE.md`, `LICENSE.txt`).
- Внутри PBO: `config.bin`, `XEH_preInit.sqf`, `XEH_postInit.sqf`, `fnlist.sqf`, `functions/` (954 файла `fn_*.sqf`, 37 576 строк вместе с XEH), `ui/` (HTML-страницы окон, ~50 МБ с превью и иконками), `i18n/` (`ru.json`, `extra_en.json`), `missions/` (79 готовых миссий по картам; `description.ext` одинаков у всех), `sounds/`, `data/`.
- `config.bin` содержит: `CfgPatches`, `ALS_RscPhoneWeb` (наследник `RscWebBrowser`), `ALS_Factions` (роли Police, Military, Opfor, Paramedics, Gangs; у каждой может быть вложенный `WithMods`), `ALS_Goods`, `ALS_Recipes`, `ALS_Licenses`, правки `CfgWeapons`, `ALS_Furniture`, `ALS_Heat`, `ALS_Weapons`, `Extended_PreInit/PostInit/DisplayLoad_EventHandlers` (CBA XEH), `CfgMissions` (список миссий).
- **Нет `CfgFunctions`.** Функции регистрируются самим модом при старте (см. 1.2).
- **Нет `CfgRemoteExec`** ни в `config.bin`, ни в `description.ext` миссий (проверено поиском по бинарнику и текстам) — поведение сети см. 1.6.
- Версия: функция `ALS_fnc_build` возвращает `["0.14.0", "", "261022.2035", true]` (имя, канал, сборка, release-флаг). Канал пустой → HUD не показывает «beta»-строку.
- Миссия (`description.ext`): `respawn = 3` (базовое), `respawnDelay = 10`, `respawnOnStart = -1`, `disabledAI = 1`, `joinUnassigned = 1`, `saving = 0` (сохраняется собственной БД, а не Arma-сейвом: «возобновлённый Arma-сейв пропускал весь запуск»), `Header: Coop, minPlayers 1, maxPlayers 4`, `skipLobby = 1`, брифинг/дебрифинг выключены. Для чужих карт достаточно «любой миссии при загруженном моде».

### 1.2 Реестр функций (главное для патчей и обёрток)
- `fnlist.sqf` — литерал-массив из имён (954). `XEH_preInit.sqf` определяет `ALS_fnc_compileAll`: для каждого имени `missionNamespace setVariable ["ALS_fnc_" + имя, compile preprocessFileLineNumbers "\als_main\functions\fn_<имя>.sqf"]`.
- Следствие: **вызов функции = поиск переменной в момент вызова** (`call ALS_fnc_x`, `remoteExec ["ALS_fnc_x", …]`). Подмена переменной действует мгновенно и для удалённых вызовов. Рекомпиляция в рантайме возможна повторным `call ALS_fnc_compileAll` (в коде отдельно не вызывается).
- **Список `ALS_fnList` — не только каталог, но и источник данных для диспетчеров:** `coopOffers` перебирает `ALS_fnList` и берёт все имена с префиксом `coopJob_`; `jobEv*`, `place*`, `scene*`, `enc*`, `tut*`, `rivalKind*`, `econOn*` ищутся по имени динамически. Поэтому функция `ALS_fnc_coopJob_xxx`, назначенная в `missionNamespace` сторонним кодом, будет вызвана `coopAccept/coopTick/coopEnd/coopAct`, но **не попадёт в предложения** (они строятся только по `ALS_fnList`).
- Диспетчерские семейства (имя = префикс + вид): `coopJob_<escort|heist|rescue|sling>`, `jobEv_<…>` (события на работе), `place_<kind>` (13 видов заведений), `scene_<…>` (21 сцена мирной жизни), `enc_<…>` (встречи), `tut_<карьера>`, `rivalKind_<air|haul|shop>`, `econOn_festival`, `dbMigrate_<n>`.
- В индексе «сиротами» (нет прямых вызовов по имени) остаются только члены этих семейств, `pauseMenu` и `jobEvPractice` (вызываются динамически или из UI).

### 1.3 Последовательность загрузки (`XEH_postInit.sqf`)
Начало: `ALS_ready = false; enableSaving [false, false]`. На клиенте с интерфейсом — язык из `profileNamespace "ALS_lang"` (если не `en`, запускается `trInit`), гимн при первом выборе русского, PFH перевода действий/маркеров (2 с), `startOpen`, `menuClient`, `startHold`. Затем **один `spawn`**:
1. На всех машинах: `scanCatalog` (каталог техники/оружия/одежды из конфигов, логирует «Catalog: 431 vehicles, 772 weapons/gear»), `factions`, `scanMap` (объекты карты, города, аэропорты, здания по классам), `houseTable`, `furnCatalog`, `licInit` (читает `ALS_Licenses` из конфига в хэш `ALS_licenses`).
2. Сервер (`isServer`): `menuWait` (ждёт выбор слота) → `dbInit` → `menuApply` (опции) → `warMap` → `addMissionEventHandler HandleDisconnect` (`playerLeft`, `playerSave`, `worldSave`) → `vehRestore` → `spawn saveLoop` → `ALS_npcSeq/ALS_npcSpots`, `spawn npcLoop` → блок подсистем с `buildStep` (прогресс «Finding the job sites…» и т.д., публикует `ALS_build`): `jobSites`, `marketInit/Publish`, `traderSpots`, `airportInit`, `dealerSpots`, `clothesInit`, `storeInit`, `fishInit`, `huntInit`, `gridInit`, **`lawInit`**, `crimeInit`, `blackInit`, `npcPublish`, `fuelInit`, `furnPrices`, **`houseInit`**, `campRestore`, `spawn leaseLoop`, **`bizInit`**, `spawn bizLoop`, **`lifeInit`**, `siteStaffInit`, `lifeTick`, **`rivalInit`**, **`coopInit`**, `bountyInit`, `pressInit`, `homeInit`, `vehLifeInit`, `spawn fleetLoop`, PFH `bgTick` (2 с), `companyInit`, `npcPublish`, `spawn lifeLoop`, `driveAssistInit`, **`drvInit`**, `storyInit`, `spawn taxiLoop`, PFH `vehLocks` (1 с), PFH `airLifeTick` (5 с), `spawn fuelLoop`, `spawn marketLoop`, `spawn jobLoop`. В конце — `buildStep [100, "Ready"]`.
3. На всех: `ALS_ready = true`, лог `[ALS] Ready`.
4. Клиент (`hasInterface`): `waitUntil !isNull player`; маркеры no-fly зон, топлива (`ALS_fuelMap`); PVEH `ALS_war`, `ALS_warSeen` (→ `warMarkers`), `ALS_jobBoard` (→ `phonePush`, `talkPush`); `warActions`; **`[player] remoteExec ["ALS_fnc_playerLoad", 2]`**; клиентские действия (`npcActions, crateMarkers, npcScroll, crimeActions, rivalActions, coopActions, pressActions, mechActions, vehPushAct`); PFH `uiKeep` (2 с), `kitEnsure` (5 с), `fishClient` (1 с), `ambSound` (2 с); `spawn hudInit`; `houseActions`, `bgActions`; EH `EntityRespawned` (→ `bgActions`, `playerCarry`, `homeRespawn`); `systemChat "Arma LifeSim: Y opens your phone."`.
- Порядок важен: **`ALS_ready` ставится только после того, как сервер выполнил весь блок инициализации**, поэтому всё, что ждёт `ALS_ready` (в том числе `ALSPMC_fnc_postInit` аддона и `playerLoad`), видит готовый мир.
- `XEH_preInit.sqf`: `compileAll`; константы `ALS_saveInterval=300, ALS_startCash=500, ALS_jobBoardSize=24, ALS_marketSpeed=1, ALS_rentRate=0.004, ALS_timeMult=4, ALS_civDensity=0.3, ALS_civCap=1500, ALS_saveVersion=1, ALS_civMax=40`; цвета UI; `ALS_adminUids = ["76561198286895226"]` (uid автора); PVEH клиента `ALS_houseExtra` (добавляет сохранённые дома, которых нет в карте); CBA-кейбинды: **показать/скрыть HUD** (Ctrl+H, `DIK 0x23` + модификатор `[false,true,false]`) и **телефон** (Y, `DIK 0x15`; keyUp открывает `phoneOpen` или закрывает дисплей).

### 1.4 Модель планирования (что в каком контексте исполняется)
Полный автоматический перечень — приложение A.2. Главное:
- **Бесконечные `spawn`-циклы (scheduled, с `sleep`):** `saveLoop` (интервал опции), `lawLoop` (2 с), `jobLoop`, `marketLoop`, `lifeLoop`, `fuelLoop`, `taxiLoop`, `fleetLoop`, `bizLoop`, `leaseLoop`, `npcLoop`, `fishLoop`; клиентские `menuClient`, `startHold`, `hudInit`.
- **CBA PFH (unscheduled):** `coopTick` 3 с; `bgTick` 2 с; `vehLocks` 1 с; `airLifeTick` 5 с; `drvTick` каждые 0,04 с (25 Гц) + ещё PFH `drvInit` 1 с и 0 (`drvOwn`); `driveAssist` 0,25 с; `storyTick` 5 с, `encTick` 1 с, `peopleTick` 20 с, `econTick` 60 с, `festTick` 5/30 с (`storyInit`); `rivalTick` 60 с; `pressTick` 15 с; `bountyTick` 30 с; `companyPublish` 20 с; `homeTick` 5 с; `vehTick` 10 с; клиентские HUD 0,25 с, `uiKeep` 2 с.
- **События:** `EntityKilled` (`lawKilled` из `lawInit`; ещё обработчик из `drvInit`), `HandleDisconnect` (в `XEH_postInit` и в `coopInit`), `EntityRespawned` (клиент), `Draw3D` (HUD-метки, аэродромы, ящики, рыбалка), ACE `ace_medical_woundReceived` (из `lawInit`).
- **`lawLoop` — «шина» для всего мира:** каждые 2 с вызывает `lawTick, cpTick, warTick("fast"), copGrudge, huntTick, guardTick, cashVan("tick"), gridTick`, а при наличии `ALS_gangTowns` — ещё `gangTick` и `drugTick` не чаще раза в 10 с (`ALS_crimeTickAt`). Ошибка в одной из этих функций (например, необработанная переменная в обёртке) **не останавливает цикл** — такие ошибки просто повторяются каждый тик.
- Атомарность: фрагменты, которые нельзя прерывать планировщиком, оборачиваются в `isNil {…}`.

### 1.5 Состояние и пространства имён
- Серверные хэши и массивы: `ALS_db` (всё сохранение), `ALS_houses` (карта недвижимости), `ALS_owned` (ключ дома → владелец uid или id компании), `ALS_crews`, `ALS_coopJobs`, `ALS_war`, `ALS_warGar`, `ALS_companies`, `ALS_biz`, `ALS_ownedVehs`, `ALS_fares`, и т.д.
- Клиенту состояние доставляется тремя путями: **публичные переменные** (`publicVariable`; `ALS_war`, `ALS_jobBoard`, `ALS_menu`, `ALS_optsInForce`, `ALS_crewPublic`, `ALS_ownedPublic`, `ALS_bizPublic`, `ALS_npcPublic`, `ALS_build`, …); **переменные объекта игрока** (`player setVariable [..., true]`: `ALS_money`, `ALS_lic`, `ALS_crew`, `ALS_coopJob`, `ALS_coopOffers`, `ALS_sideNav`, `ALS_rep`, `ALS_msgs`…); **`remoteExec` на клиента** (уведомления `ALS_fnc_notify`, окна, действия).
- Клиентский UI-контекст: `uiNamespace` (`ALS_phoneDisp`, `ALS_hudWeb`, `ALS_licDisp`, `ALS_pages`, …) и глобалы `ALS_phone`, `ALS_lic`, `ALS_talk` (хэши с контролами и флагом `ready`).

### 1.6 Сеть
- Типовой поток: клиент → `remoteExec ["ALS_fnc_x", 2]` с аргументом `[player, …]`; сервер проверяет условия, меняет состояние и возвращает результат `setVariable [..., true]`, `publicVariable` или `remoteExec` на клиента.
- Индекс: **864** места `remoteExec`; **137** серверных точек входа (`targets 2`), из них только **36 проверяют отправителя** (`remoteExecutedOwner`/`isRemoteExecuted`), 101 доверяют переданному `_unit`. Клиентских целей — 49 функций, широковещательных/прочих — 8.
- Без `CfgRemoteExec` действует режим движка по умолчанию (разрешено всё; сдерживают только BattlEye и конфиг сервера). Лицензия мода прямо рассчитана на сервера знакомых. Для сторонних аддонов отсюда следует: **любая серверная функция LifeSim вызываема любым клиентом с произвольным `_unit`**, защита — только собственные проверки функции.
- Не-ALS функции, вызываемые удалённо самим модом: `setFuel, lock, moveOut, moveInCargo, unassignVehicle, switchMove, playMove(Now), playActionNow, action, setPlateNumber, setVelocity, setHitPointDamage, addRating, enableSimulationGlobal`, `call` (с лямбдой), `ace_captives_fnc_setHandcuffed`, `ace_medical_fnc_*`.

### 1.7 Идентификация и администратор
- `ALS_fnc_uid unit` → переменная `ALS_uid` объекта, иначе `getPlayerUID`, иначе строка `"local"` (игрок без Steam). `findPlayer uid` ищет по `allPlayers`; понимает `"local"` и ботов с `ALS_uid`.
- `isAdmin`: uid в `ALS_adminUids`; хост-игрок на локальном сервере (`isServer && hasInterface`); `admin (owner unit) > 0`; на клиенте `BIS_fnc_admin`.

### 1.8 Версионные различия 0.13.0 → 0.14.0 (по сравнению функций)
Из проверенных функций изменились только: `phoneMsg` (+`case "bg"`), `phonePush` (+`state "bg"`), `warBases` (+проверка охраны телохранителями у базы), `hudInit` (мелкие правки форматирования), список `fnlist` (+`bg*`, `drugTip`, `gunInHand`, `buildShow/buildStep`, `waterClear`). Новая подсистема 0.14.0 — **телохранители (`bg*`, 21 функция)**.

## 2. Сохранения, слоты, опции и жизненный цикл игрока

### 2.1 Где и как хранится
- Единая БД: хэш-таблица `ALS_db` на **сервере**; на диск уходит в `profileNamespace` сервера под ключом `ALS_dbKey` как массив пар `[[ключ, значение], …]` (`saveProfileNamespace` пишет **весь** профиль).
- Ключ слота: `slotKey(1) = "ALS_db_<world>"`, слоты 2–5 — `"ALS_db_<world>_s<n>"`. Для каждой карты свои сохранения. Посмертные копии: `<ключ>_replaced`, `_deleted`, `_preupdate` (перед миграцией версии).
- Служебные ключи: `_version` (`ALS_saveVersion = 1`, `dbMigrate_1` пуст), `_meta` `[имя, пресет, ironman, дата, секунды игры, время сохранения]`, `_settings` (опции).
- API: `dbGet [ключ, по умолчанию]` (без умолчания — `nil`), `dbSet [ключ, значение]` (`nil` значение = удалить; ставит `ALS_dbDirty`), `dbLoading [ключи, готово?]`, `dbSave [force]` (пишет, только если `ALS_dbDirty` или `force`).
- **Защита незагруженных ключей:** `dbSet` молча отказывается писать ключ, у которого `ALS_dbGuard[key] == false` (и один раз логирует «NOT saving…»). Подсистема обязана вызвать `dbLoading [["ключ"]]` до чтения и `dbLoading [["ключ"], true]` после успешного разбора. Так наш аддон защищает `alspmc_*_v1`.
- Сохранение: `saveLoop` каждые `ALS_saveInterval` (опция «autosave», по умолчанию 5 мин): `playerSave` каждого игрока + `worldSave` (`vehSave, stashSave, furnSave, rivalSave, lawSave, crateSave, potSave, groundSave, uwStash(save), plantSave, dbSave`). Дополнительно `dbSave` вызывается разово при событиях с деньгами/имуществом (в т.ч. нашим аддоном); при `HandleDisconnect` — `playerLeft → playerSave → worldSave`.

### 2.2 Слоты, главное меню, опции мира
- Сервер: `menuWait` публикует `ALS_menu` (`state:"choose"`, список слотов `slotInfo`, определения опций, дедлайн). Выбирает **хозяин** (`isAdmin`: uid в `ALS_adminUids`; хост-игрок на локальном сервере; `admin owner > 0`); если никто не выбрал 60 с после захода первого игрока — продолжается последний слот.
- `menuPick` (RPC на сервер, проверка `isAdmin`): `hold`, `delete` (с копией `_deleted`), `new` (имя ≤32, пресет Easy/Normal/Hard/Custom, ironman, опции `optClean`), `load`. `menuApply` записывает `_meta/_settings` и вызывает `optApply`.
- Опции (`optDefs`, 20 штук + список гражданских фракций): `startMoney, pay, coldStart, homeStashes, prices, upkeep, police, witnesses, heatFade, population, timeSpeed, encounters, events, rivalCount, rivalAggro, military, war, medicAll, deathCash, autosave, tutorial`. `optApply` записывает `ALS_opt_<k>` (публично), задаёт `ALS_startCash`, `ALS_timeMult` (`setTimeMultiplier`), `ALS_saveInterval`, `ALS_civMax/Density`, перечитывает `factions`.
  - Опция `war` (0/1) включает войну двух армий; значения читаются `ALS_fnc_opt "война"`.
  - Влияние на аддон: наши награды **не** масштабируются опцией `pay`; цены базы/лицензии фиксированы (1 €).

### 2.3 Жизненный цикл игрока (сервер)
1. Клиент после загрузки: `[player] remoteExec ["ALS_fnc_playerLoad", 2]`. `playerLoad` ждёт `ALS_ready`.
2. Идентификатор: `ALS_fnc_uid` → `ALS_uid` на объекте или `getPlayerUID` (в SP/без Steam — `"local"`). `findPlayer uid` ищет по `allPlayers` (учитывает `"local"` и боты с `ALS_uid`).
3. Нет записи `player_<uid>` → `newPlayer`: деньги `[ALS_startCash,0]`, лицензия `driving`, экран выбора карьеры (`startOptions`) или сразу стартовый дом + машина. Есть запись `["dead"]` → `homeRespawn`. Иначе позиция/снаряжение/поза (`playerApply` на клиенте), в т.ч. возврат в сохранённую машину или безопасная точка (если в воде/воздухе).
4. Затем: стартовый дом (`starter_home_<uid>`, если ни разу не было `home_ever_`), стартовая машина (`veh_ever_`), `moneyMirror` (кэш денег на объекте), `jobClient` по активным работам, `courierRoute`, `lawRejoin`, `playerHeld` (вещи из отсутствующих сегодня модов хранятся в `held_items_<uid>` и выдаются в склад дома, когда мод вернулся), `gangMember`.
5. `playerSave` (каждые N минут и при выходе): `player_<uid> = [posASL, dir, loadout, stance, serverTime, aboard]` либо `["dead"]`.
6. Респаун (`EntityRespawned` на клиенте): `playerCarry` копирует переменные со старого тела на новое (`ALS_rep, ALS_lic, ALS_msgs, ALS_streetRep, ALS_gangRep/Mem/Job/Invite, ALS_corner, ALS_crew, ALS_fares, ALS_taxi*, ALS_courierRoute, ALS_smuggleDest, ALS_credit, ALS_manhunt, ALS_starterHome, ALS_statsOn, ALS_tutCard/Nav, ALS_guideNav, ALS_sideNav, ALS_standNav, ALS_rwNav, ALS_encNav, ALS_ride, …`), `homeRespawn` возвращает домой. **Не переносятся `ALS_money`, `ALS_coopJob`.** `moneyMirror` (кэш денег на объекте) вызывается только из `moneyAdd`, `newPlayer`, `playerLoad`, `careerStart`, `dealerBuy`, `debtPay`, `payMods`, `moneyFine` — не при респауне (проверено поиском). `ALS_coopJob` заново пишет тик задания (для заданий аддона — `contractMirror` каждые ~3 с).
   - Следствие для аддона: `ALS_sideNav` с метками контракта **переживает смерть**, а `ALS_coopJob` — нет.
7. Выход: `HandleDisconnect` → `playerLeft` (самолёт садится, отменяются пассажирские/таксирейсы, чистятся пассажиры) → `playerSave` → `worldSave`. Отдельный `HandleDisconnect` из `coopInit` убирает uid из crew (см. часть про crew).

### 2.4 Деньги (кратко, подробнее в части «экономика»)
- Баланс: `money_<uid>` = `[наличные, банк]` (округляются); `moneyAdd [uid, cash, bank]` — единая точка записи (`false`, если уйдёт в минус; зеркалит в `ALS_money` объекта); `moneyPay [uid, цена]` сначала списывает банк, затем наличные; компании: `money_co_<id>`; долги `debt_<uid>`.
- Смерть: опция `deathCash` — потеря доли наличных (банк в безопасности).

### 2.5 Особенности, важные для интеграции
| № | Факт | Влияние |
|---|---|---|
| P1 | `saveProfileNamespace` пишет весь профиль на каждом `dbSave` | на больших профилях частые принудительные сохранения (наши `dbSave` после денег/контракта) дороги; оригинал сохраняется по таймеру |
| P2 | `playerCarry` переносит `ALS_sideNav` и `ALS_crew` при респауне | метки заданий переживают смерть; важно при диагностике «залипших» точек |
| P3 | `dbSet` при отказе только логирует один раз на ключ | если подсистема не вызвала `dbLoading … true`, её данные не сохранятся; в логе одна строка |
| P4 | `uid` для игрока без Steam — `"local"` | на SP/локальных тестах одинаковый uid у всех «без Steam» |
| P5 | Гипотеза (проверить в игре): после респауна на новом теле нет `ALS_money` до первой денежной операции, значения по умолчанию `[0,0]` в HUD/телефоне | возможный косметический баг оригинала; у аддона ПК/телефон берёт `ALS_money` с объекта игрока (`clientTick`), поэтому «Доступно: 0 €» после смерти |

## 3. Crew (группа) и совместные задания

Прочитано построчно: `crewDo`, `crewOf`, `crewPublish`, `sameTeam`, `coopInit/Offers/Accept/Tick/End/Act/Actions`, `coopJob_escort`, `coopJob_heist`, `coopJob_rescue`, `coopJob_sling`, навигация в `hudInit`, `phoneMsg`, вкладка Crew в `phone.html`.

### 3.1 Данные
- **Crew** — хэш в `ALS_crews[id]`: `id` (`"c<N>"`, счётчик `ALS_crewSeq`), `leader` (uid), `members` (массив uid, максимум 4), `job` (id активного задания или `-1`), `offers` (массив предложений), `offersAt` (время последней генерации предложений по `time`). Создаётся лениво первым приглашением (`crewDo "invite"`); другой код (в том числе аддон PMC) может создать crew тем же форматом.
- **Приглашения:** `ALS_crewInvites[uid_цели]` = массив `[crewId, uid_пригласившего, имя, время]`.
- **Публикация клиентам** (`crewPublish`, вызывается в конце `crewDo`, `coopAccept`, `coopEnd` и обработчика отключения):
  - `ALS_crewPublic` (publicVariable): `[{id, leader, job, members:[[uid, имя|"?"]]}]`;
  - для каждого игрока: `ALS_crew` (id его crew или `""`), `ALS_crewInvites` (объект, `[[crewId, имя]]` только по существующим crew);
  - если у игрока **нет** crew: обнуляются `ALS_coopOffers` (если не пусты) и `ALS_coopJob` (если не `nil`). **`ALS_sideNav` не трогается.**
- **Задание** — хэш в `ALS_coopJobs[id]` (`ALS_coopSeq` — общий счётчик id предложений и заданий). Ключи, которые ставит ядро: `id`, `kind`, `crew` (id), `state`, `since` (`time` принятия), `team` (массив uid онлайн-участников на момент принятия), плюс копия полей предложения (`title`, `text`, `brief`, `pay`, `min`, `km`, `roles`, `cash`, …) и собственные ключи модуля.

### 3.2 Crew: операции `crewDo [игрок, what, arg]` (RPC на сервер)
| what | Поведение |
|---|---|
| `invite` | цель — онлайн-игрок, не он сам, **не состоит в другом crew**; если у приглашающего нет crew, создаётся; максимум 4 участника; повторное приглашение того же crew той же цели **раньше 60 с отклоняется**; запись в `ALS_crewInvites[цель]`, уведомления обоим. |
| `accept` (arg = id crew) | crew существует, приглашение есть, в crew < 4; **если игрок уже в crew — сначала `leave`**; `pushBackUnique`, приглашения в этот crew удаляются, уведомления участникам, затем **`coopOffers` пересоздаёт предложения**. |
| `decline` | удаляет приглашение. |
| `leave` | удаляет uid из `members`; если участников не осталось — crew удаляется; если ушёл лидер — лидером становится `members select 0`; остальным уведомление. **Задание (`job`) не затрагивается**: игрок остаётся в `team` задания. |
| `kick` | только лидер, не себя, цель должна быть в `members`; цель получает «dropped», остальным уведомления нет. |
Любая операция заканчивается `crewPublish`; результат `crewDo` — булево.
- Отключение игрока (`HandleDisconnect`, `coopInit`): убирает uid из crew, при пустом crew удаляет его, при уходе лидера передаёт лидерство первому из оставшихся, `crewPublish`.
- `crewOf uid` возвращает первый crew, где uid в `members`, иначе пустой хэш. `sameTeam [a, b]`: `true` для одного uid, одного crew или одной компании.

### 3.3 Предложения заданий: `coopOffers [crew]`
- Работает, только если лидер онлайн. Перебирает **`ALS_fnList`**, берёт имена с префиксом `coopJob_`, для каждого вызывает `["offer", {crew: хэш crew, pos: позиция лидера}]`. Непустой хэш получает `id` (`++ALS_coopSeq`) и `kind` (имя без префикса).
- Результат складывается в `crew.offers`, `crew.offersAt = time` и раздаётся каждому онлайн-члену как `ALS_coopOffers` (public): `[{id, kind, title, text, pay, min, km, roles}]`.
- Вызывается: при принятии приглашения; из `coopTick`, когда у crew нет задания (`job == -1`), в нём ≥ 2 участника и прошло > 600 с с `offersAt`; `coopEnd` ставит `offersAt = -1e9`, что вызывает пересоздание на ближайшем тике.

### 3.4 Принятие: `coopAccept [игрок, id]`
Условия по порядку: у игрока есть crew → он лидер → у crew нет задания → предложение `id` найдено в `crew.offers` → онлайн-участников ≥ `min`. Задание = **копия** предложения + `crew`, `state = "start"`, `since = time`, `team` = онлайн-участники. Затем **`["start", job] call coopJob_<kind>` должен вернуть ровно `true`**, иначе «The job fell through» и ничего не сохраняется. После успеха: `ALS_coopJobs[id] = job`, `crew.job = id`, `crew.offers = []`, у всех онлайн-членов `ALS_coopOffers = []`, уведомление «Crew job: <title>. <brief>», лог `Coop: crew … took …`, `crewPublish`.
- Одиночный игрок без crew принять задание не может («Co-op jobs need a crew»); у всех четырёх нативных модулей `min = 2`.

### 3.5 Тик и завершение
- `coopTick` — PFH каждые 3 с (`coopInit`). Для каждого задания: берёт crew по `job.crew`, формирует `_members` (**онлайн-члены crew на этот момент**, а не `team`), вызывает `["tick", job, members] call coopJob_<kind>`; если `_members` пуст — принудительно `["failed", 0]`; результат `[состояние, доля]`: `"done"`/`"failed"` → `coopEnd`, иное — продолжение. Если crew уже удалён, задание завершится как `failed`.
- `coopEnd [job, share]`:
  1. `team` = `job.team` (запасной вариант — члены crew); получатели сообщений — объединение `team` и текущих членов crew, найденные онлайн;
  2. `total = round(pay * share)`; на человека `each = round(total / count team)`;
  3. **в компанию** (деньги `money_co_<id>`), если у `team[0]` есть компания с `jobsTo`, задание не `cash` и **все** из `team` — члены этой компании: `moneyAdd [id компании, 0, total]`, запись в `ledger` («Crew job»), `companySave`; `each = 0`;
  4. иначе каждому из `team` (в том числе вышедшему из crew и офлайн — выплата по uid): `moneyAdd [uid, 0, each]`; для `cash = true` (ограбление) — наличными;
  5. всем получателям: `ALS_coopJob = nil`, `ALS_sideNav = []` (оба публично) и сообщение (провал / «в банк компании» / «вы присоединились после принятия — доли нет» / «N € each …»);
  6. `["end", job, share] call coopJob_<kind>` (очистка объектов модуля); `ALS_coopJobs deleteAt id`; у crew `job = -1`, `offersAt = -1e9`; лог `Coop: … over`; `crewPublish`; `companyPublish`, если платили в компанию. Возвращает `each`.
- **Единственное место, где `ALS_coopJob` и `ALS_sideNav` чистятся по окончании задания, — `coopEnd`;** при выходе из crew `ALS_coopJob` чистит `crewPublish` (только у игрока без crew), `ALS_sideNav` — никто.
- Смерть игрока: `ALS_coopJob` на новое тело не переносится (`playerCarry`), `ALS_sideNav` — переносится.

### 3.6 Интерфейс модуля `coopJob_<kind>` (контракт)
Функция `ALS_fnc_coopJob_<kind> = {params ["_mode", ["_a", createHashMap], ["_m", []]]; …}`:
| `_mode` | `_a` | `_m` | Возврат |
|---|---|---|---|
| `"meta"` | — | — | хэш `{title, min}` (справочно) |
| `"offer"` | `{crew: хэш, pos: позиция лидера}` | — | хэш предложения (`title, text, brief, pay, min, km, roles` + свои поля) или пустой хэш (нет предложения) |
| `"start"` | задание | — | `true` — старт принят; всё остальное — «job fell through» |
| `"tick"` | задание | онлайн-члены crew | `["on"]`, `["done", доля]`, `["failed", 0]` |
| `"act"` | задание | `[игрок, действие, объект]` | `true`/`false` |
| `"end"` | задание | доля (число) | не используется |
Модуль сам каждый тик пишет клиентам: **`ALS_sideNav`** (массив `[позиция, подпись, иконка]`; первый элемент HUD подсвечивает «главным») и **`ALS_coopJob`** (хэш `{id, title, state, status, progLabel, progText, pay}`), оба `setVariable [..., true]`. Нативные модули делают это для текущих членов crew.

### 3.7 Нативные модули (детали)
**Конвой `escort`** (`min 2`, роли «Escort driver», «Gunner»):
- Предложение: старт — объект `ALS_jobSites` типа `industrial`/`port` в 4 км от лидера; цель — город (`town/city/capital`) в 6–14 км от старта; груз из пяти; `pay = round((3000 + км·450)/100)·100`.
- Старт: дорога ≤ 600 м от места (не TRACK/TRAIL, ширина ≥ 5, ≥ 2 соединений, без зданий в 14 м); два грузовика подряд (второй сзади по `roadsConnectedTo`, до 6 звеньев), водитель — `C_man_w_worker_F` в `civilian`-группе, `allowDamage false` первые 15 с; грузовики `ALS_keep`, `ALS_convoy = id`, `lock 2`; `calculatePath` проверяет маршрут (агент удаляется), при необходимости колонна разворачивается (`orient`). Точка засады — дорога около 40–70 % прямой от старта до цели.
- Тик: состояния `wait` → `go` (любой участник ближе 150 м к голове колонны и колонна ориентирована/прошло 12 с; ведущий едет через `aiDrive`, остальные `aiFollow`; 55 км/ч, при разрыве > 150 м — 30), `held` (никого из участников в 400 м более 30 с — колонна встаёт, `ALS_hold`); грузовик «потерян», если не `alive`/`canMove` или мёртв водитель; таймаут 2700 с; **засада** при приближении головы к точке < 450 м: `2 + число участников` бандитов из `ALS_factions.Gangs.men` в **`civilian`-группе с `addRating -100000`** и `ALS_hitSquad`, COMBAT/RED. Доля = прибывших (ближе 120 м к цели) / всех грузовиков.
**Ограбление `heist`** (`min 2`, `cash = true`): магазин (`Shop`, свободный, не `ALS_reserved`) с помещением на первом этаже; сейф `Land_MetalCase_01_large_F` внутри, щит `Land_TransferSwitch_01_F` у стены, фургон и «фенс» (NPC) у дороги в 2–4 км вне городов; действия ACE (обход сигнализации 20 с, взлом 30 с, схватить 2 с); сигнализация → `lawCrime "heist"` и вызов полиции с задержкой 45 с (+60 с, если есть «наблюдатель»); добыча у носителя (`ALS_heistLoot`), при его смерти/потере сознания падает чемоданом; тюрьма носителя → провал; успех при доставке к фургону (< 30 м). «Крупное» ограбление (банк столицы, при незавершённом `ALS_taskForce`) пишет `dirty_<uid>` и вызывает `legacy "bigheist"`.
**Спасение `rescue`** (нужна своя лодка/вертолёт в `ALS_ownedVehs`): терпящая бедствие лодка и 2–4 выживших; ракета, если участник ближе 300 м; погрузка (`moveInAny`), сдача у порта (< 80/150 м), буксировка `ropeCreate`; доля = спасённые/всего (+0,4, если лодку привели на буксире).
**Подвеска `sling`** (нужен свой вертолёт с `slingLoadMaxCargoMass > 0`): три груза, площадка; крюк вешает человек на земле (ACE), подпись — человек на площадке (< 40 м); доля по точности сброса (0,7 / 0,85 / 1).
Общее: таймаут 2700 с, статус-строки заглавными, чистка объектов в `end` отложенно (`CBA_fnc_waitAndExecute`).

### 3.8 Действия `coopAct` / `coopActions`
Клиент (`coopActions`) добавляет ACE-действия к классам объектов; после прогресс-бара вызывается `[player, what, object] remoteExec ["ALS_fnc_coopAct", 2]`. Сервер находит задание по переменной объекта `ALS_coopJobId`, сверяет crew игрока с `job.crew` и вызывает `["act", job, [игрок, what, объект]]`.

### 3.9 Навигационные метки и карта (клиент)
- HUD (`hudInit`, PFH 0,25 с) пересобирает `ALS_nav` каждые 0,25 с: основной маркер = ближайший из активных заданий (перевозки, такси, курьер, туториал) + до 3 побочных; затем `ALS_encNav`, `ALS_sideNav`, `ALS_guideNav`, `ALS_rwNav`, `ALS_hallNav`, `ALS_standNav`; затем отметки членов своего crew (`ALS_crew` совпадает; позиция +1,2 м; подпись — имя). ## 4. Интерфейс: окна на веб-контроле, телефон, HUD, NPC и диалоги

Прочитано построчно: `phoneOpen`, `phonePush`, `phoneMsg`, `uiLoad`, `uiKeep`, `uiBusy`, `langSet`, `trInit` (начало), `notify`, `talkOpen`, `talkMsg`, `talkPush` (до роли `civ`), `npcCreate/Attend/Loop/Publish/Actions/Spawn/Remove/Name/Face/Scroll`, `hudInit`; в `phone.html` — мост, реестр приложений, обработка ввода и вкладка Crew. **Не читал:** тела остальных приложений телефона (кроме Crew и Rivals в части разметки), `talkPush` после роли `civ`, `tradeOpen/Msg/Push`, `dealer*`, `furn*`, `start*`, `menu*` (окна), `cockpitUI`, `fishUI`, `scalesUI`.

### 4.1 Общая технология окон
- Все окна — **HTML в `ALS_RscPhoneWeb`** (наследник `RscWebBrowser`). Окно = `(findDisplay 46) createDisplay "RscDisplayEmpty"` + `ctrlCreate ["ALS_RscPhoneWeb", IDC]` + `ctrlAddEventHandler ["JSDialog", …]` + `uiLoad`. Идентификаторы контролов: телефон **7400**, торговля 7500, диалог NPC и лицензии **7600**, мебель/старт 7700, дилер 7800, HUD и главное меню **7900**, кабина 7660, рыбалка 7650, весы 7670 (окно ПК аддона PMC — 7410).
- `uiLoad [контрол, имя]`: ставит контролу `ALS_page = имя`, регистрирует его в `uiNamespace "ALS_pages"` (для переключения языка), при языке ≠ `en` в течение 3 с (12 раз по 0,25 с) вызывает в странице `i18n.set(<язык>)`; затем `LoadFile "\als_main\ui\<имя>.html"`.
- **JS → SQF:** страница вызывает `A3API.SendAlert(JSON)`; срабатывает `JSDialog`-обработчик контрола: телефон — `ALS_fnc_phoneMsg`, диалог — `talkMsg`, торговля — `tradeMsg`, лицензии — встроенный `switch`, меню — `menuMsg`. Сообщение — JSON-объект с полем **`a`** (вид сообщения).
- **SQF → JS:** `ctrlWebBrowserAction ["ExecJS", format ["phone.set(%1)", toJSON _state]]` (аналогично `talk.say`, `hud.set`, `lic.set`…). Цикл `spawn`, пока дисплей открыт, повторяет `*Push` каждую секунду (телефон — 1 с, лицензии — 0,5 с), но только после сообщения `ready` от страницы.
- **Кодировка:** движок отдаёт странице текст как последовательность байтов UTF-8, прочитанных по одному. Поэтому в `phone.html` у всех строк «из игры» вызывается `fix()` (`decodeURIComponent(escape(s))`, с группировкой сумм «12500 €» → «12,500 €»), а на весь входящий `phone.set` накладывается `unmangle()` (однократно, только если в строке есть символы \u0080–ÿ). Исходящий текст SQF→JS кириллицей допустим (разбирается `fix`).
- Фокус: после любого клика страница снимает фокус с кнопки (иначе движок перестаёт передавать колесо мыши), кроме текстовых полей.
- Занятость интерфейса: `uiBusy` = любое из окон (`dealer, furn, lic, phone, start, tc, trade, fish`), диалог 1127001, инвентарь ACE (602) или открытая карта; `talkOpen` ждёт до 60 с освобождения.

### 4.5 NPC: модель

### 5.1 Модель сторон — главный механизм
- **Сторона полиции** `lawSide` = сторона роли `Police` из `ALS_factions` (по умолчанию `WEST`, класс `BLU_GEN_F`).
- **Роли и стороны** (`fn_factions`): `Police` → западная; `Military` → **всегда `west`** (исходный класс армии — `IND_F`, но сторона принудительно `west`); `Opfor` → **всегда `resistance`** (классы `OPF_F`); `Paramedics` → `civilian`; `Gangs` (`IND_C_F`) — по конфигу `GUER`, но реально создаются **в `civilian`-группе с `addRating -100000`** (см. 5.5).
- **Дружба сторон**, задаётся один раз в `lawInit`: `east`↔`civilian` и `east`↔`resistance` = **дружественны** (в обе стороны); `west`↔`east` = враждебны; `west`↔`resistance` = враждебны. Остальное — значения по умолчанию.
- **Сторона игрока.** Игрок обычно `civilian`. `lawOutlawLocal [unit, on]` (исполняется на машине игрока) создаёт новую группу нужной стороны и делает `joinSilent`: `on = true` → **`east`**; `on = false` → `civilian`, либо **`west`, если у игрока флаг `ALS_opforFoe`** (армия Opfor его считает врагом: `warFoe`). Отсюда:
  - **«Смертельный» розыск = игрок на `east`:** полиция и армия (`west`) воюют с ним; гражданские, банды и Opfor (`resistance`/`civilian`) к нему дружественны.
  - **Враг Opfor = игрок на `west`:** Opfor (resistance) воюет с ним, а полиция/Military (`west`) для него «свои».
- Флаг `ALS_outlawOn` на объекте игрока хранит последнее решение (сервер: `lawOutlaw`), чтобы `warFoe` при смене `opforFoe` мог пересчитать сторону.

### 5.2 Преступления и розыск
- **`lawCrime [игрок, тип, позиция?, жертва?, sure?]`.** Таблица типов (звёзды, штраф €, подпись): `shots 1/300`, `theft 1/800`, `carjack 2/1500`, `robbery 2/3000`, `kidnapping 3/10000`, `dealing 2/2500`, `smuggling 3/6000`, `cargotheft 2/2500`, `weapon 1/1000`, `drugs 2/3000`, `fugitive 1/1500`, `racing 1/600`, `stolengoods 1/500`, `assault 2/1500`, `hitrun 2/2000`, `escape 2/2500`, `evade 3/2000`, `murder 3/8000`, `copassault 3/4000`, `copkill 4/15000`, `soldierkill 4/15000`, `milattack 3/8000`, `massacre 5/50000`, `counterfeit 2/3000`, `bootlegging 1/500`, `bookmaking 1/800`, `fraud 2/5000`, `forgery 2/4000`, `vandalism 1/800`, `burglary 2/3000`, `arson 3/6000`, `threat 1/700`, `conspiracy 2/4000`, `heist 3/20000`, `checkpoint 2/1500`, `bribery 1/1000`, `accessory 1/800`, `airspace 1/1500`, `trespass 2/3000`, `force 2/2000`, `poaching 1/1500`; неизвестный тип = 1 звезда / 500 €.
- **Свидетели:** без `sure` нужен хотя бы один не-игрок в радиусе 300 м от места: бодрствующий, не в наручниках, не «blackmarket/fence/gang»; видит преступление, если ближе `25·witnesses` м либо в пределах `120·witnesses` (для полицейского — 300 м, множитель 1) и видимость > 0,25. Нет свидетеля — преступления нет. `witnesses` — опция мира.
- **Снисхождение:** для 1-звёздочных преступлений при свидетеле-полицейском, если розыска ещё нет, а репутация в городе «Liked»/«Respected» (50 %/75 %) или мнение горожанина-полицейского (`opinion`) ≥ 40 — «предупреждение», запись не создаётся.
- **Запись розыска** `ALS_wanted[uid]`: `level` (0–5), `crimes[[подпись, штраф]]`, `lastSeen`, `lastPos`, `seenFor`, `since`, `warned`, а также `lethal`, `lethalWhy`, `copAt`, `custody`, `station`, `custodyAt`, `nextCar`, `nextSquad`, `nextRb`, `still`, `stillVeh`. Уровень = `max(звёзды, старый + 1, если старый > 0 и звёзды ≥ 2)`, не выше 5. Уведомление «WANTED ★…», штраф репутации в городе `−3·звёзды` (`repAdd`), новость «Police hunt suspect…» при ≥2 звёздах (не чаще раза в 300 с на игрока), `guardNote` (см. 5.7). Сохраняется в БД ключом `wanted` (`[uid, level, crimes]`).
- **Убийства (`lawKilled`, `EntityKilled`):** убитый с `ALS_army` → `warKilled`; `ALS_hitSquad`/`ALS_hostile` (не полицейский) → не преступление; убийство жителя игроком → `murder`; полицейского — `copkill`; сбитый машиной — `lawAccident`; гибель игрока: потеря доли наличных (`deathCash`), `statsAdd`, рейтинг атакующего восстанавливается (`addRating` до 0, если был отрицательным).
- **Оповещения:** `lawChecks` (раз в тик, для игроков не в тюрьме): ствол в руках без лицензии `weapons` на виду у полицейского (≤60 м) раз в 180 с → «weapon»; подсказка о наркоторговле на углу + наркотики в карманах и полицейский ≤25 м → изъятие и «dealing»; контрабанда в ≤40 м от игрока при виде полицейского ≤22 м с шансом 20 % за тик → «smuggling», `armyDo "revoke"`.

### 5.3 Тик розыска (`lawTick`, каждые 2 с из `lawLoop`)
Для каждого игрока с записью `ALS_wanted` (кроме тех, кого нет онлайн; мёртвый — запись удаляется; в тюрьме — пропуск):
1. **Видимость:** «видящий» полицейский — из `ALS_cop`-юнитов стороны полиции: ближе 600 м и (`knowsAbout > 0,5` или ближе 60 м) и видимость > 0,2. **В городах под контролем Opfor (`warSideAt == "Opfor"`) видящих нет вовсе** (`-1`). Видящий обновляет `lastSeen/lastPos`, при движении > 6 м/с растит `seenFor`, и группы поблизости получают `reveal`.
2. **Затухание:** если `lastSeen` старше `(60 + 30·level) / heatFade / (2, если игрок платит полиции в этом городе по `payroll_<uid>`)` секунд — уровень −1 (не ниже 4 при `manhunt`), сообщения «losing your trail» / «lost the police». Нулевой уровень: запись удаляется, `lawOutlaw false`.
3. **Смертельность (`lethal`):** `оружие в руках и не сдаётся` **или** `копа атаковали за последние 120 с (`copAt`)` **или** `manhunt`; в машине статус «gun» сохраняется. При смене `lethal` вызывается **`lawOutlaw`** (смена стороны, см. 5.1) и игроку говорят «Lethal force authorised» / «Weapon down».
4. **Эвейд:** уровень < 3 и `seenFor` > 90 → преступление `evade`.
5. **Задержание:** полицейский пешком в 18 м; игрок стоит (< 1,5 м/с) 4 с подряд или поднял руки/в наручниках/без сознания (и не «lethal» либо с поднятыми руками) → подходит, ставит наручники; в машине — «Step out», через 14 с выдёргивает. Подбирается патрульная машина (ближайшая ≤ 300 м) и участок, игрок помещается в машину (`custody`), машина едет на участок; по прибытии (< 80 м), через 200 с или если игрок покинул машину >15 с — `lawArrest`. Нет машины или участка — арест на месте.
6. **Реакция:** число машин погони `round(cars · police · townPolitics.police)` (минимум 1); новая посылается не чаще раза в `20 / pol` с через `lawDispatch ("chase")`; если город под «армией» (`guardHeld`) — приезжает фракция `Military`. На 5★ дополнительно **военный отряд** (`ALS_Heat Star5 squad = 1`, `squadEvery = 180`). Патрули (`ALS_patrols`) в 1500 м присоединяются к погоне. Перекрытие дороги (`lawRoadblock`): ≥3★, игрок за рулём наземной машины быстрее 30 км/ч, не чаще раза в 240 с (`jobEv_roadblock`).
7. **Ограничения ИИ погони:** режим `COMBAT/RED` при `lethal`, иначе `AWARE/YELLOW`; вооружение растёт со звёздами (пистолет → дробовик (3★) → винтовка (4–5★), `ALS_Heat`); уходящие/оставленные машины и тела удаляются через 600 с без игроков в 400 м.
- **`ALS_Heat` (config):** 1★ — 1 машина, пистолеты; 2★ — 1 машина, пистолеты; 3★ — 2 машины, дробовики; 4★ — 3 машины, винтовки; 5★ — 3 машины, винтовки + военный отряд раз в 180 с. Фракция всегда `Police`; наборы `men/vehicles/weapons` в конфиге пусты (используются классы фракции).

### 5.4 Арест, тюрьма, штрафы
- `lawArrest [игрок, сдался?]`: штраф = сумма штрафов записей × множитель репутации города (`repTier`: Hated 1,5 … Respected 0,6), половина при добровольной сдаче; время = `уровень·40` с (при сдаче `·20`); игрок-охотник за головами рядом (≤25 м, не член crew/компании, ≤6 м или был последним, кто бил игрока за 300 с) получает награду `bountyCollect`; `moneyFine` списывает штраф; запись удаляется; `streetRep −6`; новость; `ALS_jail[uid] = [секунды, камера, город]` (сохраняется ключом `jail`, возобновляется `lawRejoin`).
- `lawJail` (клиент): затемнение, телепорт в камеру, при «насильственных» преступлениях изымается всё оружие, `ALS_jailed = true`; цикл обратного отсчёта; уход дальше 40 м от камеры = побег (`escape`, 2★); конец — `lawJailDone`.
- `lawSurrender` (диалог с полицейским): если игрок в розыске — `lawArrest(…, true)`, иначе «You're not wanted».

### 5.5 ИИ-враги и «преступники»: как выглядит нативный враг
- Банды, засады, бандиты работ: **юнит в группе `civilian` + `addRating -100000` + `ALS_hitSquad = true` (public)**. Рейтинг делает юнит «отступником» (враждебен всем сторонам), а `ALS_hitSquad` информирует `lawKilled`/`lawInit` (убийство и ранение таких не преступление). Тот же шаблон у `coopJob_escort` (засады), `gangTick`, `manhunt`, `jobEv_pirates/toll` (последние дополнительно `ALS_hostile`).
- Полицейские `lawCopEH [юнит, вооружать?]`: `ALS_cop = true`, оружие `armSidearm "police"`, обработчик `Hit` → `lawCrime "copassault"`.
- Патрульные машины полиции: переменные `ALS_copCar` (машина); `ALS_responders` — список хэшей `{grp, car, purpose (chase|scene|custody|leave), uid, pos, since, wpAt, faction, patrol?}`; `lawDispatch [pos, purpose, uid, faction, as, [men,cars]]` находит дорогу в 400–1000 м (для полиции — от ближайшего участка 300–2000 м), создаёт группу стороны фракции (`Military` — стороны полиции), машину из `cars` (предпочтительно с маяком), экипаж 2 (армия — до 7), ведёт `aiDrive` на место.

### 5.6 Репутация
- `rep_<uid>` = хэш «город → значение» (−100…100), `repAdd [uid, город, дельта, причина]` с уведомлением при смене уровня, `repMirror` → `ALS_rep` на игроке.
- **`repTier [значение]`** → массив `[имя, m1, m2, m3, m4]`: `Hated (≤ −60) [1,15; 0,85; 1,5; 0,85]`, `Distrusted (≤ −20) [1,07; 0,93; 1,2; 0,95]`, `Unknown (< 20) [1; 1; 1; 1]`, `Liked (< 60) [0,95; 1,05; 0,85; 1,05]`, `Respected [0,9; 1,1; 0,6; 1,1]`. Потребители (проверено поиском): `m1` (индекс 1) — множитель цены **покупки** у торговца (`tradeBuy`, `tradePush`, `marketRoutes`); `m2` (индекс 2) — множитель цены **продажи** торговцу (`tradeSell`, `tradeSellUnits`, `tradePush`, `marketRoutes`); `m3` (индекс 3) — множитель штрафа в `lawArrest`; `m4` (индекс 4) — множитель доходов от аренды в `leaseLoop`. Игрок в статусе `Hated` в городе **не может торговать** (`tradeBuy/tradeSell/tradeSellUnits`: «I don't do business with your kind»).
- Порядок отдельный: уличная репутация `streetRep` (число на игроке) и отношение горожан `opinion`.

### 5.7 «Армия берёт город» (`guard*`)
- `guardNote [pos, тип]`: учитываются только тяжёлые преступления с весами `copkill 3, soldierkill 3, massacre 6, milattack 2, heist 2, murder 1, arson 1, copassault 1, sabotage 2`; запись «неспокойствия» привязана к ближайшему городу (в радиусе города + 400 м).
- `guardTick` (каждые 5 с): сумма за последние 6 игровых часов ≥ 8 → город переходит под армию на 24 игровых часа (+ продление на 12 ч от последнего происшествия), вводится **комендантский час 21:00–05:00** (`ALS_warCurfew`), новости и широковещательное уведомление; пост из 4 солдат и грузовика + патруль из 3 по улицам создаются только если игрок ближе 1200 м, но дальше 200 м, и удаляются, когда игроков нет ближе 1500 м. `ALS_guardPub` (public) — список городов; хранится ключом `guard`. `guardHeld [pos]` отвечает, находится ли точка в таком городе (тогда погоню присылает армия).

### 5.8 Военные блокпосты (`cpSites`, `cpTick`)
- `cpSites` строится один раз: по каждому военному кластеру (`milClusters`, ≥6 построек) вне запретных зон и ≥800 м от аэропортов — дорога в 200 м, не ближе 1 км к другому; плюс пограничные посты войны (`ALS_war.borderPosts`) и, при включённой войне, посты у въездов в города.
- `cpTick` (из `lawLoop`, 2 с): когда игрок ближе 900 м и поста нет — создаёт его (`jobEvBlockAt`: заграждение, шлагбаум, 2 солдата роли владельца территории, машина), удаляет при отсутствии игроков в 1300 м; шлагбаум открывается/закрывается по положению машины игрока; проверка игрока в машине (состояния в `ALS_cpSt`). Посты у въездов в города (5-й параметр записи) работают только если у владельца территории включено «военное положение» (`ALS_war.martial[роль]`).

### 5.9 Особенности, важные для интеграции
| № | Особенность |
|---|---|
| L1 | Сторона `east` в LifeSim = «игрок со смертельным розыском». ИИ на `east` создаёт только `warArms` (защитники базы, отнятой игроками у Military — см. 6.6); `east` дружественна `resistance` и `civilian`, враждебна `west`. |
| L2 | Сторона `west` = полиция **и** Military **и** игроки-враги Opfor; `resistance` = Opfor; боты банд — `civilian` с отрицательным рейтингом. |
| L3 | Смена стороны игрока происходит в **его** клиенте (`lawOutlawLocal`), группа пересоздаётся при каждом переключении. |
| L4 | Любой код, меняющий отношения сторон (`setFriend`), затрагивает всех ИИ этой стороны на карте: `lawInit` задаёт отношения один раз при старте, дальше они не пересчитываются. |
| L5 | Свидетель — не-игрок, не из «подполья»; без `sure=true` преступление не фиксируется. |
| L6 | Сумма затрат на погоню зависит от опций `police` и политики города (`townPolitics`). |
| L7 | Убийство бойцов с `ALS_hitSquad`/`ALS_hostile` не наказуемо, убийство `ALS_army` — через `warKilled` (другая ветка). |

## 6. Война, армии, базы, оружейная торговля

Прочитано построчно: `warMap`, `warSideAt`, `milClusters`, `milSide`, `warTick`, `warBases`, `warTowns`, `warSquad`, `warQRF`, `warStrike`, `warHunt`, `warSupport`, `warCommander`, `warIntel`, `warArms`, `warDo`, `warKilled`, `warFoe`, `warAggr`, `warTension`, `warAirShow`, `warRoadSpot`, `armyDo`, `armyMen`, `armsNeed`, `armsGoods`, `armsBattle`, `armsDeal`, `warActionsUnit`, `warActions`. **Не читал:** `warMarkers`, `warSeenLocal`, `noFly*` (запретные зоны), `jobEv*`-часть блокпостов (`jobEvBlockAt`, `stopDress`).

### 6.1 Данные: `ALS_war` (public, сервер+клиент)
`ALS_war` — хэш, создаётся `warMap` при старте и публикуется `publicVariable`:
- `on` (опция мира `war`), `bases` — массив `[id, pos, kind, число_построек, имя]` (`id = "b"+индекс`), `own` — хэш `id → "Military" | "Opfor" | "Players"`, `took` — `id → прежний хозяин` для захваченных игроками баз, `cross` — пограничные переходы `[pos, имя]`, `borderPosts`, `tension` (0–100), `aggr` — хэш `роль → агрессия`, `free` — города, объявившие себя свободными, `freedBy`, `hq` — `роль → id штаба`, `townSide` (город → кто им владеет), `posts`, а также позже `martial` (роль → военное положение), `exercise`, `arms` (оружие на базах игроков).
- **Базы** выделяются из военных кластеров (`milClusters`: здания с признаками `\mil\`, `barracks`, `bunker`, `cargo_hq/tower/patrol`, `mil_`, `military`, без `slum`; группировка в радиусе 500 м; ≥ 6 построек — база). Вид: `airfield` (аэродром ближе 1000 м), `radar` (в 400 м здание с «radar»/«dome»), `port` (в радиусе 400 м вода < −2 м), `depot` (≥ 20 построек), иначе `outpost`.
- **Начальное владение:** все базы `Military`. Если война включена и баз ≥ 3: `round(N/3)` баз (минимум 1) отдаются `Opfor` — идут от «якоря» (база дальше всего от главного аэродрома) в порядке близости к нему, только если они дальше 1500 м от главного аэродрома; затем применяется сохранённое `war_own`. Сторона точки: `warSideAt [pos]` = владелец **ближайшей** базы (по умолчанию `Military`).
- **Границы:** пары городов `Military`–`Opfor` ближе 5 км (до 12 переходов, ≥2 км друг от друга) → посты на дороге в 350 м от перехода в каждую сторону.
- В БД (`dbSet`): `war_own`, `war_took`, `war_aggr`, `war_tension`, `war_free`, `war_freedBy`, `war_supply`, `war_fuel`, `war_ammo`, `war_sup`, `war_cmd`, `war_file`, `war_arms`, `war_armsdeal`.

### 6.2 Фракции и стороны
- `Military` (классы `IND_F`, сторона `west` принудительно) — «местная армия»; `Opfor` (`OPF_F`, `resistance`) — вторая армия; игроки, захватившие базу, получают владение `Players` (флаг зелёный).
- Без войны (`on = false`) остаётся одна армия (`Military`), вторая и всё, что связано с `Opfor`, не создаётся.

### 6.3 Тик войны
`warTick [mode]`: `"fast"` каждые 2 с из `lawLoop` (+ при `"hour"` из `civEconomy`). **Это ещё и общая шина для побочных систем:**
- `fast`: `armsDeal fast`, **конвои армии**, **вертолёты связи**, `warBases`, `warTowns`, `warHunt fast`, `warSquad tick`, `warArms tick`, `warAirShow fast`, `smuggleMeet`, `uwMeet`, `pxTick`, `piJob fast`, учёт QRF (`ALS_warQrfs`), `manhunt tick`, `legacy near`, `legacyKidnap tick`, затухание «врагов армии» (`ALS_warFoes`: −1 каждые 10 с по каждой роли).
- `hour`: напряжение −1/час; `legacy hour`; `armsDeal place/hour`; агрессия каждой роли −2/час; `warSupport hour`, `warIntel hour`, `warHunt hour`; расход снабжения/топлива/боеприпасов баз −1/час (хэши `ALS_warSupply/Fuel/Ammo`, по умолчанию 80, потолок 100); `warAirShow hour`; каждые 2 часа — **по конвою на роль** (не более 2 живых) со случайной базой-источником (`depot/port/airfield`) и базой назначения своей роли; учения («NOTAM», 09:00 каждые сутки, 3 часа, зона 1,5 км вокруг `depot/outpost/radar` не игрока).
- **Конвои армии:** «виртуальны» (движутся по прямой 11 м/с), пока игрок не ближе 1500 м, — тогда спавнятся настоящие машины на дороге (`warRoadSpot`), колонна из эскорта-грузовика-эскорта (доктрина командира добавляет ночью лишнюю машину или бронетехнику) и едет `drvGo`; доставка (грузовик ближе 250 м) = +40 снабжения/топлива/боеприпасов базе. Разбитый грузовик → новость «Army convoy hit»; машины без игроков удаляются (`ALS_warJunk`).

### 6.4 Гарнизоны: `warBases` (каждые 2 с)
- Состояние `ALS_warGar[id]` = `{grp, n, flag, crate, counter, capAt, retakeAt}`.
- Игрок дальше 1000 м от базы → гарнизон удаляется (потери переводятся в −5 снабжения за убитого), флаг/ящик тоже; **исключение:** пока на базе висит таймер контрудара (`counter`), запись и флаг не удаляются. Гарнизон создаётся при игроке ближе 700 м: флаг (Blue — Military, Red — Opfor, Green — Players), у не-игроков группа из `n = round((3 + min(size/8, 5)) · (0,5 + снабжение/200) · (1 + агрессия/200))` (3–12; в штабе ×2) юнитов из `men` фракции в группе её стороны, `taskDefend` 60 м; один командир (`Officer`) у базы-«командного пункта» роли. На флаге переменные `ALS_warBase`, `ALS_warOurs`, `ALS_warKind`; у юнитов `ALS_army = роль`.
- **Захват игроком:** нет живых бойцов роли в 150 м от флага и игрок ближе 30 м удерживает 60 с → `own[id] = Players`, `took[id] = прежний`, агрессия прежней роли +20, `counter = [прежний, время + 1800…3600 с, false]`, новость «Resistance takes …».
- **Контрудар:** по таймеру (если игроков рядом нет) армия «возвращает» базу без боя; иначе при наступлении срока вызывает `warQRF` по тиру агрессии, при агрессии ≥ 70 — `warStrike` (артиллерия); если игроки удерживают ≥ половины баз — ещё QRF 3-го тира. Через 120 с присутствия врага в 100 м от флага без игроков/оружейных защитников — база возвращена; через 1200 с — «held». С 0.14.0 «база с вашими телохранителями на посту» (`bgPosted`) считается обороняемой.
- **Депо:** ящик `Box_NATO_Wps_F` с оружием прежней фракции (первые 3 класса `men`), пополняется раз в игровые сутки (`warcrate_<id>`).
- **Радар у игроков** включает показ на карте конвоев и патрулей (`ALS_warSeen`); контрабандистам с `smugrep ≥ 5` показывается расписание конвоев.

### 6.5 QRF, удары, спецназ
- `warQRF [роль, pos, тир]`: ближайшая своя база; тир 0 — один транспорт, 1–2 — грузовик + вооружённая машина, 3 — плюс бронемашина; тир ≥ 2 — вооружённый вертолёт. При топливе базы < 20 тир ограничен 1. Дорога через `warRoadSpot`, экипаж + десант (до 3/8 пассажиров), `COMBAT/RED`, цель — точка вызова. Запись в `ALS_warQrfs`, очистка при отсутствии игроков 120 с.
- `warStrike [роль, pos, "artillery"|"air"]`: не по городам (500 м), предупреждение игрокам ближе 800 м, через 30 с — 6 мин 82 мм (`Sh_82mm_AMOS`) или 2 бомбы (`Bo_GBU12_LGB`); запрещено при боеприпасах базы < 20.
- `warHunt hour`: **военное положение** роли при агрессии ≥ 85 (КПП в каждом городе, комендантский час, `warSupport "heavy"` +5 для городов), снимается при < 70; при агрессии ≥ 85 раз в 24 игровых часа на «самого убийственного» игрока (по `ALS_warKills`) посылается отряд из 4 бойцов «recon/sniper/sf» (`STEALTH/RED`, навык 0,9, до 2 часов).
- `warAggr [роль, +дельта]`: по умолчанию 10, максимум 100 (50, если командира шантажировали); при подкупленном командире рост вдвое медленнее. Начисления: убитый пехотинец +4, техника +3, танк/БТР +8 (`warKilled`).
- `warTension [+дельта]`: старт 20, ≥ 70 — «граница закрыта» (новость и сообщение всем), < 70 — «открыта». Увеличивается событиями (убийство солдата рядом с границей +10, «подстава» формой другой армии +10).

### 6.6 Игрок и враждебность армий
- `warKilled [убитый, убийца, инициатор]` (убитый с `ALS_army`): роль `Opfor` → `warFoe(убийца, "Opfor", 100)` (игрок становится «врагом Opfor»: **его сторона `west`**, см. 5.1); роль `Military` → `lawCrime "soldierkill"` (или `milattack`); если убийца в форме противоположной армии — «подстава»: напряжение +10, агрессия роли +2; иначе (обычное убийство) — агрессия роли (+4/+3/+8 см. 6.5); при агрессии ≥ 40 — `warSupport "curfew"` (комендантский час в ближайшем городе в 1500 м); командир (`ALS_commander`) → `warCommander "killed"`; не чаще раза в 180 с на роль — `warQRF` с тиром `3/2/1/0` при агрессии `≥85/≥60/≥30/ниже` (доктрина `air` поднимает тир 1 до 2) и, при тире ≥ 2, с шансом 30 % — `warStrike` по позиции убийцы (`artillery` для тира 2, `air` для 3). В ветке «подстава» (убийца в форме противоположной армии) обработка на этом заканчивается.
- `warFoe [юнит, роль, жар]`: `ALS_warFoes[uid][роль] = min(100, +жар)`; `ALS_opforFoe = (Opfor > 0)`; смена пересчитывает сторону через `lawOutlaw`. Жар убывает на 1 раз в 10 с.
- **Командиры** (`warCommander`): у роли один «командующий» (имя «Colonel/General <фамилия>», доктрина `night|road|air` определяется по числу наблюдавшихся тактик ≥ 5); убить командира — агрессия −20, замена через 48 игровых часов с новой доктриной; подкуп (5000 €) на неделю вдвое замедляет рост агрессии и стирает «досье» игрока; шантаж (фото `cmd_<роль>`) на неделю ограничивает агрессию 50.
- **Досье** (`warIntel`): армия запоминает машины (id+окраска) и дома игрока, замеченные в городе с поддержкой < 25 и оружием в руках; раз в 3 часа при агрессии ≥ 50 — конфискация машины или рейд на дом. Информаторы из жителей.
- **Поддержка городов** (`warSupport`): `value = (max репутации игроков в городе)/2 + heavy·2 − harmed·5 + min(доброе дело, 20)`; город принадлежит игрокам (`warSideAt == Players`) и поддержка ≥ 60 → «свободный» (ополчение из 2 жителей `warTowns`), < 40 или потеря → «turns its back». Завербовать жителя в отряд (`recruit`, 300 €, поддержка ≥ 50, до 8 человек), `warSquad` хранит `squad_<uid>`.
- **Оружейная торговля** (`armsDeal`/`armsNeed`/`armsGoods`): интендант (`quartermaster`) каждой роли у одной базы; цена = стоимость оружия·0,5·`need` (`need = 0,4 + 1,2·(1 − доля своих баз)`; победившая сторона (≥ 80 % баз) не покупает), лимит 15000 €/сутки на роль; 25 % шанс, что сделку заметили → 2 суток бан у другой стороны и её агрессия +5; накопленный «перевес» ≥ 8000 раз в 12 игровых часов запускает **атаку на ближайшую базу противника** (`armsBattle`: если рядом игроки — QRF и результат через 900 с по числу живых, иначе по шансу).
- **База игроков** (`warArms`): ящики «parts» у флага → оружие базы (`+2` за ящик); защитники базы — по `arms/3` (до 8) юнитов из `Gangs.men`, **в группе `east`, если база отнята у Military, и в группе `west`, если у Opfor** (единственное место оригинала, где реально используются юниты на `east`); технические (пикап + 5 оружия + 3000 €) и «реквизиция» техники (аэродром/порт, 50 % цены).

### 6.7 Прочее
- `warAirShow`: в воскресенье в 14:00 при напряжении < 70 и агрессии Military < 40 — авиашоу над городом с аэродромом (`festStart`).
- `armyDo "revoke"`: при провале контрабанды отзывает лицензии `contractor` и `military`; `armyMen` отбирает пехотные классы (с оружием, без пилотов/экипажей/офицеров) и пассажирские грузовики (≥6 мест) для отрядов.

### 7.1 Каталог зданий `ALS_houses` (генерация мира)
- `houseTable` строит хэш `ALS_houses` один раз при загрузке (на всех машинах, не публикуется — каждая машина считает сама по одной и той же карте). Ключ — `houseKey(posASL)` = `"h_<round x>_<round y>"`. Значение: `[posASL, модель, площадь, комнаты, город, цена, тип, состояние]` (`select 0…7`; тип и состояние читаются через `param [6, "Home"]` / `param [7, "Good"]`).
- Тип: `Home` | `Shop` (в т.ч. «medical») | `Industrial`; состояние: `Good` | `Abandoned` | `Wrecked` (множители цены 1 / 0,7 / 0,35). Для не-промышленных зданий нужно ≥ 2 комнат, для `Industrial` — площадь ≥ 120 и ≥ 1 комната.
- Базовая цена: обычная `15000 + площадь·110 + min(комнаты, floor(площадь/20))·2600`; промышленная `30000 + площадь·70`. Множитель города: деревня 0,75 / городок 1 / город 1,3 / столица 1,6 (вне города 0,6); множитель типа: Home 1, Shop 1,3, Industrial 1. Результат округляется до 500 €, минимум 5000.
- **Сохранённые «лишние» дома:** `houseKeep` читает `house_info` из БД; ключи принадлежащих игрокам зданий, которых нет в каталоге текущей карты/сборки (`ALS_houseExtra`), добавляются обратно с записью в лог и публикуются (`publicVariable "ALS_houseExtra"`). Так покупка не пропадёт, если алгоритм каталога изменился.
- `houseObj(key)` — объект здания: `nearestTerrainObjects` в 3 м, у которого **модель совпадает** с сохранённой. `houseFloor(obj)` — позиции `buildingPos`, лежащие в пределах 1,2 м от самой нижней (первый этаж); `houseSpot` — первая такая точка (место пробуждения/появления).

### 7.2 Цены, покупка, продажа
- **Реальная цена** — не поле каталога, а `housePrice(key)`: `round(цена·(0,8 + 0,4·p)·(0,85, если p < 0,35 и дом числится в ALS_emptyHomes)·опция "prices"/100)·100`, где `p` — показатель благополучия города `ALS_townState[город][0]` (0…1, по умолчанию 0,5; `townPulse`: `0,6·занятость + 0,4·min(траты на жителя/8, 1)`). То есть цена домов в городе плавает в пределах ±20 % вместе с экономикой, а в вымирающем городе (p < 0,35) пустые дома ещё на 15 % дешевле.
- `houseBuy [unit, key]` (RPC на сервер): игрок ≤ 40 м от точки дома; здание свободно (`ALS_owned`) и не в `ALS_reserved`; для типов не `Home` нужна лицензия `business`; оплата `moneyPay` (банк → наличные); `houseClaim` атомарно (`isNil {…}`) проставляет `ALS_owned[key] = uid`. Если проиграл гонку — деньги возвращаются. Событие обучения `house_buy`.
- `houseClaim`: если у игрока ещё нет `home_<uid>` и здание — `Home`, оно становится главным домом; ставит `home_ever_<uid>`; `housePublish`; `civEvict` (жители, у которых это был дом, переезжают: «had to move out…» в новости города); для `Home` создаётся склад (`stashCreate`).
- **Продажа** `houseSell` (владелец, либо основатель компании-владельца): выручка = 70 % `housePrice` (округляется до 100); для стартового дома («подарок») — 0 и дом возвращается совету. Условия отказа: склад не пуст и негде его разместить (нужен другой дом того же владельца, не арендованный и не бизнес); в мебели-хранилище (холодильники и пр.) лежат вещи. Содержимое склада переносится на склад другого дома; арендный/запертый статус снимается; если был главным домом — главным становится «следующий» дом (или пустой). Купленная мебель возвращается по 50 % цены (подарочная не оплачивается); бизнес в здании ликвидируется с выплатой 60 % рыночной цены остатков. Деньги зачисляются **в банк** (`moneyAdd [owner, 0, got]`).
- **Главный дом** (`houseMain`): только `Home`, не арендованный; пишет `home_<uid>`; от него зависит `homeRespawn`.
- **Замки** (`houseLock`): `canUse` (владелец или член компании-владельца) → `houseDoors` ставит на **объект здания** переменные `bis_disabled_Door_<i>` (1…`numberOfDoors`, public); список `locks` в БД. Нельзя запереть/открыть арендованный дом. `houseLetOut` — изнутри здания на 15 с открывает запертую дверь и запирает снова.
- **Публикация** (`housePublish`): БД-ключи `houses` (пары ключ→uid), `house_info` (запись каталога для каждого принадлежащего здания); `ALS_ownedPublic` = `[ключ, pos, uid-владельца, город, комнаты, цена, заперт?, сдан?, главный?]`; переустанавливает `ALS_stashOwner` на ящиках.

### 7.3 Права доступа и компании
- `canUse(uid, owner)`: владелец == uid, **или** uid ∈ `ALS_companies[owner].members` (владельцем может быть id компании). `mine(owner)` (клиентская проверка для действий): владелец == свой uid или == `player.ALS_company`. Поэтому компания может владеть недвижимостью, а действия над ней доступны всем её участникам; продавать (`houseSell`) — только основатель.
- Так же устроены склад (`ALS_stashOwner`), мебель (`ALS_furnOwner`), бизнес.

### 7.4 Аренда и жильцы
- `houseLease [unit, key, on]`: сдача дома — `ALS_leased` + запирание дверей; если дом был главным, главным становится другой незанятый дом владельца. Доход: `leaseLoop` (spawn-цикл, **раз в 60 с игрового `sleep`**, т. е. реального времени сервера) зачисляет на **банк** владельца `цена·ALS_rentRate(0,004)/60·mult`, где `mult` — 4-й столбец репутационного тира владельца **в городе дома** (см. 5.x), дробный остаток копится в `_owed`. Если жилец просрочил (`ALS_tenants[key][1] > gameHours`), за этот цикл ничего не платят. Поскольку `leaseLoop` не зависит от скорости времени и считает 60 с, при `timeSpeed` ≠ 1 ставка «в игровой час» не совпадает с реальной; сообщение «€ an hour» — условное.
- Жильцы (`lifeHour "tenants"`, раз в игровой час): жителя выбирает `pick` среди гражданских города (если нет — из всех); у каждого `honesty` из `civTraits`. При `honesty ≤ 3` с шансом 15 % аренда задерживается на 12 ч (сообщение владельцу); с шансом `3 % + 1 %·(5 − honesty)` в час — «прорвало котёл»: счёт 150…600 € (`moneyOwe`, а не `moneyAdd`) на владельца. Хранится в БД `tenants`, публикуется `ALS_tenantsPub` (имя, просрочка?). Выселение (`houseLease off`) удаляет жильца.
- Автономные гражданские (`civs`) покупают дома сами: цель `home` из `lifeHour` — при 15 000 € у жителя и шансе 20 % он занимает свободный `Home` в статусе `Good` в своём городе (не в `ALS_reserved`), в новостях города — «has a home of their own». Свободные дома для гражданских берёт `civFreeHome` (сначала `Good`, затем `Abandoned`, никогда `Wrecked`, не в `ALS_reserved`).

### 7.5 Улучшения дома и охрана (`homeDo`, `homeTick`)
- `homeDo [unit, op, key]` (проверка `canUse`): `alarm` — 1500 €, `dog` — 2500 € (оплата **из банка**: `moneyAdd [uid, 0, -price]`; при нехватке отказ); `guard` и `manager` — переключатели (найм/увольнение), стоят 120 / 200 € **за игровой час**: `lifeHour "staff"` ежечасно вызывает `moneyOwe` у владельца (при нехватке денег копится долг). Данные: БД `house_up`, `ALS_houseUp[key] = ["alarm","dog","guard","manager"]`, публикуется `ALS_homePublic` для телефона.
- `homeTick` (CBA PFH `homeInit`, каждые 5 с реального времени), три задачи по таймерам `time`:
  1. **Ограбление домов игроков** (раз в 60 с): для каждого склада дома, если ни один игрок не ближе 300 м и в нём есть вещи: шанс 0,2 %/мин днём и 0,4 %/мин ночью (23:00–06:00). `guard` защищает полностью; приписанный к дому телохранитель (`bgPosted`) отгоняет и шлёт сообщение; `dog` отменяет попытку с шансом 80 %; `alarm` вызывает полицию (`lawDispatch … "scene"`), кража не происходит; иначе удаляются 1–2 случайные позиции (типы: предметы/оружие/магазины), копия в БД (`stashSave`), сообщение владельцу и 50 % — новость города.
  2. Раз в 60 с — `weatherTick` и `marketStalls` (поиском по всем функциям подтверждено: **других вызовов нет**, погода и рынки живут только за счёт этого PFH). `weatherTick`: следующая смена через 2400–5400 с реального времени; веса ясно 0,45 / облачно 0,35 / волнение 0,2; во время экономического события `storm` держится шторм; применяется через **`remoteExec ["call", 0]`** (сервер исполняет на всех машинах код `1200 setOvercast …`). `marketStalls`: по выходным (`weekendMarket`) и когда игрок ближе 700 м к городу/деревне создаёт на ровном месте три навеса с товарами и двух «Market vendor»; удаляет, когда выходные кончились или игрок дальше 1200 м.
  3. Раз в 15 с — собаки: если игрок ≤ 400 м от дома с `dog`, создаётся агент `Alsatian_Random_F` (метка «Guard dog»), возвращается к дому при уходе > 30 м, удаляется при отсутствии игроков.

### 7.6 Склады дома и схроны жителей
- `stashCreate [key, cargo, at]`: ящик `Box_NATO_Equip_F` на самой высокой точке первого этажа (`houseFloor`, последняя точка), `allowDamage false`, ACE-переносимый/перетаскиваемый; переменные `ALS_stashHouse`, `ALS_stashOwner` (public). Создаётся для **каждого** принадлежащего дома типа `Home`, в `houseInit` восстанавливается из БД `stashes` (`[key, [items, weapons, mags, backpacks], [posASL, dir]]`). Другие типы зданий склада не имеют.
- `stashSave` (в `worldSave`) также сохраняет ящики лагерей (`campbox_<uid>`).
- Просмотр чужого склада (`InventoryOpened` на клиенте): ящик `ALS_stashOf` (схрон жителя) впервые открытый — немедленно преступление `burglary` (`lawCrime`); у своих и компании доступ открыт; чужой — «stash is locked», инвентарь не открывается; запертый `ALS_armouryLocked` — отказ.
- `homeStash "tick"` (из `lifePlaces`, опция `homeStashes`): схрон жителя существует **не в каждом доме, а только в каждом 7-м по детерминированному хэшу ключа** (`хэш(key) mod 7 == 3`), только `Home`, не принадлежащем игроку, не зарезервированном, где ≥ 1 игрок в радиусе 40 м и есть первый этаж. Ящик `Box_Syndicate_Wps_F` (иначе `Box_NATO_Wps_F`) создаётся с содержимым `fill`: 1 оружие (2 — в городах из `ALS_gangTowns`), выбранное детерминированно из всех «видимых» орудий конфига (`scope 2`, тип 1/2, с магазинами) + 2…4 магазина + 2 предмета из `[FirstAidKit, ItemWatch, ItemRadio, ItemCompass, Binocular, ItemGPS]`. Когда игроков рядом нет — ящик сохраняется в БД `stash_<key>` (оружие, магазины, предметы, игровые часы) и удаляется; сохранённое старше 168 игровых часов с пустым оружием обнуляется и ящик генерируется заново. Общий список орудий `ALS_stashGuns` создаётся при первом вызове `homeStash "fill"`; для этого `manhunt`, `warSquad`, `warSupport`, `warTowns` тоже вызывают `fill`.
- Побочный эффект сохранения: ключ `stash_<key>` создаётся на каждый посещённый «схрон-дом» — число ключей БД растёт с исследованием карты.

### 7.7 Лагерь (`campPlace`, `campRestore`)
- Лагерь — «дом» бездомного: `campPlace [uid, pos, dir, restore, avoid]` ищет ближайшую плоскую точку (до 9 попыток по 40+i·15 м, не ближе 10 м к дороге и не на «взлётной полосе» из `avoid`), ставит хижину (`Land_Slum_House02_F` → … → `Land_Shed_02_F`), ящик `Box_NATO_Support_F` (`ALS_stashOwner = uid`, содержимое из БД `campbox_<uid>`) и топливную точку; публикует `ALS_campsPublic` (позиция, класс, город, тип «Hut»/«Shack» — «Shack», если по краям 60 м вода). БД `camp_<uid> = [pos, dir]`, `home_ever_<uid>`.
- `campRestore` (при старте) обходит **все ключи `ALS_db`** и пересоздаёт лагеря (`camp_*`) и расчищает ВПП (`strip_*`, `stripClear`).
- Порядок при респауне: `homeRespawn` сначала проверяет `lawRejoin` (заключённый возвращается в тюрьму, на этом всё), затем отдаёт приоритет 1) главному дому (`home_<uid>`), если он жилой и не арендован; 2) лагерю; 3) другому дому владельца (не бизнес) — записывается как новый главный; 4) возле своей машины; 5) точке `starter_spot`. Если места нет или оно в воде, подбирается ближайшая суша (`landPos`) — «moved to land». Всё пишется в лог («Respawn: uid at grid (…)»).

### 7.8 Стартовый дом и «подарочная» мебель
- `starterHome`: ближайший из шести ближайших городов (`village/town/city`), в котором есть свободный `Home` с 2…6 комнатами; предпочитаются `Abandoned`, затем самые дешёвые 1/3 списка, выбирается случайно; `houseClaim` + `furnStarter` (кровать, стол, 2 стула, стеллаж «в подарок» — `ALS_furnGift`, 0 €, продаётся за 0) + БД `starter_home_<uid>`, `ALS_starterHome` на юните.
- Подарочный дом продаётся «обратно совету» за 0 €, но игрок получает деньги за купленную им мебель.

### 7.9 Мебель
- **Каталог:** `furnCatalog` строится из `CfgVehicles`: `scope 2`, непустое имя и **editorCategory содержит «furniture»** (группа по `editorSubcategory`: Residential→Living, Office→Office, Camping/Beach→Outdoor, Electronics, Food→Kitchen, Medicine→Bathroom, Storage→Storage, иначе Other) либо подкатегория Electronics в «things»; плюс по правилам из конфига `ALS_Furniture` (`categories`, `words`, `classes`, `exclude`, `prices`) для остальных предметов с проверкой «пригодности» (есть модель, не техника/человек/животное/оружие на земле); +4 фиксированных «мастерских» предмета (лампы для выращивания, бочка-самогонный куб, плитка). Предметы любых модов с такой категорией попадают в каталог автоматически.
- **Цены** (`furnPrices`, публикуется `ALS_furnPrices`): по габаритам `createSimpleObject → boundingBoxReal`: `(40 + объём·260)·(2,2 для Electronics)`, шаг 5, 20…6000; предметы длиннее 4,5 м исключаются; фиксированные цены из конфига имеют приоритет.
- **Размещение** (клиент): «Furnish» в действии над своим домом → окно `furnish` (HTML), выбор → «призрак» (`furnGhost`: `createSimpleObject`, луч камеры 8 м; Q/E — поворот на 15°, Shift — 1°, Esc — отмена, ЛКМ — поставить; можно ставить **только внутри габаритного бокса своего дома**: проверка `boundingBoxReal` каждого своего дома). Сервер `furnPlace`: проверка прав, не арендован, цена существует, здание ≤ 30 м от точки, оплата `moneyPay`; создаёт объект `createVehicle`, `enableSimulationGlobal false`, `allowDamage false`, `ALS_furn=key`, `ALS_furnOwner`; предметы-хранилища (`maximumLoad`/`transportMax…` > 0) получают инвентарь.
- **Перемещение/возврат** (`furnPickup`): владелец; хранилище должно быть пустым; «Move this» (перенос без оплаты через призрак с `back`), «Pick up (80 % back)» — возврат 80 % цены (подарочная — 0). Холодильник/морозилка с рыбой (`coldDo`) — «cold store» для улова.
- **Сохранение** (`furnSave`, `worldSave`): `furniture = [ключ, класс, posASL, dir, up, gift, содержимое]`; `houseInit` восстанавливает только для **принадлежащих** сейчас домов (иначе запись молча теряется).
- Особенность: мебель не имеет симуляции — отключены физика и урон; переменная `ALS_ghost` (HashMap: объект-призрак, класс, поворот, ключ дома, флаги, обработчики) — единственное клиентское состояние режима размещения; `nil` означает «не размещаем».

### 7.10 Бизнес (`biz*`)
- **Условия:** только здания `Industrial` (покупка — лицензия `business`); `bizSet [unit, key, use, recipe]` выбирает назначение: `Warehouse` (склад), `Factory` (завод; нужен рецепт из `ALS_Recipes`), `Garage` (гараж/мастерская), `Shop` (магазин); хранится `ALS_biz[key] = {use, recipe, inv, made, sold, income, prog, acc}`.
- **Ёмкость:** `bizCap = round(clamp(площадь/[4, 6, 8][Warehouse, Factory, Shop], 20, 600))`. `bizStore` — на кнопке «Store crates here» складывает ящики `Land_WoodenCrate_01_F` в радиусе 45 м (игрок ≤ 60 м) в инвентарь бизнеса; `bizTake` создаёт ящики обратно и грузит в ближайшую свою машину ≤ 45 м.
- **Тик** `bizTick` (spawn-цикл `bizLoop`, раз в 60 с): 
  - *Factory*: производит партии по `perHour` рецепта; зарплата `wages·h·upkeep` списывается с владельца.
  - *Garage*: 2 заказа/час, расходуют `parts`, доход +300 € за заказ; каждый принадлежащий игроку `Garage` становится сервисной точкой (`garagePublish`: радиус действия 60 м; кроме них — «станции» 60 м, аэродромы 450 м, порты 200 м; публикуются `ALS_garagePos`, `ALS_garageReach`); `vehDo` (ремонт/страхование и т. п.) находит ближайший гараж (`garageAt`) и платит его владельцу за выполненную работу («Your garage did a job: …»).
  - *Shop*: продаёт запас по рыночной цене города, цена ×1,1; менеджер +10 %; налог мэру; в освобождённом игроками городе налог идёт освободителю.
  - БД `biz` (охраняется `dbLoading`); публикации `ALS_bizPublic`, `ALS_recipeList`.
- Продажа дома с бизнесом ликвидирует запас (60 % цены) — см. 7.2.

### 7.11 Заведения (`venue*`, `place_*`) — «Places»
**Идея.** Магазины, кафе, бары, мэрия, полиция, клиники, мясные лавки, автосалоны, оружейные, торговцы — это не отдельные модели, а **реальные здания каталога `ALS_houses`, зарезервированные под заведение** и обставленные скриптом.
- **Резервирование:** `venue [центр, радиус, тип, мин. комнат, ключевое слово, ближайшее?]` (вызывается из `storeInit`, `clothesInit`, `eateryInit`, `clinicInit`, `butcherInit`, `crimeInit` (скупщик), `dealerSpots`, `traderSpots`, `lawInit` (участок полиции), `rivalOpen` (штаб банды)) ищет в `ALS_houses` лучшее здание в радиусе: состояние `Good`, не в `ALS_reserved`, не принадлежит игроку (учитывает ключи `houses` из БД!), подходит по типу/комнатам/ключевому слову в модели (`shop`, `hospital`…), «на земле» (`venueGround` — самая низкая точка `buildingPos` ≤ 2,5 м над рельефом). Оценка = `площадь − 0,4·расстояние` (или просто ближайшее); если ключевое слово не медицинское, здания с «hospital/medical/clinic» в имени модели исключаются. Выбранный ключ добавляется в `ALS_reserved` (публикуется) — **такие здания нельзя купить и в них не селятся жители** (проверки в `houseBuy`, `houseActions`, `starterHome`, `civFreeHome`, `civLoad`, `lifeHour`, `homeStash`, `coopJob_heist`).
- **Реестр** `ALS_venues` (`venueInit` вызывается в конце `siteStaffInit`): для каждого NPC-места (`ALS_npcSpots`) с ролью, совпадающей с `meta.role` некоторого `place_<kind>`, находится зарезервированное здание в 25 м; создаётся запись `{kind, key, town, spot, shown, props, busy}`; для заведений с персоналом регистрируется «рабочая точка» `ven_<key>` и нанимаются гражданские (`venueHire`).
- **Метаданные заведений** (`place_<kind> "meta"`, прочитаны все 12):

- **План здания** `venuePlan` (по приближению игрока < 1500 м, не более 1 заведения за тик): `venueFloor` растеризует пол здания сеткой 0,75 м лучами (`lineIntersectsSurfaces`), находит стены; `venueDoors` определяет фронты и двери (ближайшие к улице первыми); выбирает комнату у входа, точку продавца (ближе к стене, лицом к двери), прилавок, место клиента, очередь, полки (до 5), места у полок, столики. Если здание не годится («фасадное» без интерьера — меньше 10 точек/4 стен), продавец стоит перед дверью (`front: true`). План кэшируется (`ALS_venuePlans`).
- **Показ** (`venueTick` вызывается из `lifePlaces`, а та — из `lifeLoop` каждым пятым «срезом», т. е. примерно раз в 10 с): ближайшие 3 заведения в 450 м (и только если в радиусе здания +3 м нет игрока) получают реквизит (`venueShow`: прилавок, полки, мебель, столы со стульями, «extras», товары на полках, припаркованные машины, участки `lot`); скрываются, когда игрока нет ближе 650 м (`venueHide`). Реквизит — обычные `createVehicle` без симуляции; проверки ограждений, пола, пересечений, людей внутри. Товары (`venueGoods`) заполняют полки в долю `venueStock` (−5 % за каждый визит с последнего пополнения; шторм ×0,5; забастовка в городе ×0,67; минимум 20 %).
- **Персонал и смены** (`venueHire`): три смены (утро/день/ночь) для закрывающихся — одна или две; нанимаются гражданские без рабочего места и работодателя (сперва безработные, иначе любые), чей дом не дальше 2500 м (12 000 м, если у жителя есть машина). `venueClerk` создаёт юнита-продавца (`civBorrow` «берёт взаймы» гражданского из виртуального мира: тот на смене не живёт «виртуально»), отключает ему `MOVE/PATH/FSM/AUTOCOMBAT`; `venueShift` обеспечивает смену: пришедший «сменщик» идёт к прилавку, ушедший уходит домой и удаляется.
- **Посетители** (`venueVisit`): гражданские «заходят»: смотрят полки (15–50 с), встают в очередь (до 60 с), подходят к прилавку, обмениваются жестами (торг), забирают товар (`venueGoods take`: исчезает один предмет с полки, у гражданского в руке корзина 3 мин), для сидячих заведений садятся за стол на заданное время. Максимум одновременных клиентов 4 (10 для сидячих).
- **Заказы игрока** (`eateryOrder`): нужно находиться ≤ 8 м от прилавка и быть обслуженным (`serveAt`: отказ, если продавец мёртв, обезврежен/в наручниках или для игрока идёт охота — «They know who you are…»); цена = `меню·опция "prices"·мнение продавца` (`counterPrice`: `opinion "price"` — мнение продавца об игроке; < 0 = отказ; торг ×0,9 действует определённое время); выдача предмета (ALS_coffee/pastry/souvlaki или ACE-вода) или эффект (`eateryEffect`: уменьшение ACE-жажды/голода; **алкоголь** — размытие DynamicBlur, накапливается за 30 мин, 3+ напитка — предупреждение «Maybe don't drive»).
- **Клиника** (`clinicDo`): `ask` — расчёт счёта по ACE-состоянию (`clinicState`: кровопотеря, раны, переломы, боль → `clinicBill`: `40 + 150·потеря + 10·раны + 60·переломы + 20 (боль)`, ×опция цен); игрок лечится на месте `clinicCare`; по окончании (`done`) списывается `moneyOwe` (недостающее записывается как долг, «comes out of your pay») и вызывается `ace_medical_treatment_fnc_fullHealLocal`; **если игрок в розыске — запись розыска обновляется** («Someone at the clinic recognised you»). Закрыв окно раньше — «left» без оплаты.
- **Резервирование больниц:** если найдены реальные медицинские здания, резервируются все медицинские здания в 80 м вокруг выбранной; иначе клиника ставится в обычном магазине-здании.

### 7.12 Действия игрока над недвижимостью и миром (`houseActionsUnit`)
Весь клиентский набор действий вешается на **каждое новое тело игрока** (`CBA_fnc_addPlayerEventHandler "unit"`), условия вычисляются каждый кадр движком. Ключевые зависимости:
- Объект «под взглядом»: PFH каждые 0,25 с берёт `cursorObject` ≤ 25 м (не в технике), через `houseKey(getPosASL)` получает ключ, требует `getModelInfo` == сохранённой модели; переменные `ALS_lookHouse`, `ALS_lookHouseObj`.
- Действия дома: *Buy this house*, *Lock/Unlock the doors* (по `bis_disabled_Door_1`), *Store crates here* (только не-`Home`), *Furnish*, *Throw a party here* (`Home`, 17:00–01:00), *Let yourself out* (если дом чужой и заперт, а игрок внутри габарита).

## 8. Деньги, банк, долги, «грязные» деньги, лицензии, компании, политика городов, наследие

Прочитано построчно: `moneyAdd/Pay/Get/Owe/Fine/Mirror`, `payMods`, `debtPay`, `bankMove`, `bankLoan`, `loanDo`, `launder`, `launderCap`, `fmtNum`, `licInit/Has/For/Grant/Buy/Open/Push`, `companyInit/Of/Publish/Save/Do`, `townPolitics`, `townPulse`, `townAt`, `voteShare`, `haulProfile`, `haulRank`, `msgSend`, `notify`, `legacy`, `legacyBiz`, `legacyDo`, `legacyKidnap`, `serveAt`, `counterPrice`; блок «банк/аренда/персонал» в `lifeHour`; `ALS_Licenses` и `ALS_Goods` из `config.bin` (разобрано собственным читалкой рапифицированного конфига, `index/config_dump.txt`).
Не читал: `civEconomy` (зарплаты и налоги гражданских, вызывает `loanDo tick` и `townPolitics tick`) — в разделе «мир»; `forgeDo`, `bookie`, `cashVan`, `drugDo`, `smuggle*`, `uwEarn`, `ruinDo` (источники «грязных» денег) — в разделе «подполье»; `piJob`.

### 8.1 Кошелёк: ключи и атомарные операции
- Баланс игрока: `money_<uid>` = `[наличные, банк]`; компании: `money_co_<N>` (`[0, банк]`). Значения всегда округляются (`round`) при записи, **дробные суммы теряются** — поэтому `leaseLoop` копит дробную часть сам.
- Все операции — серверные (`moneyAdd` имеет `if (!isServer) exitWith {false}`):
  - `moneyAdd [uid, Δналичные, Δбанк]` → `true/false`; если любой из балансов уйдёт в минус — отказ без записи. После записи — `moneyMirror` (в `ALS_money` и `ALS_debt` на объекте игрока, public). Это **единственная точка записи**; `bankMove`, `houseSell`, `furnPickup` и наши выплаты идут через неё.
  - `moneyPay [uid, цена]` → `true/false`: сначала **банк**, затем наличные (`fromBank = min(цена, банк)`). Отказ, если `наличные + банк < цены`.
  - `moneyOwe [uid, цена]` → `[заплачено, долг]`: списывает сколько есть (банк, затем наличные), недостающее добавляет в `debt_<uid>` (кроме компаний `co_*`). Используется для обслуживания, которое нельзя «не оплатить» (клиника, аренда машин, ремонт, зарплата охраны/менеджера, счёт сантехника, налоговые сборы).
  - `moneyFine [uid, сумма, owe?=true]` → фактически списанная сумма (штраф: банк, затем наличные); недостача по умолчанию становится долгом. Это путь штрафов (полиция, КПП, ATC, `bankMove`, `launder`…).
- `fmtNum` — формат «12,345»; `payMods` — модификатор оплаты работ (ниже).
- Сами `moneyAdd/Pay/Owe/Fine` — внутренние серверные функции, проверок отправителя в них нет. Клиентские точки входа (`remoteExec … 2`): `bankMove`, `debtPay`, `licBuy`, `companyDo` берут `_unit` из аргумента **без** сверки с `remoteExecutedOwner`; `bankLoan`, `launder`, `legacyDo`, `legacy "pub"` такую сверку делают.

### 8.2 Оплата работ и долг (`payMods`)
Вызывается при выплатах за курьера, развозку, пассажиров, такси (`courierDrop`, `jobDeliver`, `paxTick`, `taxiTick`):
- ночью 22:00–05:00 **+25 %**; для лодок при `weather == "rough"` **+40 %**; затем × опция мира `pay`; округление; игроку приходит строка «Extra on that one: …».
- если у игрока есть долг (`debt_<uid> > 0`) — **25 % выплаты (не больше долга)** уходит на долг. Это единственный автоматический механизм погашения. **Выплаты аддона (`coopEnd`/наша логика) не проходят через `payMods`**: ночных надбавок, опции `pay` и удержания долга для них нет.
- `debtPay` (телефон, «Банк»): гасит долг из **банка** (не из наличных): `min(долг, банк)`.

### 8.3 Банк, кредит, проценты
- `bankMove [unit, сумма]`: положительная — внесение (наличные → банк), отрицательная — снятие. Работает через `moneyAdd [uid, −сумма, +сумма]`.
- **Кредит** `bankLoan` (с проверкой отправителя): нельзя при долге > 0 и при открытом кредите; сумма — `credit_<uid>` (по умолчанию 10 000); игрок получает её в банк; создаётся долг `credit·1,1` (10 % сверху), флаг `loanOpen_<uid>`. Возврат — только через общий долг (25 % выплат или `debtPay`). Как только кредит погашен (`lifeHour "bank"`), лимит удваивается (`min(credit·2, 160 000)`) и приходит письмо банка.
- **Проценты** (`lifeHour "bank"`, проверка каждый игровой час по `interestDay_<uid>`): первым часом нового игрового дня начисляется `min(банк·0,5 %, 2000)` на банк. Начисление получают только игроки, которые в этот час онлайн и живы (цикл по `allPlayers`).
- Негласное правило «грязных денег»: счётчик `dirty_<uid>` (число, не привязано к купюрам) растёт от преступных заработков: телохранитель-«дело» (`bgJob`), букмекер, инкассатор (`cashVan`), ограбление (`coopJob_heist`), наркосбыт (`drugDo`), раскопки (`ruinDo`), три вида контрабанды (`smuggleDeliver/Drop/Hand`), подпольный заработок (`uwEarn`: ×60 за единицу), сбор долга ростовщика. При внесении `bankMove` часть, равная `min(сумма, dirty)`, считается «грязной»; сверх **2000 €/игровые сутки** (`dirtyIn_<uid> = [день, сумма]`) штраф **25 % от превышения** (`moneyFine`) и письмо налоговой.
- **Отмывание** `launder [unit, key, n=1000]` (с проверкой отправителя; действие «Put 1,000 € through the books»): здание игрока (не `Home`) в пределах 30 м, нужны `n` наличными; 90 % уходят в банк (`−n` наличными, `+0,9n` банк), `dirty_` уменьшается, `laundered_<uid>` растёт. Дневной лимит бизнеса: 1000 € (магазин) / 2000 € (иное), ×1,5 если бизнес уже что-то продавал; при превышении — 50 % шанс проверки: штраф 40 % от `n` (деньги при этом всё равно остаются на счёте). Дневной счётчик хранится в записи бизнеса `ALS_biz[key].laundered = [день, сумма]`; запись создаёт `bizGet` (по умолчанию `Warehouse`, для `Shop` — `Shop`).
- **Наследие/аудит** (`legacy "hour"`): при «доле экономики» игрока ≥ 25 % раз в 72 игровых часа налоговая «изымает» половину `dirty_` из **наличных**. Тонкость: возвращаемое значение `moneyAdd` не проверяется — если наличных меньше половины счётчика, деньги не списываются (операция отклонена), но счётчик `dirty_` всё равно уменьшается и приходит сообщение «Audit: … seized».

### 8.4 Ростовщик и займы жителям (`loanDo`)
- «Дать в долг» жителю (диалог `loan:fair`/`loan:shark`): у жителя < 300 € и нет займа; игрок платит 500 €, житель обязуется вернуть 575 € (честный) / 800 € (акула, нужна уличная репутация ≥ 30) за 48 игровых часов; мнение жителя `opinion +10 / −10`.
- `loanDo "tick"` (из `civEconomy`): после срока и при деньгах у жителя возврат на счёт игрока (в **банк**); честный заём списывается как невозвратный через 72 ч; займы «акулы» живут, пока их не взыщут.
- `collect` (только для «акулы» после срока): забирает всё, что есть у жителя, до долга; если не хватает — машина за 1500 €; деньги **наличными** и зачисляются в `dirty_`; мнение −50.

### 8.5 Лицензии
- Список — из конфига `ALS_Licenses` (`licInit`): `[имя, цена, ранг доставки, covers[], описание]`. Всего 13 (цены €): `driving` 0 (car/offroad/van/sports/supercar/motorbike), `truck` 6500 (truck, bus; ранг 1), `taxi` 2500, `boat` 4500 (boat/speedboat/ferry), `heli` 28 000, `plane` 35 000, `weapons` 15 000, `business` 12 000, `mechanic` 3000 (+ ToolKit), `contractor` 15 000, `military` 25 000, `press` 1500, `hunting` 1200. Остальные моды/аддоны добавляют класс в `ALS_Licenses` (так делает аддон: `alspmc_pmc`).
- Хранение: `lic_<uid>` — массив id; **поддельные** лицензии `fakelic_<uid>` — хэш id → …; `licHas` засчитывает обе. Поддельная лицензия проверяется и снимается на КПП (`jobEv_checkpoint`).
- Покупка `licBuy [unit, id]`: нужен **клерк** (`serveAt` с ролью `clerk`, ≤ 15 м; ратуша), ранг доставки `haulProfile` ≥ требуемого, оплата `moneyPay`; `licGrant` пишет `lic_<uid>` и `ALS_lic` на юните; событие обучения `lic_<id>`; для механика выдаётся ToolKit в рюкзак (или новый рюкзак) через **`remoteExec ["call", unit]`**; повторная покупка механика без ToolKit — 250 € за новый.
- `licFor(категория)` возвращает id лицензии, покрывающей категорию машины (для проверок вождения).
- Окно лицензий (`licOpen/licPush`): отдельный HTML-экран, обновляется раз в 0,5 с, только при изменении JSON.

### 8.6 Ранги доставки (`haulRank`, `haulProfile`)
`stat_jobs_<uid>` (число выполненных работ) → ранг: Courier (0, грузоподъёмность 5, множитель 1,0), Driver (4, 8, 1,1), Hauler (10, 11, 1,25), Long-hauler (20, 14, 1,45), Road legend (40, 14, 1,7). `haulProfile` = `[макс. грузоподъёмность своей наземной машины (без truck-лицензии не больше 8), ранг, имя, число работ, порог следующего, слоты, множитель, имя следующего, морская грузоподъёмность]` (последний элемент 0 без boat-лицензии). Ранг нужен и для покупки лицензии (`truck` требует ранг 1).

### 8.7 Компании (`company*`)
- Состав: `ALS_companies[id]` = `{id "co_N", name, founder, members[], names{uid→имя}, jobsTo(bool), ledger[], since, stakes{uid→доля вклада}, gifts{ключ→uid-даритель}}`; БД `companies` (список «ключ→значение» для каждой компании, **вложенные хэши сохраняются как есть**); защита `dbLoading "companies"`; `ALS_companySeq` = максимум суффикса при загрузке.
- Основание `found`: игрок — лидер крю, в крю ≥ 2 человек, не состоит в компании; 2500 € **из банка** (`moneyAdd [uid, 0, −2500]`); имя «<фамилия> & Partners»; участники — члены крю, ещё не имеющие компании; `jobsTo = true`: награда крю-работ идёт на **банк компании** (см. 3.x `coopEnd`). Один игрок — одна компания (`companyOf` берёт первую по `members`).
- `deposit/withdraw` (вклад/снятие, банк↔банк компании): снять можно не больше своего вклада (`stakes`), основатель — любую сумму; при первом обращении для старых компаний доли выставляются поровну от текущего баланса; журнал `ledger` (30 записей, 8 в интерфейсе).
- `jobs` (основатель) переключает, куда платят крю-работы (на каждого / в компанию). `add/remove` — только основатель и только из своего крю; `leave` — участник уходит, его «подаренные» владения возвращаются; основатель, выходя, **закрывает** компанию: банк делится поровну между участниками (остаток от округления остаётся в удалённом ключе), недвижимость возвращается дарителям (`gifts`) или основателю.
- `give` — передать свою недвижимость компании (пропадает «главный дом»); `ALS_owned[key] = id компании`. Дальше права проверяются через `canUse` (см. 7.3), продажа — основатель.
- Публикация (`companyPublish`, PFH каждые 20 с): на каждом игроке `ALS_company` (id) и `ALS_companyInfo` (имя, основатель, `jobsTo`, банк, 8 записей журнала, участники, список недвижимости); пересылается только при изменении. Игрок вне компании очищается.
- Важно: у компании нет собственных налоговых/репутационных данных; её `uid` для `repGet` не определён.

### 8.8 Политика городов и выборы (`townPolitics`)
- `ALS_mayors[город]` = `{who (id жителя либо uid игрока), name, tax (0,05), police (1), next (игровые часы), stand[], fund[[uid, 2000]], backers[]}`; БД `mayors`, публикуется `ALS_mayors`. Старт: мэр — самый «влиятельный» (`people`) житель ≥ 30 лет; даты первых выборов разнесены (24 + (индекс mod 7)·24 ч).
- Выборы раз в **168 игровых часов**: «претендент» — первый заявившийся игрок (`stand`) или (если никто) случайный житель; шанс победы претендента = `voteShare(50 + привлекательность, пожертвования)`, где привлекательность игрока = `(репутация в городе − 40)/4` + голодная община (до +25), пожертвования `fund/500` (каждые 2000 € = +4 п.п., максимум +20), итог в [5 %, 95 %]. Победа: игрок становится мэром (письмо ратуши), либо житель (с `backers` = жертвователи). Если претендент проиграл, власть не меняется. Следствие: мэр-игрок, у которого нет соперника-игрока, теряет пост с шансом ≈ 50 % на каждых выборах (раз в неделю игрового времени).
- Заявиться: репутация в городе ≥ 40, свой дом в городе, 1000 €. `fund` — 2000 € на кампанию претендента. `bribe` (3000 €, только когда мэр — житель) вносит игрока в `backers` («налоговая вас не побеспокоит» — в `bizTick` налог для такого игрока равен 0).
- Мэр-игрок может менять налог на бизнес (0…15 % шагом 5 п.п.) и «полицию» (70…130 % шагом 15 п.п.); значения читают `bizTick` и `lawTick`. Налог в `bizTick` берётся с выручки **магазина** и просто вычитается (мэр его не получает; в освобождённом игроками городе налог переводится освободителю). Множитель полиции `опция police × police города (по последней известной позиции разыскиваемого)` в `lawTick` масштабирует число патрульных машин в погоне (`round(cars по звёздам · множитель)`, минимум 1 при розыске) и интервал между подкреплениями (`20 с / множитель`).

### 8.9 Экономика города (`townPulse`) и влияние на цены
`townPulse` (вызывается только из `civEconomy`) считает для каждого города `ALS_townState[город] = [p, занятость, число жителей]`, где `p = 0,6·занятость + 0,4·min(траты на человека/8, 1)`; при `p < 0,35` банды в городе усиливаются (`strength +1`, максимум 9) и пишется новость «Hard times»; при `p ≥ 0,75` — «booming». От `p` зависят цены домов (±20 %) и список пустых домов `ALS_emptyHomes` (скидка 15 % на пустые). `ALS_townSpend` (траты города за период) обнуляется в конце каждого вызова.

### 8.10 Наследие (`legacy`) — давление на богатых игроков
Часовой (`warTick "hour"`) расчёт трёх «путей»:
- **Экономика** `econ = 100·(богатство игрока)/(богатство острова)`; богатство = деньги + цена недвижимости (`housePrice`) + 0,6·стоимость машин; «остров» = сумма всех игроков, жителей (`money`) и активных соперников. Пороги 10/25/50 дают записи и новости; при ≥ 25 — враждебность самого богатого соперника (`hostility 60`) и **аудит** (см. 8.3); при ≥ 30 — **забастовка** (раз в 72 игровых часа, 12 ч «Nothing of yours runs»), при ≥ 40 — **«рыночный сбор»** 2 % всех денег раз в неделю (`moneyOwe`), при ≥ 35 — **похищение** одного из наёмных жителей (`crew_<uid>`) с выкупом 5 % состояния (5000…50 000, шаг 500) на 48 часов (точка выкупа отмечена на карте, 3 бандита охраняют заложника, выкуп `legacyDo "ransom"` ≤ 30 м). Победа «econWin» — поглощение самой крупной компании соперника.
- **Подполье** `crime = min(50, 10·влияние) + min(25, отмыто/10 000) + уличная репутация/4`, влияние = число купленных начальников станций/портов (`legacyDo`: 5000 € сразу, **500 € в игровые сутки** — `payroll_<uid>`, не заплатил — всё обнуляется) + мэры (свои/подкупленные) + подкупленные командиры. При ≥ 40: формируется «следственная группа» (инспектор в столице), доносы со стороны членов вашей банды (жадность ≥ 8, 25 %/сутки), ликвидация делянок и арест участников; победа «crimeWin» — ограбление банка (`bigheist`) или убийство инспектора.
- **Освобождение** `total = 60·доля_баз_у_игроков + 40·доля_освобождённых_городов` (только при включённой войне); ≥ 50 — новость; победа «totalWin» — все штабы армий взяты.
- Результаты публикуются на телефон (`ALS_legacyPub`, приложение «Legacy»).

### 9.2 Модель рынка города
- **Города с рынком** (`ALS_markets[город]`, `marketInit`): для каждого города по ролям рабочих площадок (`ALS_jobSites`) считаются `prod[товар] = Σ makes·число_площадок_роли` и `cons[товар] = people·число_зданий/100 + Σ uses·число_площадок`. Товар входит в рынок города, если город его производит или потребляет > 0,05; город — если у него есть хотя бы один такой товар.
- **Нормализация по острову:** для каждого товара, у которого есть и производство, и потребление, `cons` всех городов умножается на `ΣP/ΣC` — на острове баланс сходится. Цель запаса `target = max(6, (prod+cons)·6)`; стартовый запас `target·(0,7 при дефиците, 1,3 при избытке)·(0,8…1,2)` либо значение из БД `market_stock`.
- **Тик** (`marketLoop`, раз в 60 с): `stock += (prod − cons)·dt`, где `dt` — **реальные** часы сервера (`time` между вызовами, `ALS_marketSpeed = 1`; ускорение игрового времени не учитывается), в пределах 0…3·target; затем «арбитраж»: если у товара разница долей запаса между самым и самым бедным городом > 0,6, 8 %·запас·dt·4 переходит от богатого к бедному.
- **Цена** `marketPrice(город, товар, сторона)`: `r = запас/target`; коэффициент `f = clamp((2/(1+r))^0,9, 0,45, 2,2)`; `середина = базовая·f`. События умножают на `[покупка, продажа]` (ключи `город|товар`, `*|товар`, `город|*`); дефицит еды (`ALS_shortPub`) ×1,25; **рыночные выходные** (суббота/воскресенье 07–14) для produce/fish/oliveoil/grain: покупка ×0,9, продажа ×1,15; в городах под контролем `Opfor` — детерминированный коэффициент 0,8…1,3 на товар (хэш имени). Итог: покупка `середина·1,08·ev·опция prices`, продажа `середина·0,92·ev`, середина — среднее.
- **Репутация** (тир `repTier`): игрок покупает по цене × `tier[1]` и продаёт × `tier[2]` (см. 5.x); при тире `Hated` торговец отказывает.
- **Публикация** (`marketPublish`, раз в минуту и после каждой сделки): `ALS_marketBoard[город] = {pos, goods{id: {buy, sell, stock, ratio}}}` и `ALS_goodsNames` — публичные; в БД `market_stock` (запас, 0,1 точность).
- **Маршруты** (`marketRoutes`, клиент, для телефона): для каждого товара самый дешёвый город с запасом ≥ 2 и самый дорогой по продаже; восемь маршрутов с максимальной прибылью, плюс прайс-лист ближайшего города с учётом репутации.

### 9.3 Покупка и продажа у торговца (`trade*`)
- **Торговец** — NPC роли `trader` в каждом городе с рынком (`traderSpots`: резервирует здание-магазин через `venue`, иначе стоит у торговой площадки). Окно `trade` (HTML) обновляется раз в секунду.
- **Купить ящик** (`tradeBuy`, режим `crate`): продавец ≤ 15 м (`serveAt`), репутация не `Hated`; цена `marketPrice buy × tier[1]`; на рынке −1 ящик; создаётся `Land_WoodenCrate_01_F` (масса 40, ACE-перетаскиваемый/переносимый, размер по товару) с `ALS_good`, `ALS_owner = uid`, `ALS_boughtAt = город`; сразу передаётся игроку в руки (`carryCrate`).
- **Купить поштучно** (`unit`, только `pack = 1`): до `min(запас·20, 200)` штук по `ceil(buy·tier[1]/20)`; выдаётся предмет `ALS_good_<id>`; запас −n/20; в `ALS_unitBuys[uid|город|товар]` учитывается, сколько куплено здесь, чтобы нельзя было сразу продать обратно с наценкой.
- **Продать ящики** (`tradeSell`): ящики этого товара в радиусе 35 м от торговца (не прицеплены, не рабочие `ALS_job`, свои/команды/бесхозные без контрабанды); цена каждого `продажа × tier[2]`; **если ящик куплен в этом же городе — цена не выше 90 % цены покупки**; ящики удаляются (`crateDelete`), запас +1; оплата в **банк**. **Продать поштучно** (`tradeSellUnits`): те же ограничения; для `fish` 25 % выручки (до долга) идут на погашение долга; если продавец недоступен (`serveAt` отказал), клиент уже снял предметы с игрока, поэтому сервер возвращает их ему через `remoteExec ["call", unit]`; при `Hated` — через `invAdd`.
- **Ограничения доступа:** все ветки требуют `serveAt` (продавец жив, не в наручниках/сдался, нет охоты `manhunt` в этом городе — «They know who you are…»).

### 9.4 Экономические события (`econStart/Tick`)
- Тик `econTick` (CBA PFH из `storyInit`, раз в 60 с): события живут `20 + random 20` минут реального времени (можно задать); одновременно не более двух; следующее — через `(1500 + random 1500)/опция events` секунд (событий нет при `events = 0`).
- Типы (вес): `market` 0,3 — один город, закупка +25 % (`[0,95; 1,25]`); `festival` 0,2 — город (town/city/capital), `groceries/produce/oliveoil/clothing/fish` покупка ×1,15 / продажа ×1,6 и локальный праздник (`festStart`); `strike` 0,2 — город с промышленной площадкой: все товары, в `makes` которых есть роль `industrial`, ×1,45 (покупка и продажа); `fuel` 0,15 — весь остров, `fuel` ×1,6; `storm` 0,15 — весь остров, `fish/steel/clothing/electronics` ×1,4, **рассылка клиентам кода `0 setOvercast 1; 0 setRain 0.9; …` через `remoteExec ["call", 0]`** (в тексте новости порты закрыты; обеспечивается ли это запретом выходов в море — в этом разделе не проверял).
- Публикуется `ALS_econPublic`, пишется новость города/острова и уведомление всем игрокам.

### 9.5 Дефицит еды, протесты (`shortTick`)
`shortTick` (вызывается из `econTick`, т. е. раз в 60 с) считает долю запаса еды (produce/groceries/fish/meat) относительно цели: `< 25 %` — «Empty shelves» (новость), копится «голод города» (`ALS_townFood[город].hungry`, часы), а через 12 игровых часов при 09–15 час, если нет других протестов и прошло ≥ 48 ч с прошлого, — **протест** у ратуши на 4 часа (новость, маркер); восстановление `> 40 %` разгоняет протест. «Голод» добавляет претенденту на выборах до +25 п.п. (см. 8.8). Состояние хранится в БД `townFood`, публикуются `ALS_shortPub`, `ALS_protests`.

### 9.6 Универсальный магазин (`store*`), одежда (`clothes*`), оружейный (`gun*`)
- **Общее:** прилавок = NPC роли `store` / `clothes` / `gunshop`. Покупка идёт через **ACE Arsenal на виртуальном ящике** (`ace_arsenal_fnc_initBox` с ограниченным списком): игрок «берёт» предметы на клиенте, при закрытии арсенала клиент считает счёт по **серверным ценам** (`storePrice`/`clothesPrice`) и отправляет `[player, bill]` на сервер. Сервер **пересчитывает сумму** по отправленному списку и списывает `moneyPay`; **не сверяет**, что предметы действительно оказались на игроке. Если не хватает денег — `storeRevert`/`setUnitLoadout` возвращает прежнее снаряжение клиента. `counterPrice` (мнение продавца) может изменить цену или отказать.
- **Универсальный** (`storeInit`: по одному на город с рынком; здание резервируется через `venue`): прайс — таблица из 47 позиций (медицина ACE 6–300 €; ToolKit 250, кусачки 60, сапёрная лопата 45, стяжки 3, карта-инструменты 15; рация 60, бинокль 120, высотомер 180, microDAGR 300, Kestrel 400, беруши 5; фонари 30–45; хемлайты 4–6; удочка 120, эхолот 450, ловушка на крабов 60) + **автоскан** (`storeScan`) предметов и магазинов любых модов по ключевым словам (медицина — перевязки, жгут, морфин, растворы, `kat_` и т. д.; еда — MRE, вода, консервы и т. д.), с цены по ключу; исключаются боеприпасы, взрывчатка, `als_*`, пустые/полупустые. Цена × опция `prices`. Колесо (`storeBuy "wheel"`): 80 €, `ACE_Wheel` кладётся у ног.
- **Одежда** (`clothesInit`: городки/города с рынком): уровни — униформа 60 €, головной убор 25, очки 15, рюкзак `40 + maxLoad/2`; список из `CfgWeapons/CfgGlasses/CfgVehicles` (униформы только **гражданские** — сторона 3, шлемы без брони (`armor ≤ 0`), очки без ПНВ, рюкзаки с `maximumLoad > 0`, без собираемых, радио и БПЛА-рюкзаков). Платится только за **изменённые** слоты.
- **Оружейный** (`gunBuy`): лицензия `weapons`, продавец ≤ 15 м; список `gunStock` — из каталога `ALS_catalog` (`family weapon`): категории `handgun, shotgun, rifle, sniper rifle`, цена ≤ 12 000 €, по 3 позиции на категорию (перцентили 0/0,35/0,7 по цене), либо список `gunShop`/`gunShopAdd` из конфига `ALS_Weapons`; покупка = оружие + 3 магазина (`giveWeapon`, лишнее — на пол); патроны: `3·max(15, round(цена·0,02/5)·5)`. `gunInHand` — «оружие в руках» для правил города.
- **Расширение модами** (`weaponRules`): все классы `ALS_Weapons >> <мод>` сливаются: `prices` (список `[класс, цена]`) переопределяет цену, `banned` убирает оружие из торговли, `gunShop`/`gunShopAdd`, `fence`/`fenceAdd`, `gunShopKinds`, `gunShopMax`, `fenceKinds`, `fenceMax`. Скупщик (`fenceGuns`) выставляет 3 стволов, выбранных по `npcId`.

### 9.7 Дилеры (`dealer*`)
- **Размещение** (`dealerSpots`): в каждом `city/capital` — «Town hall» (клерк лицензий, здание через `venue` ≥ 4 комнат), автосалон (роль `dealer`, `data = car`); у каждого аэродрома — «Aircraft broker» (`air`); у портов (раз в 4 км) — «Boat dealer» (`boat`). Чёрный рынок (роль `blackmarket`) создаётся в подполье (`blackOpen` — в разделе о подполье, здесь не читал).
- **Каталог** (`dealerStock`): из `ALS_catalog` по категориям: `car` — car/offroad/van/truck/bus/sports/supercar/motorbike; `air` — вертолёты и самолёты; `boat` — лодки/катера/паромы; без полиции, скорой, пожарных, БПЛА; скорость ≥ 15 км/ч; **без вооружённой и военной техники**. У игрока с лицензией `military` список заменяется на `<вид>mil`: вся военная техника (включая вооружённую) и гражданская без оружия. Чёрный рынок (`black`): любая техника скорости ≥ 15 км/ч без артиллерии/тяжёлых боеприпасов и БПЛА, по самой дешёвой версии каждой модели, цена ×1,5.
- **Покупка** (`dealerBuy`, `isServer`): ≤ 40 м от дилера (если место выбрано — в радиусе 120 м для авто / 400 м для самолётов / 300 м для лодок / 150 м для чёрного рынка +100), клерк обслуживает (`serveAt`), класс в списке этого дилера, лицензия категории (кроме чёрного рынка), место выбирает клиент через «призрак» (`vehGhost`), сервер проверяет расстояние, воду/сушу, пересечения с техникой/людьми, дорогу для авто; цена × `prices`; **кредит** — только лодки, при долге 0 и цене ≤ 60 000 €: 20 % сразу, 80 % в `debt_<uid>` (с удержанием 25 % выплат и улова). Машина получает владельца (`vehOwn`); **при любой покупке военной техники у обычного дилера (не на чёрном рынке) вооружение снимается** (`removeWeaponTurret` по всем турелям).
- **Продажа** (`dealerSell`): своя, не в экипаже, не в перевозке, не работает во флоте; ≤ 150 м от точки; выплата `vehTradeIn = round(цена·0,5·(1 − износ/400)·(1 − урон·0,8)/50)·50` на **банк**.

### 9.8 Топливо (`fuel*`)
- **Колонки:** все объекты `FUELSTATION` карты, у которых в конфиге `ace_refuel_fuelCargo ≠ 0`; привязаны к ближайшему городу с рынком (`ALS_pumps = [[объект, город]]`). Плюс «точки заправки» (`fuelPoints`): топливные цистерны `Land_fs_feed_F` на аэродромах и у портов (ставятся на берегу, рядом с глубокой водой) и бочки `CargoNet_01_barrels_F` у лагерей; для них объём не меньше 500 л, а объект, не бывший ACE-источником, делается им на 3000 л.
- **Связь с рынком:** топливо колонки = `запас fuel × 150 л/бочка` (`fuelSync` через ACE-refuel `setFuel`); при блэкауте города (`ALS_gridPub = "dark"`) колонка пустая (кроме точек).
- **Оплата** (`fuelTick`, spawn-цикл `fuelLoop`, каждые 3 с): по изменению уровня определяется плательщик — тот, кто держит форсунку, владелец заправляемой машины или ближайший игрок; цена литра = `цена бочки(buy)/150`; списывается `moneyPay`; не хватило — колонка останавливается на 60 с («card declined»); по завершении — квитанция и событие обучения. Рынок: `fuel −л/150`.
- **Канистра** (`fuelCan`): 20 л, `40 + 20·цена_литра` €, ACE-канистра с владельцем и `ALS_keep`.
- `fuelPlan(км, скорость, бак, топливо)` — подсказка в диспетчерской (нужный запас = (время + 0,75 ч)·бак/4).

### 10.1 Каталог техники и снаряжения `ALS_catalog` (`scanCatalog`)
- Строится **на каждой машине** при запуске (`XEH_postInit` → `scanCatalog`, вместе с `weaponRules`), хэш `класс → описание`. Для техники: `CfgVehicles` со `scope 2`, не человек и не животное, и `vehInfo` возвращает не `nil`; для снаряжения: `CfgWeapons` со `scope 2` и `weapInfo` ≠ `nil`. Запись техники: `{class, name, family, category, speed, cargo, seats, armor, armed, military, price, faction}`; запись оружия/снаряжения: `{class, name, family, category, power, rof, mag, armor, legal, price}`.
- **Семейства** по `simulation`: `carx/motorcycle` → car; `tankx` → armor; `helicopterx/RTD` → heli; `airplanex` → plane; `shipx/submarinex` → boat (только если у корабля есть водитель); `StaticWeapon` → static; прочее отбрасывается; машины с `maxSpeed < 10` отбрасываются.
- **Категории**: `motorbike`; `truck` (Truck_F с грузом ≥ 16 или местами ≥ 10, либо «truck» в подкатегории) / `armored` (если вооружён); `van` / `bus` (≥ 12 мест); `supercar` (скорость ≥ 280 или мощность ≥ 600); `sports` (≥ 230 или мощность ≥ 300); `offroad` (suv/pickup/4x4 в подкатегории); `car`; `armor`; вертолёты `light/transport(≥ 8 мест)/attack`; самолёты `light plane (≤ 4 места, < 500 км/ч)/plane/cargo plane(≥ 10 мест или груз ≥ 20)/combat jet`; лодки `boat/speedboat(≥ 60 км/ч)/ferry(≥ 8 мест)/gunboat`; БПЛА — `drone`.
- **Цена** (`vehInfo`): кривая по скорости `2500 + 75·(min(v,120)−50)+ + 8000·((min(v,350)−120)/60)^2,2`, смешанная с кривой по мощности для лёгких машин; надбавки за груз (×500/800) и места (×200–500); отдельные формулы для truck/bus/van/armored/armor, вертолётов (`120000·…`), самолётов (`60000·…`), лодок, статики (15 000), дронов. Затем ×1,7 для «люксовых» названий (mercedes, bmw, … `limo`), ×0,55 для «дешёвых» (lada, uaz, old, rusty, classic…), детерминированный разброс ×0,8…1,2 по хэшу имени класса, ×2 если вооружена, ×1,5 если военная; округление до 100. «Вооружена» = есть оружие, чей магазин имеет `hit > 1` (гудки, дым, ракетницы, лазер, прожектор исключены).
- **Оружие** (`weapInfo`): категории `handgun/smg/shotgun/rifle/sniper rifle/machine gun/launcher` по `cursor` оружия; базовые цены 400/900/700/1500/3000/4000/6000 × `(hit/10)^1,2` × ROF-коэффициент × `(1 + магазин/200)`; ракетницы/дымы (hit < 3) исключены; оптика (приближение + ТВ/ПНВ), бронежилеты (`80 + armor^1,6·15`), шлемы (`30 + armor^1,5·20`); «легально» без лицензии только pistol/shotgun, оптика без тепловизора, жилет с броней < 16.

### 10.2 Запись машины и владение
- `ALS_owner` (uid игрока или `co_N`) на объекте (public); `ALS_ownedVehs` — список; `vehOwn` ставит владельца, создаёт запись, публикует, фиксирует `veh_ever_<uid>` и пересчитывает ранги доставки (`haulMirror`).
- `ALS_vrec` (локальная на сервере): `{id "v<N>", odo (км), wear (0…100), insured, premAt, plate, paint}`; `ALS_vpub` (public) = `[id, износ, застрахована?, одометр, сломана?, застряла?]`.
- **Сохранение** (`vehSave` в `worldSave`, БД `vehicles`): для каждой *своей* машины (кроме «одолженных» `ALS_loaner`): `[класс, posASL, dir, up, топливо, урон, владелец, запись, расширение{hits, inv, cargo}]`; для флотских машин, «уехавших на работу», позиция подменяется базой; авиация в воздухе сохраняется на ближайшем аэродроме/стоянке. В расширение входят повреждения по точкам, содержимое багажника и груз ACE. Классы, которых нет в сборке, остаются в `ALS_vehHeld` и переписываются обратно в БД без изменений.
- **Восстановление** (`vehRestore`, перед `ALS_ready`): `createVehicle` над землёй, затем `setPosASL`, `allowDamage false` до `ALS_ready` + 20 с; груз грузится через 5 с; страховые платежи откладываются на 600 с; `veh_pending` (ожидающие замены) досылаются через 60 с; восстанавливаются ящики/предметы (`crateRestore`, `groundRestore`, `uwStash restore`).

### 10.3 Замки и доступ
- `vehLocks` — CBA PFH раз в секунду (`XEH_postInit`): 
  1. **Свои машины** (`ALS_ownedVehs`; обрабатываются только открытые и автозапертые, замок 2 — ручной — не трогается): если рядом (≤ 120 м) или в экипаже есть человек, которому можно (`vehMayUse`), — `lock 0` и сброс `ALS_unlocked/ALS_autoLock`; если нет и в экипаже нет игроков и машина не помечена `ALS_unlocked` — `lock 3` (флаг `ALS_autoLock`).
  2. **Раз в 5 с — все бесхозные машины** (`vehicles` без `ALS_owner`): `lock 3`, если у них нет `ALS_unlocked`, нет `ALS_ride` (поездка в такси/в автобусе), не парашют и `locked < 2`. То есть **любая созданная скриптом без владельца машина будет заперта в течение 5 с**, пока не получит `ALS_unlocked = true` (это учтено в 0.6.3 для конвойного грузовика аддона).
- `vehMayUse(uid, veh)`: владелец; на сервере также участник компании-владельца и участник того же крю, что и владелец; на клиенте — через `ALS_crewPublic` и `ALS_company`.
- `lockPick`: предмет `ALS_lockpick`, ≤ 6 м, пешком, замок = 3, машина либо бесхозная, либо автозапертая своя; открывает, ставит `ALS_unlocked` и `ALS_stolenBy`, для бесхозной — `ALS_keep` и учёт `ALS_picked`; преступление `theft` (для полицейских/военных `carjack`); 20 % — отмычка ломается. Клиентское действие `Pick the lock`: ACE-прогресс 10 с (18 с для полицейских/военных).
- **Угон при посадке** (клиентский `GetInMan`, см. 7.12): водитель чужой/гражданской/полицейской машины → `lawCrime theft/carjack` один раз на машину и вора.

### 10.4 Износ, поломки, страховка, потеря
- `vehTick` (CBA PFH, 10 с): одометр + пройденное (≤ 600 м за тик), `wear += км/20` (100 % ≈ 2000 км), при `wear > 50` и скорости > 10 км/ч вероятность поломки `((wear − 50)/50)·0,004` за тик → `HitEngine = 0,95` и сообщение экипажу про «Garage app»; признак «застряла» (`ALS_stuck`) — водитель есть, двигатель включён, смещение < 8 м дольше 45 с (180 с для авиации); раз в 60 с `mechTick`; `vehAssist` для вызовов помощи. Страховка: премия `цена·0,005/6·опция upkeep` каждые 600 с реальных, если владелец онлайн (не списалась — страховка слетает).
- `vehBroken`: не едет, двигатель ≥ 0,9, перевёрнута, колесо ≥ 0,5, топливо < 2 %, затопила (`vehWet`).
- **Страховой случай** `vehWrecked` (из `lawKilled` и `fenceDo`): если владелец не в сети — письмо от страховщика; если уничтожил сам владелец, машина застрахована и `random < 0,4` — мошенничество (страховка отказана, преступление `fraud`); иначе страховка платит **70 % цены** (округл. до 100) на **банк**. Затем `vehReplace`.
- **Замена** (`vehReplace`): если это **последняя** живая машина игрока (без учёта работающих во флоте и ломаных ≥ 0,9) и она не «одолженная» и не компаний — через 30 с на «стартовой точке» (`starter_spot_<uid>`) или у дома/лагеря появляется такая же; цену платит владелец (`moneyOwe`) либо **тот, кто её разбил**, если это игрок из другой команды; БД `veh_pending`, `vehDeliver` создаёт машину (`allowDamage false` на 5 с).

### 10.5 Сервис и вызовы (`vehDo`, `vehAssist`, `mech*`)
- Действия приложения «Garage» (`vehDo [игрок, действие, id, аргумент]`; только своя машина, найденная по `ALS_vrec.id`): `insure` / `uninsure`; `service` (нужен «гараж» поблизости: `garageAt` — любая заправка ≤ 60 м, аэродром ≤ 450 м, порт ≤ 200 м или бизнес-гараж; цена `max(100, износ·цена·0,0008 + урон·цена·0,1)`; обнуляет износ и урон; плату получает владелец гаража); `paint` — 600 € (только текстуры `TextureSources` с гражданскими фракциями); `plate` — 300 € (до 8 символов); `assist` — помощь на дороге/эвакуатор (100 € застрахованной, иначе `250 + расстояние до гаража/10`; через `moneyOwe`); `fetch` — доставка машины к игроку (`200 + км·10`, ×0,5 застрахованной, 60–120 с; запрещено, если она работает во флоте, внутри кто-то есть или рядом ≤ 200 м другой игрок).
- `vehAssist` (автомат помощи): состояния `wait → coming → walk → fix`; для воздуха/воды/затонувших — «эвакуатор» (60 с); иначе приезжает ремонтный фургон (`C_Offroad_01_repair_F`) с механиком (ИИ, едет через `aiDrive`), чинит (`HitEngine`, перевёрнутую ставит, «застрявшую» перемещает на ближайшее доступное место `vehDropSpot`, `setDamage 0`, топливо ≥ 20 %, износ −30), затем уезжает и удаляется. При сбое — возврат денег.
- **Механики-игроки** (`mechTick/mechDo/vehFix/vehPatch`): лицензия `mechanic` + `ToolKit`. `mechTick` (раз в 60 с): с шансом 25 % создаёт для каждого механика-игрока «вызов жителя» (сломанная машина вдали от города); вызовы живут 900 с (1200 с после взятия). `mechDo "take"` берёт вызов и ставит на метку `ALS_sideNav = [[pos, "Call-out: …", "recipient"]]` (формат записей навигации: `[позиция, подпись, тип]`); `vehFix` лечит машину, платит цену вызова в **банк**, возвращает машину жителю (он уезжает на 2 км и удаляется) и **очищает `ALS_sideNav` у механика**; `vehPatch` (любой игрок с ToolKit) ограничивает все повреждения 0,3 — «дотянуть до гаража».
- `vehPush` — «толкнуть» самолёт/вертолёт на 4 м вперёд/назад (ACE-действия на классах `Plane`, `Helicopter`).
- Прочее: `vehSiren` запускает действия `beacons_*`/`siren_*` из `UserActions` модели; `strapLoad` — пометка груза ACE «пристёгнутым»; `vehCargoLoad` — загрузка сохранённого груза после рестарта.

### 10.6 Размещение и парковка
- `vehFits [точка, курс, класс, игнор, запас]` — **SAT-проверка прямоугольника машины** (габариты геометрии класса + запас 0,5 м) против всех объектов в радиусе (дома, статика, техника, деревья), высота 0,3…2,2 м над землёй; `drvFits` — вариант по лучам (`lineIntersectsSurfaces`) для проверки проходимости.
- `parkSpot [pos, класс, радиус, строго]` — ближайшая дорога → пробует 12 мест у обочины (по обе стороны), затем кольцами 8–55 м, требуя ровное место, не дорогу, не здание, и **выезд на дорогу** (`wayOut`); возвращает `[позиция, курс, годится?]`. `vehSpots` — N мест для группы машин (кольца вокруг точки). `vehDropSpot [класс, точка]` — для лодок `boatSpot`/ближайший порт; для самолётов — ближайшая стоянка аэродрома (если нет в зоне запрета полётов) или свободное место на перроне; для наземной — берег, затем `parkSpot`. `homeParkSpot` — место у дома (см. 7).
- **Покупка у дилера:** клиентский `vehGhost` (призрак `createSimpleObject` + PFH): луч от центра экрана ≤ 80 м, проверки «рядом с дилером», «поверхность» (суша/вода ≥ 1,5 м), «не заблокировано», «не крутой склон (< 0,95)», «не на дороге»; Q/E — поворот (Shift — точный), Esc — отмена.

### 10.7 Автопилот ИИ: `aiDrive` → `drv*` (Drive v2) и `driveAssist`
**Кто вызывает.** Любая автомобильная ИИ-техника в оригинале (такси, фургоны ремонта, трафик, конвои армии, эскорт, инкассация, подвоз товаров) ездит через `aiDrive [машина, точка, скорость]`:
- для **наземной** техники без `ALS_noAssist` → `drvGo` (собственный автопилот ниже); для остальной и для `ALS_noAssist` — стандартные waypoint'ы + `calculatePath` агентами «car/safe» и `setDriveOnPath`.
- `aiFollow [машина, лидер, цель, скорость]` — «ехать следом»: берёт путь лидера (`ALS_drv.c`), либо для `ALS_noAssist` — след лидера + остаток плана (`setDriveOnPath`, перерасчёт раз в 3–10 с).
- Аддон вызывает `aiDrive` для конвойного грузовика (`contractReady`); он попадает именно в `drvGo`.

**Состояние `ALS_drv`** (хэш на машине, локальный): точки траектории `c` (шаг 2 м), нормали `n`, боковой сдвиг `o`, скорости `spd`, границы `lo/hi`, индекс `idx`, `refTo/rawTo`, `dests/leg/finalLeg/loop/direct/avoid`, режим `mode` (`rail`|`own`), `state` (`PLAN` → `ARRIVED`), `acc`, `vmax`, `vcmd`, габариты `size[hw, hl, rmin]`.
**Планирование:** `drvGo` корректирует точку назначения на сушу, ставит CARELESS и `forceFollowRoad false`, создаёт waypoint'ы и план: `drvPlan` — для расстояний < 2500 м свой A* по дорогам (`drvRoads`, до 4000 узлов, дороги без пешеходных (`getRoadInfo select 2` = `isPedestrian`)), иначе `calculatePath` агентом (до 3 попыток, лучший по приближению к цели); `drvPlanEnd` обрезает путь, заменяет участки вне дорог своими дорожными (до 1500 узлов), дописывает старт/конец; `drvAppend` прореживает развороты, ресемплирует (2 м), 12 итераций сглаживания (≤ 2,5 м от оригинала), нормали; `drvRefine` (асинхронно, пакетами по 125 точек): `drvClear` лучами измеряет свободное место слева/справа (кэш `ALS_drvRoom`, до 60 000), считает допустимый коридор, поджимает к обочине (45 % полуширины, 1,2…2,6 м), сглаживает, проверяет габариты `drvFits`, ограничивает скорость по кривизне `√(aLat/κ)` (aLat 2,8, 4 с сиреной), по типу (скоростные кэпы: обычный режим 45/80 км/ч город/вне города, LIMITED 35/60, FULL 50/90, сирена 70/100; TRACK ≤ 40 км/ч вне города), и по `ALS_maxKmh`.
**Исполнение** (`drvInit`, три CBA PFH): `drvTick` по каждой машине по очереди (1/5 списка за вызов, период 0,04 с), `drvOwn` (режим `own`, 20 Гц); список `ALS_drvEyes` (позиции игроков) раз в секунду.
- Режим `rail` (дальше 380 м от игрока): штатный `setDriveOnPath` по готовым точкам, регулировка скорости `limitSpeed`, остановка `forceSpeed 0`.
- Режим `own` (ближе 300 м от игрока): **скрипт сам задаёт скорость и угловую скорость** (`setVelocityModelSpace`, `setAngularVelocityModelSpace`, тормоза отключены) — следование по траектории с упреждением (`L = 0,6·v + 2,5`, регулятор кривизны), развороты вперёд/назад (до 8 манёвров), задний ход после удара (`EpeContactStart`), парковка (`ownParked`).
- Восприятие `drvSense`: объекты в лобовом коридоре на дистанции `1,2·v + v²/5 + 15` (20…140 м): интервал до препятствия, его скорость и тип (`man`, `car`, `oncoming`, `thing`); следование по модели IDM (`a = aMax(1−(v/vmax)^4) − aMax·(s*/gap)²`, aMax 1,6 (2,6 с сиреной), торможение 2,2, safe time 1,1 с). Пешеходы тормозят до 15 км/ч; неподвижный «объект» ждёт 6 с (15 с, если у него есть водитель), затем машина считает его статикой (`statics`), перепланирует путь вокруг и/или сдаёт назад.
- Разъезд «лоб в лоб»: после 3 с взаимного стояния уступает машина с большим netId; перед машиной с игроком-водителем и перед машиной без автопилота уступает всегда.
- Застревание: нет прогресса 25 с → `drvGo` заново; 3 раза подряд и нет игроков в 150 м → телепорт на ближайшую точку впереди (10…20 индексов), где `vehFits`.
- Остановки: `ALS_hold` или `ALS_attending` у водителя (диалог с игроком) — стоит; `ALS_calmed` — не быстрее `ALS_calmKmh` (15 км/ч); `ALS_maxKmh` — потолок.
- **Прибытие:** при достижении конца на последней ноге `state = ARRIVED` и на машине ставится `ALS_drvArrived = true`; автопилот остаётся (машина удерживается).
- **Смерть/обморок водителя** (`EntityKilled` + ACE `unconscious`): `drvHalt` — останавливает автопилот, выключает двигатель, плавно гасит скорость за ≤ 5 с, и **у бесхозной машины ставит `ALS_unlocked`, `ALS_keep` и `lock 0`** — поэтому игроки смогут сесть, но тело водителя остаётся в кресле (за него нужно вынести/пересадить).
- **Краш-сцены:** `EpeContactStart` на машине с автопилотом при столкновении с другой машиной на относительной скорости > 20 км/ч запускает `crashStart` (сцена аварии), если рядом (≤ 600 м) есть игрок и ни в одной машине нет игрока.

**`driveAssist`** (старый «лёгкий» режим) — для наземных ИИ-машин **без** `ALS_drv` и без `ALS_noAssist` в радиусе 1200 м от любого игрока (`ALS_assistVehs` обновляется раз в 2 с): раз в 0,25 с считает цепочку дорожных сегментов впереди, интервал до препятствий, ограничивает скорость (80/45 км/ч, сирена 100/70), тормозит `setVelocity`, обходит неподвижного «блокирующего» через 8 с (20 с, если в нём есть живые), распутывает застревание (задний ход через 10 с, возврат на дорогу через 60 с, если игроков нет в 150 м), уступает проезд игрокам.

### 10.8 Флот (`fleet*`, приложение «Fleet»)
- **Ёмкость**: одновременно работать может `1 + 2 (лицензия business) + 3 (участие в компании)` машин. Нанять водителя: из трёх кандидатов-жителей (21–60 лет, ≤ 4 км, без работодателя; обновление раз в 600 с), зарплата `150 + (skill−1)·62,5/5` € **в час реального времени сервера** (начисляется по `time`), минус тренировка 300 € → +1 навык (+25 €/ч). Можно назначить палубного матроса (`deckhand`) для рыбалки.
- **Назначение** (`assign`): машина → работа `haul` (груз ≥ 8), `taxi`, либо `line` (пассажирская линия для самолёта/вертолёта/лодки до 3 ближайших хабов 2,5…25 км вне зон запрета). Водитель выезжает (реальный ИИ-водитель + `aiDrive`, если игрок ближе 300 м; иначе машина «прячется» — `hideObjectGlobal`, `enableSimulationGlobal false`), работает по плану `fleetRun` (рейс), возвращается; доход = `рейс·(0,35 + 0,05·навык)`; 12 % − 2 %·навык — происшествие (поломка, штраф 150 €, битый груз −50 %, авария: 0 € и +0,35 урона); при честности ≤ 2 — 15 % шанс удержать 30 % и подозрительное письмо бухгалтера. Зарплата начисляется по секундам реального времени (`wage·dt/3600`) и списывается через `moneyAdd` из **банка**; не хватило — водитель увольняется.
- **Сдача в аренду** (`lease`): ставка `max(20, round(цена·0,004/10)·10)` €/час реального времени, машина «забирается», когда рядом нет игроков, хранится скрытой; возврат в течение ~3 мин после `unlease`; шанс `min(0,3; 0,02·часы)` вмятин (+0,25 урона).
- **Забастовка** `strike_<uid>` (см. 8.10) останавливает флот, `fleetDo "raise"` соглашается на +10 % к зарплате.
- Состояние хранится в БД `fleet_<uid>` (+ `crew_<uid>` — список нанятых); `ALS_fleetSession` — случайная метка сессии: при первом обращении после рестарта все работы возвращаются в `idle`.

## 11. Работы: доска грузов, курьер, такси, райд, дорожные события, пассажирские и воздушные/морские заказы

Прочитано построчно: `jobSites`, `jobGenerate`, `jobLoop`, `jobPublish`, `jobAccept`, `jobAbandon`, `jobCheck`, `jobClient`, `jobCollect`, `jobDeliver`, `jobHandUnload`, `jobContract`, `jobSupply`, `jobStory`, `jobEntry`, `jobsOf`, `haulRoom/Mirror/Profile/Rank` (см. 8.6), `courierTake/Drop/Cancel`, вся инфраструктура событий `jobEv*` (`jobEvTypes`, `Call`, `Start`, `Post`, `Answer`, `Clear`, `Client`, `Arrive`, `Refresh`, `To`, `Door`, `Pax`, `NearestField`, `Tidy`, `Seize`, `Contraband`, `Calm`, `Block`, `BlockAt`, `Practice`) и все 15 типов событий (`atc`, `blowout`, `cargo`, `checkpoint`, `engine`, `errand`, `medical`, `overboard`, `pirates`, `roadblock`, `sick`, `smuggle`, `toll`, `vip`, `weather`), `taxiLoop/Duty/Rate/Tier/Offer/Pick/Answer/Publish/Tick`, `faresPublish`, `rideDo/Tick/Publish`, `paxKind/Seats/Fare/Hint/Cancel/Accept/Board/Offers` (полностью), `paxTick` (первая половина: общий каркас и состояния `wait`), заголовок `aerialOffer`, `seaFreightGen` (начало).
Не читал: вторую половину `paxTick` (состояния `ride`/`tour`/`drop`, посадка и высадка), `aerialWork`, остаток `aerialOffer` (параметры по типам), `seaFreightGen` (расчёт рейса), `airportRun`, `tripWhy`, `seatsFree`, `stopTalk`/`stopDress`, `ratingFor`/`lessonDo` (уроки пилота), `careerMirror`.

### 11.1 Доска грузов (`ALS_jobs`)
- **Площадки** (`jobSites`, один раз при загрузке): для ролей `industrial`, `farm`, `port`, `fuel`, `commercial` из каталога зданий карты (`ALS_map get "buildings"`) выбираются точки с разнесением ≥ 250 м (800 м для `farm`, если ферм мало и берутся сараи вне городов), порты — только у воды, исключаются зоны запрета полётов и военные базы (`milSide`). `ALS_jobSites = [[позиция, «<город> <роль>», роль, город]]`.
- **Генерация** (`jobGenerate`): случайный товар из `ALS_goods`; поставщик — площадка роли из `makes` города, где запас > 50 % цели; получатель — площадка из `uses` (или `commercial` для товаров `people > 0`) с запасом < 110 %; дистанция 1500 м … `maxKm` (случайно 5/8/11/14 км, веса 45/25/15/15 %), разные города (кроме «короткого» режима 300…4000 м); тир 0/1/2 (веса 45/35/20 %, не выше разрешённого рангом) → 2/4/6 ящиков, 1/2/3 ед. на ящик, размер ACE 1/2/3. **Оплата:** `(200 + км·120)·{1; 1,8; 3}·need·ставка_соперника` (`need = 1 + 0,6·(1 − min(запас получателя/цель, 1))`), округление до 10. Время: `15 + км·3 + тир·4` мин.
- **Цикл** (`jobLoop`, spawn, шаг 3 с): удаляет протухшие открытые (30 мин, `boardUntil`); держит на доске не менее `ALS_jobBoardSize = 24` открытых; для каждого игрока добавляет заказы под его машину (до 4 подходящих в радиусе 6 км; новичкам до 2 «коротких» до 4 км) и морские (`seaFreightGen`, до 3); каждые 120 с реального времени — `jobSupply` (заказы заводам игроков) и `jobContract` (строительные контракты, до 3 открытых); `cargoWatch`; публикует `ALS_jobBoard` (при изменениях); раз в 10 с — зеркало ранга (`haulMirror`).
- **Принять** (`jobAccept`, сервер, атомарно): у игрока должно хватить места (`haulRoom`: сумма `ящики·размер` по взятым работам ≤ грузоподъёмности лучшей наземной/морской машины), длина ≤ лимита ранга (км; для моря лимита нет); `status = taken`, срок `(минуты·1,3 + 5 + км_до_пункта_погрузки·2,5)·60 с`; создаются NPC «Foreman» у погрузки и «Receiving» у выгрузки (`npcCreate`) — для контрактов только получатель; клиенту рисуются локальные маркеры (`jobClient`: зелёный пункт погрузки, синий выгрузки, линия).
- **Погрузка** (`jobCollect`, диалог с прорабом ≤ 15 м): вариант «в твою машину» (машина владельца ≤ 40 м — море 70 м — с достаточным ACE-местом), «сам» (ящики кладутся на землю, +15 % к оплате) либо «экипаж»; создаются `Land_WoodenCrate_01_F` (`ALS_job = id`, `ALS_good`), запас на рынке города −ящики·ед.; `collected = true`.
- **Доставка** (`jobDeliver`, диалог с получателем ≤ 40 м от ящиков): все ящики рядом и не прицеплены; оплата `pay·множитель_ранга` + 15 % за ручную погрузку + 15 % за ручную выгрузку + 25 % за возврат украденного + 5 % за ремни (`strapLoad`, не море) + 3 % за предрейсовую проверку, затем `payMods` (ночь/море/опция/долг); деньги на **банк**; `repAdd +2` в городе получателя; `stat_jobs_<uid>++`; запас получателя +ящики·ед. (для `supply` — на склад бизнеса, стоимость списывается с владельца), через 60 с ящики и NPC удаляются. Продвижение ранга сообщается.
- **Провал** (`jobCheck`): ящики уничтожены или время вышло → `failed`, непокинутые ящики возвращаются на рынок поставщика; `jobAbandon` — то же по желанию.
- **Контракты** (`jobContract`): «купить N ящиков стройматериалов у любого торговца и привезти на площадку в городе»; оплата `N·цена_материалов·1,7 + 400`; ящики берутся из ближайших бесхозных `ALS_good = materials` (≤ 40 м от получателя) и удаляются при сдаче.
- **Заказы заводам** (`jobSupply`): для бизнеса `Factory` владельца, где запас ингредиента рецепта < 4 партий и у владельца > 3000 €, на доску ставится заказ «Supply» (4 ящика по 2 ед.) на 1500…12000 м; оплата `300 + км·150`; стоимость товара + оплата списываются с владельца (`moneyPay`, иначе `moneyOwe`).

### 11.2 Курьер (посылки)
`courierTake` (клерк роли `clerk`/ратуша ≤ 15 м): 4–6 домов жителей в радиусе 150…1500 м (целые, не `Wrecked`), посылки (`ALS_parcel` в инвентарь), маршрут в `ALS_courier[uid]`, на юните — `ALS_courierRoute`; `courierDrop` у двери ≤ 25 м: оплата `45 + км·70` + бонус 25 € за посылку за «круг», **наличными** (через `payMods`); `courierCancel` возвращает неотданные.

### 11.3 Такси (`taxi*`)
- **Дежурство:** лицензия `taxi`; `ALS_taxi = true` на юните; работает только на **своей наземной машине** (владелец = водитель) с лицензией. Пока на дежурстве, `taxiTick` (из `taxiLoop`, каждые 2 с) раз в 20 с (сразу, если нет предложений и поездок) создаёт предложение (до 4 одновременно, живёт 300 с): случайный житель (не занятый в виртуальном мире) садится на ближайшей дороге в 200…1200 м (между 01:54 и 03:30 с шансом 60 % — у бара, едет домой), цель — его дом/работа, города (тир 2–3), до 6 адресов; число пассажиров 1–4 по тиру и свободным местам.
- **Тиры** (`stat_taxi_<uid>` — число завершённых): 1 (0–9): 300…1500 м, 1 пассажир, ×1,0; 2 (≥ 10): 1000…5000 м, 2, ×1,15; 3 (≥ 30): 1500…12000 м, 4, ×1,3. Ставка: `(40 + км·140 + км_подъезда·40)·тир·(1 + 0,3·(пассажиры − 1))`.
- **Поездка:** `taxiPick` создаёт пассажира(ов) у обочины → он подходит к машине, спрашивает (диалог `fare`, 90 с) → садится → цель отмечена; `ride` — `jobStory` (дорожные события, ниже) и поездка; прибытие (≤ 40 м, скорость < 5): оплата `payMods` + чаевые по звёздам (`taxiRate`: время > км·1,6 мин минус звезда, > ×1,8 ещё одна; урон > 5 % / > 20 % — минус звезда); чаевые от оплаты: 1–2★ — 0, 3★ — 10 %, 4★ — 20 %, 5★ — 30 % (×1,25 при среднем рейтинге ≥ 4,5); рейтинг в `taxirate_<uid>` и `ALS_taxiRating`, новости на 10/25/50/100 поездках; пауза до следующего предложения 15–45 с (×0,6 при рейтинге ≥ 4,5, ×1,8 при < 3). Отказ/выход пассажира/смена статуса — без оплаты.
- **Дорожные события** для такси: `blowout`, `roadblock`, `toll`, `sick` (21:00–04:30), `errand` (остановка у дома, 35 % — «секрет»: сумка с наркотиками +400 €, 30 % — наводка полиции `accessory`).

### 11.4 Райд (`rideDo/rideTick`) — вызвать такси игроку
Телефон: `call [цель, имя]`: ≥ 300 м, не в машине, цена `(6 + 2·км)·опция prices` (хватает наличных+банка), создаётся такси (`vehPick` car/sports ≥ 4 мест) с ИИ-водителем в 600…1000 м вне поля зрения (`sceneUnseen`), едет через `drvGo` («coming → here → riding → done»), ждёт до 600 с, 180 с у игрока; машина заперта (`lock 2`/`ALS_ride`); по прибытию плата списывается через `moneyOwe` (недостающее уходит в долг), водитель уезжает/удаляется (`sceneAway`). Если игрок вышел раньше, платит пропорционально пройденному (минимум 3 €).

### 11.5 Дорожные события (`jobEv_<type>`) — расширяемый реестр
- **Реестр:** `jobEvTypes` собирает из `ALS_fnList` все `jobEv_*` с метаданными `{careers, weight, hours}`; новые типы из другого мода подхватываются автоматически (как `coopJob_`).
- **Старт** (`jobStory`, вызывается из `jobLoop` по груженым работам, из `taxiTick`/`paxTick` по поездкам): в пути (карьера и скорость/высота/расстояние до цели), не чаще раза в 150 с на игрока и на работу, не более 2 событий на работу, шанс `0,35·опция events`; выбирается тип с подходящей карьерой и часами, не повторявшийся, `can` не вернул `false`. Состояние: `ev` (диалог с вариантами и тайм-аутом `def`), `evTick` (тики события), `via` (точка «заехать/заглянуть» с радиусом, высотой, подсказкой), `evObjs`/`evMarks` (объекты и маркеры, убираются `jobEvTidy`).
- **Интерфейс события:** `["meta"]` → хэш; `can`, `start` (возвращает хэш `{title, text, choices, def, secs, silent, note}` либо `createHashMap` — не начинать), `answer` (игрок выбрал вариант, клиентские действия `jobEvClient`), `tick` (`false` — закончить), `via` (достигнута точка), `arrive` (прибытие, правка оплаты). Помощники: `_say`, `_ask`, `_unask`, `_roll`, `_keep`, `_mark`, `_setVia`, `_follow`.
- **Каталог** (карьеры → событие, эффект):
  - `truck` — `cargo` (груз сместился; перетянуть ремни 15 с или −25 % оплаты с шансом 50 %), `blowout` (колесо; сменить 12/20 с с ToolKit/без или вызвать помощь; −15 % оплаты, если приехал на пробитом), `roadblock` (блок-пост полиции на дороге: документы → контрабанда/чужой груз/наркотики/тахограф/поддельные бумаги; штраф `500 max (1500·контрабанда + 600·чужой + 100·наркотики + …)`, взятка 40 % штрафа с шансом 55 % (+25 % при репутации ≥ 50), конфискация `jobEvSeize`, розыск при побеге), `toll` (банда берёт «пошлину» 25–35 % оплаты ≥ 100 €; платить, назваться другом (репутация банды ≥ 30) или отказаться → перестрелка; нужен свободный город банды), и для всего `checkpoint` (армейские КПП; вес 0, запускаются другими модулями).
  - `taxi` — `blowout`, `roadblock`, `toll`, `sick`, `errand`.
  - `plane/heli` — `engine` (отказ/птица; сесть на ближайшем поле за 70 % оплаты), `weather` (грозовая ячейка, вес 1; через неё — тряска и −25 % с шансом 50 % при пассажирах), `medical` (пассажиру плохо; посадка в 7 мин → +600 €, иначе −50 %), `vip` (низкий пролёт над городом → +40 % чаевые), `atc` (задать высоту, штраф 400 € за ±150 м), `smuggle` (сбросить «посылку» за 2000–4000 € наличными; 30 % — розыск и отзыв лицензий армии).
  - `boat/sea` — `pirates` (3 бандита на лодке: заплатить 600…1500 € наличными, уйти или драться; победа — 600 € премии), `overboard` (пассажир за бортом; вернуть +10 % или бросить −50 % и −3 репутации).
- **Блок-посты/вмешательство игрока:** `stopTalk` и `ALS_stopFor` (диалог остановки), `ALS_attending` (ИИ-остановка на время разговора), `jobEvCalm` (трафик замедляется у места события и пропускает игрока).

### 11.6 Пассажирские, грузовые и спецзаказы для самолётов/вертолётов/лодок (`pax*`)
- **Доска** (`paxBoard`, раз в ~8 с, `paxOffers`): по одной лучшей машине владельца каждого вида (`plane`, `heli`, `boat`; нужна соответствующая лицензия), до 6 предложений, живут 360…840 с, 12 % «срочных» (×1,6 оплаты, ограниченное время). Узлы: аэродромы (`hubSpot`), для вертолётов ещё города (`town/city/capital`), для лодок — порты `ferryPorts`; фильтр зон запрета полётов (`noFlyClear`).
- **Типы:** самолёт — `charter`, `mail`, `freight`, `skydive`, `survey`, `crop`, `banner`, `army`; вертолёт — `charter`, `medevac`, `tour`, `freight`, `outpost`, `mail`, `pinnacle`, `hoist`, `fire`, `news`, `patrol`, `army`, `armysling`, `pursuit`, `escort`; лодка — `charter` (паром), `freight`, `fishing`, `sightseeing`, `salvage`. Ставки: чартер самолёта `n·(180 + км·60)`, вертолёта `n·(160 + км·60)`, лодки `n·(60 + км·20)`; почта `400 + км·70`; груз `250 + км·кг·0,12`; снабжение аванпоста `500 + км·кг·0,15`; прыжки `n·240 + км·30`; съёмка `350 + 160·точек + км·25`; обзорный тур `n·150 + 420 + км·20`; рыбалка `250 + n·120 + км·25`; береговой тур `n·100 + 330 + км·18`; спасение груза `600 + км·70`; медэвак `700 + км·90`. Конкуренты (`rivalRate "air"`) снижают ставку, иногда убирают одно предложение.
- **Принятие** (`paxAccept`): нужна своя подходящая машина; «армейские» работы (`army`, `armysling`, `escort`) — лицензия `contractor`; горные/подъёмные (`pinnacle`, `hoist`) — рейтинг из уроков (`lessonDo`); длинные задания (`tour`, `fishing`, `survey`, `salvage` …) занимают всю машину; пассажиры (гражданские ИИ с мотивами поездки `tripWhy`) создаются у точки взлёта (аэропорт — у выхода), лицо задания — `ALS_pax[uid][id]`.
- **Выполнение** (`paxTick`, раз в 2 с из `taxiLoop`, а также `taxiTick`, `atcTick`, `noFlyTick`, `airCare`, `fishTick` по 20 с): состояния `wait` (ожидание посадки; для почты/груза — грузовой фургон и погрузка у терминала через `airportRun`; для спасения груза — удержание над обломками 60 с), `ride` (доставка, события `jobStory`), `tour` (по точкам), `drop` (прыжки с высоты > 800 м); провалы — смерть пассажира, просрочка (`deadline`), смена машины; оплата `payMods` на **банк**, учёт `stat_pax_<uid>` и рядовые «charter/salvage», экономический след для гражданских (`civVisit`).
- **Нет денег без лицензии/машины:** лодки — `boat`, самолёты — `plane`, вертолёты — `heli` (см. 8.5). Работа каждого вида учитывается в карьерных ступенях (`careerMirror`, не читал).

## 12. Живой мир: жители («Life Director»), расписание, пузырь, мнения, друзья и враги, новости

Прочитано построчно: `lifeInit`, `lifeLoop`, `lifeTick`, `lifePlaces`, `lifePlan`, `lifeBubble`, `lifeHour` (целиком), `civNew`, `civLoad`, `civSave`, `civTraits`, `civPlan`, `shiftPlan`, `festPlan`, `civSpawn`, `civDespawn`, `civBehave`, `civPullOver`, `civIdle`, `civFidget`, `civFlinch`, `civReact`, `civPose`, `civDry`, `civOutfit`, `civAs`, `civBorrow`, `civGone`, `civInfo`, `civVisit`, `civNews`, `civEvent`, `civEconomy`, `civAmbition`, `civRefill`, `civFreeHome`, `civEvict`, `opinion`, `peopleTick`, `peoplePub`, `storyInit`, `storyTick`, `newsPost`, `newsSubjects`.
Не читал: `civPose` вызовы анимаций в `scene_*`, `ambientTick` (после первых 40 строк: трафик и патрули), `lifeBubble` совместно с `siteStaff*`, `fest*` (праздники: `festStart/Tick/End/Pay/Plan`), `weekDay`, `npcName`, `tripWhy`.

### 12.1 Данные жителя и создание мира
- **`ALS_civs`** — хэш `id (число) → запись` (сервер; в БД `civs` как список пар без служебных ключей `pos, dest, drive, act, met, ops, traits`, которые хранятся в виде `*List`). Запись: `{id, name, age (18–69), class, town, tpos, home (ключ дома), work (поз.), workName, job, car (класс или ""), money (200…4200), mood (0,5…1), wake (5,5…8), start (7…9,5), shift (7…10), sleep (21,5…24), out (0…1, «общительность»)}` + позже `act/pos/dest/drive`, `friends/enemies`, `ops` (мнения), `met`, `traits`, `site/shiftNo/night` (рабочее место в заведении), `visit`, `employer` (соперник/игрок), `loan`, `squadOf`, `kidnapped`, `skill/fleetWage`.
- **Создание** (`lifeInit`, при отсутствии сохранения): для каждого города число жителей `round(max(зданий·ALS_civDensity, 4))` (до 120), `ALS_civDensity = 0,3·опция population`, общий предел `ALS_civCap = 1500`; дом — свободный `Home` города (`civFreeHome`), машина с вероятностью 55 % из каталога (`car/offroad/van`, не военные, цена < 40 000, без полиции/скорой/такси/картов/тракторов), работа — случайная площадка в радиусе 2500 м (12 000 м с машиной), должность по роли (`Factory worker`, `Farmer`, `Dock worker`, `Shop assistant`, `Fuel station attendant`). Класс одежды — из `ALS_civClasses` (`C_man*` без пилотов/медиков/прессы и др.); опция `civFaction` подменяет пул на классы выбранной гражданской фракции.
- **Загрузка** (`civLoad`): дополняет запись шаблоном, восстанавливает хэши `traits/ops/met`; если дом куплен игроком, зарезервирован или разрушен — выдаёт новый (`civFreeHome`).
- **Пополнение** (`civRefill`, раз в 300 с): если в городе жителей < 90 % расчётного, «переезжает» новый (новость города).
- **Черты** (`civTraits`): девять значений 0…10 (`ambition, honesty, loyalty, greed, nerve, driving, mechanics, people, combat`), **детерминированно** из id (LCG, не зависит от сохранения); цель (`goal`): `out of debt`, `revenge`, `shop` (ambition ≥ 8 и < 55 лет), `haulier` (ambition ≥ 6, водитель), `car`, `rich` (greed ≥ 7), иначе `home`.

### 12.2 Расписание (`lifePlan`, `civPlan`)
- `lifeLoop` (spawn, шаг ~2 с): список жителей делится на 5 «срезов» по `floor(id) mod 5`; каждые 2 с планируется один срез → **каждый житель пересчитывается раз в ~10 с**. План `[действие, позиция, назначение, едет_ли_на_машине]`: действия `sleep`, `home`, `commute`, `work`, `errand`, `return`, `festival`, `visit`, `away`.
- Рабочий день: `wake = min(wake, start − время_в_пути − 0,3)`, дорога = расстояние/скорость (5 км/ч пешком, 45 км/ч на машине) → `commute` с линейной интерполяцией позиции → `work` до `start + shift` → при `out > 0,55` магазин/поручение в течение часа → `return` → вечернее поручение при `out < 0,35` (20+out·3 … 21,5+out·3) → `home`/`sleep`. Выходные и безработные: прогулка к «поручению» (магазин из `venueFor` или точка рядом), церковь по воскресеньям в 9,3+out…11,5 при `out < 0,4`, вечер при `out < 0,5`. Ночью в «комендантский час» армии (`ALS_warCurfew`) — дома/сон; во время протеста (`ALS_protests`) днём — «errand» к месту сбора; при гостевом визите — `visit` (8–22 ч) либо `away`. Смена в заведении (`shiftPlan`) и праздник (`festPlan`) переопределяют план.
- В `lifePlaces` (каждый пятый срез, ~10 с): `civRefill`, `venueTick`, `homeStash tick`, `armoury tick`, `yardLife`, `sceneTick`, `partyTick`, `rideTick`.

### 12.3 Физические юниты: «пузырь» вокруг игроков
- **Правило** (`lifeBubble`, каждые ~2 с): жители виртуальны, пока игрок далеко. Физический юнит создаётся, если игрок ближе 650 м (1300 м для едущих на машине; для уже существующих ×1,25), максимум `ALS_civMax = round(40·population)` минус занятые продавцы; ближайшие первыми; исключены: заимствованные (`civBorrow`), работающие в заведении (`site ≠ ""` и `act = work`), «away», «Fish buyer». Если игрока нет — все физические юниты удаляются. Создание происходит, только если житель не виден игроку (никто в 150 м не имеет прямой видимости) либо спит/дома.
- **`civSpawn`**: юнит `createUnit` в гражданской группе (`CARELESS`, `LIMITED`), переменные `ALS_npc = "civ_<id>"`, `ALS_npcRole = "civ"`, `ALS_npcName`, `ALS_npcLabel`, `ALS_civInfo`, `ALS_civId`, `ALS_loanPub`, `ALS_employer`, `ALS_civDuty`, `FiredNear` (реакция «пригнуться и убежать» на выстрелы < 70 м раз в 20 с); для едущих — машина (`ALS_civCar = id`) на дороге у позиции; для сна/дома — внутри здания (`houseFloor`) ночью, снаружи днём.
- **Удаление** (`civDespawn`): юнит и (если не помечена `ALS_keep` и нет других живых в экипаже) машина удаляются.
- **Заимствование** (`civBorrow`, `civAs`): когда скрипту нужен NPC с биографией (продавец, водитель такси, пассажир, механик, спутник сцены), он «берёт» ID незанятого жителя того же города (минимум 3 кандидата), помечая его `ALS_civBorrowed[id] = юнит`; при удалении юнита запись освобождается. Так «настоящие» жители работают в заведениях и т. д.
- `civGone` удаляет жителя (смерть, переезд), прекращает работу у соперника.

### 12.4 Поведение (`civBehave` и спутники)
- `civBehave`: при смене действия — едущие пешком идут по waypoint'ам (`LIMITED`/`FULL` под дождём), на машине едут через `drvGo` (`LIMITED`; к заведению — к ближайшей дороге в 35 м); достигнув цели (`ALS_drvArrived`) с машиной на дороге → `civPullOver`; при `errand` в заведении — запускается `venueVisit`.
- `civPullOver`: найти место (`parkSpot`), съехать в сторону (до 10 км/ч, затем 6 км/ч), при необходимости поставить машину в карман, заглушить двигатель и выйти; бесхозная машина жителя удаляется, когда игроков нет в 150 м.
- Неспешная жизнь (раз в 6 с): `civFidget` (прогулка рядом, 8 %/25 % днём), `civIdle` (позы и разговоры; пары «говорят/слушают», работа — позы по профессии, праздник — танцы, отдых, зарядка), `civReact` (в 12 м от игрока: вооружённый — следит и отступает/жестом «нет»; друг — приветствует; враг — отворачивается; повторяется не чаще раза в 180 с; зрители вокруг «зрелищ» `ALS_spectacles`), `civFlinch` (бег от выстрелов ~50–70 с).
- Все эти циклы пропускают юнитов в состояниях `ALS_attending`, `ALS_scene`, `ace_captives_*`, `ALS_venueVisit`, `ALS_fleeing`.

### 12.5 Экономика жителей (`civEconomy`, `civEvent`, `civAmbition`)
- `civEconomy` (раз в 60 с реального времени, аргумент — игровые часы `60·timeMultiplier/3600`): работающий получает зарплату (Factory 14, Farmer 11, Dock 16, Shop 10, Fuel 10, Driver 15, Pilot 22, прочее 12 € в час), минус 3 €/ч расход, в «errand» тратит до 25 €/ч (идёт в `ALS_townSpend[город]`, из него считается `p` города, см. 8.9); настроение ± (за деньги > 800, −0,02/ч при дефиците еды и при блэкауте города), границы 0,1…1.
- **Раз в игровой час** (`ALS_ambitionAt`): `civAmbition` (цели — купить машину за 4000 €, открыть магазин за 25 000 € (соперник-«shop»), стать перевозчиком за 30 000 € («haul»); с шансом 20–30 %/час), `loanDo tick`, `townPolitics tick`, `warTick "hour"`, `lifeHour`; раз в 6 игровых часов `townPulse [6]` и `lifeHour "towns"` (см. 8).
- `civEvent` (раз в 90–180 с): случайный житель с вероятностями по порядку проверок (r — одно случайное число): потеря работы (r < 0,08), поиск работы у безработного (r < 0,5), прибавка +500…1500 € (r < 0,2), ограбление −30 % денег (r < 0,3), потеря машины (r < 0,37), покупка машины при деньгах > 6000, долг; **каждое событие пишет «слух»** `civNews` (`ALS_news` — до 40 строк) и с шансом 35 % — заметку в газету.
- `lifeHour` (раз в игровой час): цели `home`/`revenge` (прокол колёс у «врагов» игрока), проценты и кредиты (8.3), аренда и жильцы (7.4), оплата охраны/менеджеров (7.5), (режим `towns`, раз в 6 игровых часов) пересчёт списка пустых домов `ALS_emptyHomes`, переезд одного безработного из «умирающего» города (p < 0,35) в лучший и **взломы машин игроков** (10 % для припаркованных машин в таком городе: пропадает инвентарь, разбивается стекло, сообщение «Your car was broken into»); `piJob "hour"`.

### 12.6 Мнения, друзья, враги (`opinion`, `peopleTick`)
- `ops[uid]` — мнение жителя об игроке −100…100; друзья +40, враги −40 (хэши `friends`/`enemies` содержат uid). `opinion "price"`: ≤ −70 → отказ, ≤ −30 → ×1,2, ≥ 20 → ×0,93, ≥ 50 → ×0,85; `"line"` — реплика. Изменения (`add`) распространяются на коллег на том же рабочем месте (`site`) в треть силы.
- `peopleTick` (раз в 20 с на игрока): друзья пишут сообщения (`msgSend`): подсказка о цене рынка, подарок 50–200 € (из денег друга), «слух» (+3 репутации в городе друга), при розыске — предупреждение; враги **стучат** (≤ 200 м, раз в 120 с: полиции становится известна позиция игрока) и мстят (прокалывают колёса машины игрока вдали, раз в 25–50 мин, 50 %). `peoplePub` — топ-8 «хороших» и «плохих» для приложения People.

### 12.7 Новости (`newsPost`, `newsSubjects`)
- `ALS_paper` — газета, до 60 записей `[номер, дата, город, заголовок, текст, тег, о ком, фото]`, `publicVariable`, БД `paper/paperSeq`; фото может быть автоматически привязано к машине игрока рядом, о котором статья. `newsSubjects` (для «фотографов с press pass») составляет список «сюжетов для снимка»: аварии, встречи (crash/fire/wildfire/robbery/body/pilot/race), праздники, погони (розыск ≥ 2★), тела (≤ 900 с), нападения на конвой и ограбление (кооп-задания), командиры армий по ночам и «двое, которым не стоит быть вместе» (`piJob`); у каждого цена и подпись.

### 12.8 Планировщик встреч (`storyInit`, `storyTick`)
- `storyInit` регистрирует PFH: `storyTick` (5 с), `encTick` (1 с), `peopleTick` (20 с), `econTick` (60 с), `festTick` (5 с) и очистку пустых групп (30 с).
- `storyTick`: для каждого игрока свой таймер `next` (первая встреча через 4–8 мин, далее 8–15 мин / опция `encounters`; 30 с после неудачного запуска; тишина > 5 мин без изменения денег ускоряет на 4 мин): условия «свободен» — жив, не в розыске, не в тюрьме, не AFK, не на паузе; контекст `road` (на дороге вне города, ≥ 25 км/ч, за рулём), `town` (в городе пешком < 12 км/ч), `sea` (лодка > 10 км/ч вне города); из реестра встреч (`encTypes`, метаданные `where`, `hours`, `weight`, `peak`, `needSeat`) выбирается взвешенно, недавние два типа получают вес ×0,1; запускает `encStart` (см. следующий раздел).

### 12.9 Особенности для интеграции
| № | Факт |
|---|---|
| L1 | Игроки не видят большинство жителей: физическое тело существует только в радиусе 650–1300 м от игрока, максимум `40·population` одновременно. Скрипты, которым нужен житель, должны использовать `civBorrow`/`civAs`. |
| L2 | `civSpawn` вешает на жителя `FiredNear`: любой выстрел < 70 м заставляет его бежать ~50–70 с; это же срабатывает на выстрелы ботов. |
| L3 | `lifeBubble` исключает жителей с `site ≠ ""` и действием `work` (продавцы, сотрудники заведений), поэтому заведения живут независимо от плотности населения. |
| L4 | Сохранение жителей исключает любые ссылки на объекты; в БД попадают только скаляры/массивы/хэши (`civSave`). |
| L5 | Все циклы мира тикают в планировщике: `lifeLoop` (spawn, ~2 с), `civEconomy` (60 с), `civEvent` (90–180 с), `civSave` (300 с); при падении `lifeLoop` вся жизнь замирает. |
| L6 | Мнение жителя влияет на цены в заведениях (`counterPrice`) — на 15 % и отказ при ≤ −70; награды аддона на мнения не влияют. |

## 13. Сцены («декорации мира») и встречи (истории с игроком)

Прочитано построчно: `sceneTick`, `sceneAway`, `sceneUnseen`, `scenePerson`, `scene_wreck`, `sceneArrest` (начало), `sceneTow` (начало), `encTypes`, `encStart`, `encSpot`, `encResident`, `encRoadAhead`, `encSpawnCiv`, `encNavSet`, `encTalk`, `encActs`, `encAnswer`, `encTick` (целиком); у каждого из 14 `scene_*` и 15 `enc_*` — метаданные и выборочно начало `start`, а также все строки с наградами/штрафами/репутацией/преступлениями (grep по `moneyAdd/_tip/repAdd/lawCrime/moneyFine/moneyPay`).
Не читал построчно: тела `tick` у большинства `scene_*`, подробные ветки диалогов и анимаций `enc_*`, остаток `sceneArrest`/`sceneTow`, `crashStart` (читал начало в разделе 10), `fireBrigade`.

### 13.1 Два разных механизма
| | **Сцены** (`scene_*`) | **Встречи** (`enc_*`) |
|---|---|---|
| Идея | живые «картинки» мира, на которые можно смотреть: ссора, свадьба, рынок на рассвете; почти не требуют реакции | короткие истории, где житель обращается к игроку за помощью/предложением и ждёт ответа |
| Запуск | `sceneTick` из `lifePlaces` (~раз в 10 с) | `storyTick` (каждые 5 с на игрока) через `encStart` |
| Темп | на игрока: первая в 60–120 с, затем раз в 120–240 с; не больше 2 живых сцен в 700 м | первая через 4–8 мин, затем 8–15 мин (÷ опция `encounters`), 30 с после неудачи |
| Реестр | по `allVariables missionNamespace` (`ALS_fnc_scene_*`) | по `ALS_fnList` (`enc_*`, как `coopJob_`/`jobEv_`) |
| Отключение | опция `encounters = 0` отключает оба | то же |

### 13.2 Сцены
- **Выбор:** `meta` модуля даёт `weight`, `hours [от, до)`, `days` (день недели; 0 = воскресенье); подходят типы с `weight > 0` по часу и дню; повторяются до 3 попыток; `where [позиция игрока]` возвращает точку сцены (или `[]`), `start` создаёт реквизит и возвращает `true/false`. `ALS_sceneForce` принудительно задаёт тип (отладка).
- **Жизнь сцены:** `tick` каждые ~10 с; сцена завершается, если `tick` вернул `false` или прошло 1500 с; затем остаётся, пока кто-то видит её объекты (`sceneUnseen`: игрок ближе 120 м или видит точку с ≤ 700 м), но не дольше 900 с; объекты без экипажа-игрока и без `ALS_owner` удаляются. Машины сцен заперты (`lock 3`) и помечены `ALS_jobEvObj`.
- **Каталог:**

### 13.3 Встречи
- **Запуск:** `storyTick` определяет контекст игрока (`road` — за рулём на дороге вне города ≥ 25 км/ч; `town` — пешком в городе < 12 км/ч; `sea` — лодка > 10 км/ч), отбирает типы с совпадающим `where`, часами и наличием места (`needSeat`), вес с учётом `peak` (повышенный вес в часы пик), недавние два типа ×0,1; `encStart` ищет точку (`encSpot`: на дороге ~300–450 м впереди по ходу `encRoadAhead`; в городе 45–75 м рядом; на море 250 м впереди), берёт «жителя» (`encResident`: из города, не в физическом мире), создаёт запись `ALS_enc[id]` и вызывает `setup` модуля.
- **Состояния** (`encTick`, каждую секунду): `wait` (житель ждёт у обочины и машет) → `approach` (игрок остановился/подошёл → житель идёт к двери машины) → `ask` (диалог через `talkOpen`, варианты ответов из `ask`) → ответ игрока (`encAnswer`, RPC `["answer"]` модуля) → специфичные состояния (`board`, `ride`, `racing` …) → `done` (житель уходит, через 30 с после ухода игрока или 300 с всё удаляется). Игнорирование: 120 с без ответа или уход > 80 м — «no»; два игнорирования подряд дают паузу 20 мин (`pauseUntil`). Если игрока нет — встреча закрывается. Все встречи со временем > 1800 с удаляются.
- **Влияние на мир:** участвующий житель получает `friends`/`enemies` (помощь делает его другом, +настроение; обман/кража — врагом), награды выдаются «чаевыми» (`_tip`: берутся из денег жителя, `moneyAdd` на **наличные**), репутация в городе жителя меняется (`repAdd`).

### 13.4 Особенности для интеграции
| № | Факт |
|---|---|
| E1 | Сцены и встречи используют те же `ALS_jobEvObj`/`ALS_keep`-помечённые объекты; удаляются по таймауту, если за ними никто не смотрит. Не помечайте так свои объекты. |

| E3 | Реестр встреч (`enc_*`) и сцен (`scene_*`) расширяемый, но сцены собираются один раз (`ALS_sceneTypes` кэшируется на запуск), встречи — по длине `ALS_fnList` (кэш сбрасывается при росте списка). |

| E5 | Сцена `crash` и ряд встреч запускают полицию/эвакуатор через `lawDispatch` и `drvGo`; на них влияет автопилот (раздел 10) и замедление трафика `ALS_calmed` (раздел 11). |

### 14.1 Банды
- **Состав.** Четыре NPC-банды (`ALS_gangs`): *The Syndikat* (красная), *Black Olives* (оранжевая), *Saint Pavlos Boys* (розовая), *The Harbour Rats* (жёлтая); банды игроков добавляются как `p_<uid>` (БД `mygang_<uid>`, список `mygangs`, публикуется `ALS_pGangs`).
- **Города банд** (`ALS_gangTowns[город] = {gang, strength, owner, pos, radius}`; БД `gangTowns`; создаются один раз): три «семени» — самые удалённые друг от друга малые города/деревни; каждый малый город в 7 км от ближайшего семени достаётся его банде с вероятностью 55 % (всегда, если ближе 100 м); `strength` 4–8, `radius` 250–600 м; все `city/capital` без банды получают *Harbour Rats* с силой 6–9.
- **«Тусовка»** (`gangTick`, из `lawLoop`, раз в ~10 с): если игрок ближе 800 м, у города нет владельца-игрока и `strength > 0`, на «точке» (`gangSpot`, плоское место 30 м от центра) появляются до 3 бандитов (`min(strength, 3)`): пистолет (`armSidearm`), у некоторых — купленное у игроков оружие (`gang_guns`, до 6 стволов на банду), позы «отдыха», `ALS_npc = "gang_<город>"`, роль `gang` (диалог). Обработчики `Hit`/`Killed`/`FiredNear < 25 м` от игрока → `gangDefend`: все оживают, переходят в бой (`addRating −100000`, `SAD` к нападавшему), через 60 с вне зоны успокаиваются. После уничтожения тусовка возвращается через 600 с (20 с, если город выбран целью чьего-то `hit`-задания). Удаляются, когда игроков нет рядом.
- **Убийство члена банды** (`gangKilled`): `strength −1`; если убийца — не игрок (или просто «чей-то» NPC), больше ничего не меняется. Убийство телохранителем игрока (`ALS_bgOf`) засчитывается его хозяину. У игрока-убийцы репутация в банде −15, уличная +2; закончилось задание `hit` — 1500 € **наличными**, +15 репутации. При `strength ≤ 0` и свободном городе город **переходит игроку** (`owner = uid`): магазины платят «крышу» 400 € за каждый город **раз в 600 реальных секунд** на **банк** владельца (суммируются по всем его городам; сила города и онлайн владельца не проверяются), банда-враг −40.
- **Репутация в банде** `ALS_gangRep[uid][gid] ∈ [−100, 100]` (БД `gangrep_<uid>`, публикуется `ALS_gangRep`). Ступени (`gangRanks`): *Runner* (старт, репутация ≥ 15), *Dealer* (5 выполненных заданий, репутация 40), *Lieutenant* (12 заданий, репутация 70). Вступить можно с репутацией ≥ 15; при вступлении у всех остальных банд −20.
- **Задания у лидера** (`gangDo "work"`, один активный): `run` — отнести пакет (`ALS_gang_package`) в другой город той же банды (до 9 км) за 400 € и +6 репутации; `collect` — забрать у торговца «долг» (получаете 800 €, возвращаете 560 €, остаток ваш; +10 репутации; присвоили — −30 и угрозы); `hit` — убить 1–2 бойцов соперников в их городе, 1500 € и +15; просроченные задания дают штрафы (−10 / −30).
- **Бонусы ранга:** Dealer (оптовые закупки: 10 пакетов травы по 45 € или 5 пакетов кокаина по 160 €), Lieutenant (собственный **угол** `ALS_corners[uid] = [город, трава, кокаин, следующий_расчёт]`: каждые 600 с до 3 пакетов продаётся автоматически (сначала кокаин, остаток — трава): кокаин 310 €, трава 120 € за пакет ×0,8 ×«затоваривание» (`ALS_streetSold`), деньги — в **банк**, без `dirty_`; с шансом 1/12 за расчёт — налёт полиции, запасы обнуляются), скупка оружия у игрока за 40 % цены (+3 репутации), наводка на скупщика, чёрный рынок (репутация ≥ 30 либо ранг ≥ 2).
- **Месть:** если у игрока репутация ≤ −40 хотя бы в одной банде, он пешком и **ни один центр города не ближе 400 м**, то на каждом тике `gangTick` (~10 с) с шансом 5 % (не чаще раза в 900 с `time`, первый раз — не раньше 600-й секунды работы миссии) 3 боевика (`ALS_hitSquad`, сторона `civilian`, `addRating −100000`, пистолет) появляются в 350–500 м от него и идут на него (`SAD`, `reveal`). Группа удаляется, когда прошло ≥ 600 с и ни один игрок не ближе 300 м к живым членам.
- **Полицейские облавы на тусовки** (`gangSearch`): патруль в 150 м от точки с вероятностью 35 % останавливается, обыскивает (15 с, все «сдаются»), с шансом 25 % одного арестовывают; затем 900 с «перерыв».
- **Банды игроков** (`myGang`, `gangWar`): основание — уличная репутация ≥ 50 («feared»), 5 000 € (`moneyPay`), название 3–28 символов, цвет из шести (`ColorRed/Blue/Green/White/Brown/Khaki`, иначе белый); запись в `ALS_gangs["p_<uid>"] = {name, color, owner, crew[]}` и БД `mygang_<uid>`. Набор в экипаж: цель — NPC (`ALS_civId`) 18–35 лет, без работодателя и без другого экипажа; шанс `max(0,2; уличная_репутация/100)`; не более 8 человек. Пока в городе-«владении» игрока есть живой игрок в 800 м, до 3 членов экипажа показываются «тусовкой» (`civBorrow`, пометка `ALS_myCrew`). Участники-игроки: до 6 (*Soldier*/*Lieutenant*), приглашение 60 с; война с NPC-бандой (новости), перемирие стоит 10 000 €; пока идёт война, раз в 2 игровых часа с шансом 34 % «враги» отбивают город, если участников нет рядом; война заканчивается, когда у врага не осталось городов.
- **Уличная репутация** (`streetRep` 0…100, БД `streetrep_<uid>`): *nobody* < 10, *known on the street* ≥ 10, *respected* ≥ 30, *feared* ≥ 50, *a legend* ≥ 75. Растёт за убийства бандитов (+2), задания (+3), влияет на ростовщика (≥ 30) и букмекера (≥ 30), входит в счёт «наследия» (8.10).
- **Покупатели на улице** (`streetBuyers`): вызывается в конце `drugTick` (~10 с). С травой/кокаином в инвентаре, пешком, не AFK, в пределах `min(радиус города, 400 м)` от центра города: каждый тик шанс 5 % (20 % ночью; «ночь» здесь — до 5 и после 20 ч, в `drugDo` — до 6 и после 20 ч), после срабатывания — кулдаун 90 с. Выбирается один из свободных физических жителей на 15–90 м (список сортируется по расстоянию и отдаётся в `ALS_fnc_pick`; не на сцене, не обслуживающий), идёт к игроку (`ALS_buyer = uid`, `ALS_scene = true`) и предлагает купить (диалог `deal`); если игрок отошёл > 120 м, потерял товар или прошло 90 с — отмена.

### 14.2 Преступления и «домашний бизнес» (ACE-меню «Crime»)
- **Условие меню:** есть семена/сырьё, спелые растения рядом или ≥ 4 деталей `ALS_good_parts` у своей недвижимости.
- **Выращивание:** посадка (6 с) допустима вне городов (`город.r ≥ 300 м`), вне дорог и воды — либо внутри своего дома под лампой; растение `ALS_plants = [объект, владелец, время, поз., спелое?, влага, здоровье, рост, время последнего шага, комната]`, зрелость `ALS_plantGrowSecs = 1200 с` накопленного «роста». Шаг модели (`plantStep`, вызывается `drugTick` для каждого неспелого растения; интервал режется на куски ≤ 60 с): влага −0,1 за 600 с; под открытым небом во время дождя +0,002/с (до 1); границы влаги 0…1,5; здоровье за 600 с: влага < 0,15 → −0,12; влага > 1,1 → −0,18; иначе +0,03 (0…1); «рост» копится только при влаге ≥ 0,15 и здоровье > 0,2, в помещении (над растением есть геометрия в 20 м) — ×1,25. Здоровье 0 → растение гибнет (сообщение «высохло» / «корни сгнили»). Спелым считается при росте ≥ 1200 с и здоровье > 0: модель меняется на «большую», игрок получает сообщение. Состояние сохраняется в БД `plants` (с относительными возрастами) и восстанавливается `plantSave "restore"`; клиентам публикуется `ALS_plantsPublic`. Полив даёт +0,45 влаги; самцы (по хэшу позиции, 1 из 7) дают только семена. Сбор: до 6 сырья на растение ×здоровье.
- **Обработка** (`drugDo "process"`, дом игрока, до 12 сырья; клиент — HTML-окно «весов» `scalesUI`: 3,5 г на единицу сырья, результат (пакеты, «лёгкие», резать/нет) присылает клиент, но сервер ограничивает: пакетов ≤ ⌊сырья·3,5/2⌋, «лёгких» ≤ пакетов, сырья не больше имеющегося): качество `45 (+25, если сырьё сушилось на полках в течение 30 мин) − 2·«лёгких»`; обрезка (`trim`, 30 мин, нужен стол) ×1,25 пакетов, «разбавить» (верстак) ×1,5 с −40 качества — множители применяются **после** ограничения; лёгкие пакеты хранятся счётчиком `short_<uid>`; качество усредняется в бренд (`uwBrand`: EMA 3:1, множитель цены 0,7 + 0,006·качество; своё название ≤ 24 символа). Каждая обработка повышает «жар» лаборатории `ALS_labHeat[дом]` на число единиц сырья.
- **Мастерская:** `gunsmith` (4 детали → случайная винтовка/пистолет-пулемёт/пулемёт дешевле 6 000 € из каталога без «banned», +2 магазина, +4 жара), `print` (нужен принтер/компьютер, 800 € → 5 фальшивых банкнот 500 €, +3 жара), `fake` (нужен верстак, 300 € → фальшивая древность), `distil` (нужны бочка/плита/печь в своём доме и ящик продуктов `ALS_good_produce` → 6 бутылок ципуро; лавочнику — 60 €/бутылка наличными и в `dirty_`, ≤ 6 бутылок в игровые сутки на лавку, 10 % — преступление `bootlegging`).
- **Полиция и соседи:** `drugTick` (из `lawLoop`, раз в ~10 с): раз в 300 с жар каждого дома остывает на 1; **каждый тик каждое растение, посаженное в комнате дома, прибавляет +1 к жару** этого дома (то есть домашняя плантация греет дом быстрее, чем он остывает). Ступени `lawInquiry`: ≥ 8 — письмо «Police station» (жалоба соседа); ≥ 14 — письмо соседа «What IS that smell…» (раз в 24 игровых часа) + новость «Strange smell in <город>» + у дома через 60 м паркуется запертая гражданская «неприметная» полицейская машина (`C_SUV_01_F` по умолчанию); ≥ 20 — открытка детектива; ≥ 24 — **налёт**: жар обнуляется, изымаются все наркотики со склада дома и растения этой комнаты, штраф `1000 + 50·найдено` (если что-то найдено), на место едет патруль (`lawDispatch "scene"`), при игроке в 150 м — преступление `drugs`; если ничего не найдено — игрок получает сообщение, что полиция ничего не нашла.
- **Сбыт** (`drugDo "deal"`, житель из физических): продаётся кокаин, если он есть в инвентаре, иначе трава (вкус постоянного клиента может переопределить выбор); один житель — не чаще раза в 600 с. 6 % (3 %, если это ваш «ждущий» покупатель) — это полицейский (`dealing`, арест); обычный прохожий соглашается с шансом 45 % (65 % ночью); отказавший с шансом 15 % сообщает полиции (`dealing`); продаётся 1–3 пакета: кокаин `250…369 €`, трава `90…149 €` за пакет ×`1/(1 + проданное_в_городе/20)` (насыщение рынка, `ALS_streetSold[город]`; счётчик общий для улицы и «угла» игрока, падает на 1 раз в 120 с в `streetBuyers`) и, для травы, ×0,7…1,3 (бренд); для травы при `short_<uid> > 0` с шансом 50 % «лёгкий пакет» замечен: цена пополам, клиент помечается `ALS_shorted`; постоянный клиент — множитель `drugClients`; **деньги наличными и в `dirty_<uid>`**.
- **Постоянные клиенты** (`drugClients`): раз в 20 мин для каждого игрока: жители, купившие ≥ 2 раза с доверием ≥ 20, с шансом 30 % пишут с просьбой о встрече (`uwMeet`: на карте метка, житель ждёт у дома до 2 игровых часов); цена ×1,25 для постоянных; каждый 10-й клиент даёт полиции наводку (`drugTip`: через 180 с по месту встречи высылается патруль `lawDispatch "scene"`, наводка действует 1800 с; если за это время игрок с любым `ALS_drug_*` в инвентаре окажется ≤ 150 м от места и его увидит полицейский в 25 м — всё изымается, преступление `dealing`), дом игрока в 100 м от места +8 жара.
- **Ограбление** (`crimeRob`, с оружием ≤ 6 м): у жителя берётся 8 % денег (20…600 €), повтор той же жертвы раньше 30 мин — «ничего нет»; у заведения (роль не `civ`): 600…2000 € (×2 для автосалона/оружейного), повтор раньше 30 мин — только тревога; через 15–30 с — преступление `robbery`, если кто-то видел/жертва жива/тревога; обиженный становится врагом игрока.
- **Угон** (`crimeCarjack`): водитель-гражданин, оружие в руках ≤ 9 м; водитель убегает, машина отпирается и помечается `ALS_civCar` (чужая) и `ALS_stolenBy`, через 12 с — `carjack`.
- **Карманник:** в больших городах (`city/capital`) в точке банды бродит вор (`ALS_thief`); при приближении ≤ 3 м с шансом 34 % (раз в 300 с) забирает 5 % наличных (≤ 300 €).
- **Подделка** (`forgeDo`, 400 €, у своей недвижимости, к машине): `fakelic_<uid>[лицензия] = качество` (0,5 + 0,1·число подделок, 0,3…0,9); качество — шанс пройти проверку на КПП (проваленная — штраф 1500 € и изъятие, 8.5).
- **Раскопки** (`ruinDo`, ночью 20:30–05:00, на «античных» объектах): ≤ 3 находки/участок/сутки, шанс 40 %; продажа коллекционеру 400…1200 € наличными (+`dirty_`); подделки 30 % — отказ и бан на сутки.
- **Арсеналы** (`armoury`): ящики оружия у участков полиции и у военных зон запрета полётов; закрыты (`ALS_armouryLocked`); взлом отмычкой (3 с) → преступление `heist` и тревога; пополняются раз в 72 игровых часа.
- **Букмекер** (`bookie`): ночью (20–02 ч) со стрит-репутацией ≥ 30 принимаете ставки на «гонки» двух жителей; итог = пул (2000–6000) − выплата, **может быть отрицательным**; 10 % — `bookmaking`; прибыль в `dirty_`.

### 14.3 Скупщики (fence) и чёрный рынок
- **Скупщики** (`crimeInit`): до 4 NPC «Fence» на промплощадках/портах (≥ 1500 м от станций полиции, ≥ 4000 м друг от друга), в укромном месте. После первого контакта город попадает в `ALS_fencesKnown` (БД `fences_<uid>`).
- **Услуги** (`fenceDo`, ≤ 15 м; `serveAt` отказывает, если торговец мёртв/сдаётся/в наручниках или если игрок в «охоте» и скупщик стоит в одном из её городов): продать **краденую** машину в радиусе 30 м без живого игрока-экипажа (подходят: ваша угнанная `ALS_stolenBy`, гражданская `ALS_civCar`, полицейская, скорой, или чужая «владельческая», которой вы пользоваться не вправе) — 25 % цены каталога (35 % для полицейской) ×(1 − 0,8·урон); если у машины был владелец, она убирается из `ALS_ownedVehs` и вызывается `vehWrecked` (страховка владельцу); **ящики чужих рабочих грузов** (40 % цены товара ×число единиц; задание хозяина получает статус `failed`, NPC задания убираются, хозяин уведомлён) и **чужие контрабандные ящики** (по 300 € плоско); **трава 55 €/пакет** (все пакеты сразу); оружие из инвентаря (35 % базовой цены; оружие в руках не берётся); купить оружие (130 % цены, 3 позиции у каждого скупщика детерминированно по `npcId`: `(npcId·7 + k·13) mod n` от отсортированного списка, с 3 магазинами); отмычка 150 €; семена ×5 — 200 €; подсказка про инкассатора 500 €; новые документы на краденую машину (`max(цена, 2000)/2`, снимаются метки кражи, ставится `ALS_forged`, вы становитесь владельцем); контрабандные рейсы (три вида); тайник-«дроп» (1200 € → 6 пакетов кокаина через 7 игровых часов на метку); путь к чёрному рынку после ≥ 3 сделок (`fencedeals_<uid>` растёт на каждую продажу машины/ящиков/травы/оружия). Все продажи — **наличные**, счётчик `dirty_` скупщик **не трогает**. Список продаваемого оружия настраивается через `ALS_weapRules`: `fence` (явный список), `fenceKinds` (по умолчанию rifle / machine gun / smg / sniper rifle), `fenceMax` (макс. цена, по умолчанию 20 000), `fenceAdd`.
- **Чёрный рынок** (`blackInit`): до 4 торговцев в глуши (≥ 1300 м от городов, ≥ 150 м от дорог, плоско, вне зон запрета и военных баз, разнесены на 4 км); палатка + фургон + лампа; открывается через скупщика/банду; **ACE Arsenal на любые предметы** (цена `каталог·1,5·prices`, для не-каталожных — по типу), оплата после закрытия (`blackPay`); техника — `dealerStock "black"` (×1,5, без документов и лицензий).
- **Тайники** (`uwStash`): до 3 скрытых ящиков на игрока (вне дорог/зданий/воды), хранятся в БД `uwstashes`.
- **Ломбард** (`uwEarn "pawn"`): оружие в руках за 40 % цены (до 8 м от NPC).

### 14.4 Контрабанда (`smuggle*`)
- **Старт** (у скупщика, `smuggleStart`): один заказ на игрока (`ALS_smuggle[uid]`), виды `fence` (другой скупщик дальше 2,5 км), `valley` (точка в холмах 3–7 км от скупщика: плоское место вне 1500 м от городов и дорог, сброс с парашютом), `boat` (точка в море 2,5–4 км, глубина > 15 м). Груз: `3 + floor(smugrep/2)` ящиков (макс. 8), каждый `ALS_contraband = uid`, `ALS_good = "contraband"`. Оплата `round((1500 + км·350)·M·n/3 / 50)·50`, где в коде `M = 1 + (0,12·rep) min 1,5` записано без скобок вокруг `min`; по приоритетам SQF `min` стоит наравне с `+`, поэтому выражение читается как `(1 + 0,12·rep) min 1,5` — множитель не выше 1,5 (достигается при `smugrep ≥ 5`). Это вывод из чтения кода, в игре не проверялся. При `smugrep ≥ 2` скупщик берёт **взнос заранее** `5 %·rep` (≤ 50 %) от оплаты через `moneyPay` (нет денег — заказа нет); срок 2400 с; с шансом 10 % маршрут «слит» (`informed`).
- **Встречи по пути** (`smuggleMeet`, раз в тик): для `valley`/`boat` при приближении на 1500 м (3000 м для лодки) создаются неуязвимые «покупатели» (`C_man_p_fugitive_F`, пикап `C_Offroad_01_F` или лодка `C_Boat_Civil_01_F`), которые удаляются, когда игрок ушёл дальше `r + 1000`; для авиации в 2 км от точки — «наводчик» (подсказки «dead ahead / come right 30°» раз в 6 с). Если маршрут «слит» и трасса ещё не раскрыта, при удалении > 1000 м от старта за игроком вылетает полицейский вертолёт (`ALS_copCar`, 150 м, `doMove` на игрока): оторвались на > 2 км — «потеряли»; висит 180 с — трасса раскрыта. Для лодки с грузом один раз (34 %) в 1400 м появляется катер береговой охраны (`west`, `CARELESS`): в 40 м — груз изымается, преступление `smuggling`, заказ снят; не догнали за 300 с — уходит.
- **Доставка:** на машине — к скупщику (`smuggleDeliver`), 8 % — «подстава» (преступление `smuggling`, груз потерян); из рук (`smuggleHand`) — те же 8 %; сброс с самолёта/вертолёта (`smuggleDrop`: высота 60–300 м, не далее 300 м от метки, парашюты, оплата пропорционально приземлившимся ≤ 300 м, +10 % при всех ≤ 100 м); лодка: ящики за борт, забрать за 24 ч.
- **Слежение** (`smuggleTick`, самолёт/вертолёт с контрабандой в ACE-грузе): включённый транспондер (`ALS_squawk` не `""`/`"0000"`) — сразу «прослеживают»; полёт > 150 м над землёй в радиусе (зона запрета + 6 км) копит «засветку» (ночью без бортовых огней — вдвое медленнее); ≥ 15 с — трасса раскрыта; посадка на полосу аэродрома (скорость < 15) — один раз на аэродром 35 % таможня: ящики изымаются, `smuggling`, **отзыв лицензий `contractor`/`military`** (`armyDo "revoke"`). Раскрытая трасса — оплата ×0,5 и преступление при доставке.
- **Награда:** `smugrep_<uid>++`, деньги на **наличные** и в `dirty_<uid>`; при включённой войне поступления поставляются в арсенал баз игроков (`warArms "smuggled"`, только для `smuggleDeliver`/`smuggleHand`).

### 14.5 Награды за голову (`bounty*`) и охота на убийцу (`manhunt`)
- **Заказ** (`bountyDo post`): цель — другой игрок в сети (себя нельзя), сумма ≥ 1000 € списывается строго с **банка** (`moneyAdd [uid, 0, −n]` — нет денег в банке, нет заказа); ≤ 3 активных на заказчика; срок 60 «минут» (`mins`), `bountyTick` вычитает 0,5 каждые 30 с реального времени (то есть 60 реальных минут); не взяли — вся сумма возвращается в банк; отмена (`cancel`) возвращает 90 %. Оповещаются цель и все остальные игроки; публикуется `ALS_bountyPublic` (приложение Bounties) и `ALS_myBounties` у заказчика; хранится в БД `bounties`.
- **Выплата** (`bountyCollect`, всегда в **банк** взявшего): (а) убийство цели другим игроком (`lawKilled`, если он не в экипаже/компании убитого) — сумма **всех** заказов на цель, кроме собственных заказов убийцы; убийство «честное» или нет значения не имеет; (б) арест цели игроком-«охотником» (`lawArrest`: не в экипаже/компании, не в тюрьме, в 25 м; последний, кто ударил цель за 300 с, либо любой в 6 м) — то же плюс при розыске цели ≥ 3★ премия полиции `1000·ур²`. В публичный список розыска ≥ 3★ выводится как «police»-награда той же суммы. Новость «Bounty hunter collects …» и сообщения обеим сторонам.
- **Охота** (`manhunt`): вызывается из `lawKilled` при убийстве игроком жителя, имеющего `ALS_civId`. Журнал убийств `ALS_killLog[uid]` за последние 600 с `time`; «в толпе» — в момент смерти в 30 м было ≥ 8 живых людей не из армии. Условие: 5 убийств в журнале **или** ≥ 3 убийства «в толпе». Запись `ALS_manhunts[uid] = {towns, until = игровые_часы + 72, victims, at, hitSent}`; `towns` — города в 2000 м от последней жертвы плюс город первой записи журнала; в каждом `repAdd −200`, преступление `massacre`, новость «Manhunt», `ALS_manhunt = true` у игрока. Действие: `serveAt` — ни один магазин/скупщик/торговец в этих городах не обслуживает; `lawTick` — розыск не опускается ниже 4★ и постоянно включён режим «lethal» (патрули в `COMBAT/RED` с `SAD`-путевыми точками; пассивные ветки ареста — остановка машины и стояние на месте — отключены, остаётся только сдача с поднятыми руками); блокпосты `lawRoadblock` (общее для розыска ≥ 3★) помечены `manhunt` (радиус 900 вместо 600). Тик `manhunt "tick"` вызывается из `warTick`. Через 600 с `time` «семьи» присылают одиночного наёмного убийцу (`C_man_hunter_1_F` в 300 м от последней позиции розыска, винтовка из `ALS_stashGuns` типа 1, 6 магазинов, навык 0,8, `addRating −100000`, `reveal` и `doMove` к игроку каждые 20 с). Охота кончается: срок вышел, **убийца убит** (или пропал) после отправки, либо откуп — 10 000 € (`moneyPay`) у члена банды с `ALS_gangTown` в 4 м (`warDo "buyoff"`, действие видно только при `ALS_manhunt`).

### 14.6 Особенности для интеграции
