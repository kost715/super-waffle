## 1. Назначение и устройство

Аддон — **необязательное дополнение к Arma LifeSim**: вводит «ЧВК» как игровую организацию.
1. Лицензия «PMC establishment license» (1 € для теста) — через штатную систему лицензий.
2. База — купленное свободное здание вида `Industrial` (1 € для теста), штатный склад со штатными дверями/хранилищем.
3. Название организации (3–40 символов Unicode, кириллица).
4. Рабочее место на базе (стол, монитор, системный блок, клавиатура) — «компьютер» с окном управления.
5. Приложение «ЧВК» в штатном телефоне LifeSim.
6. **Контракты ЧВК**: доска предложений, рейтинг (5 уровней), 10 типов заданий (7 государственных, 3 частных), награда в личный банк основателя. Прежний «тестовый» контракт «eliminate» (0.4.0) остаётся запасным вариантом.

Архитектурный принцип (как заявлено в комментариях): **не заменять штатные функции целиком, а оборачивать/дополнять** — аддон использует штатные деньги (`moneyPay/moneyAdd`), недвижимость (`houseClaim/houseSell/houseLock`), группы (`crewOf`, `coopAccept/coopEnd`), автопилот (`aiDrive`), UI-веб-контрол (`ALS_RscPhoneWeb`) и БД (`dbGet/dbSet/dbLoading`).

## 2. Запуск и планировщик

**Порядок:**
1. `postInit` (CfgFunctions `postInit = 1`, на каждой машине): `spawn` → ждёт `ALS_ready` оригинала → подменяет в `ALS_licenses["alspmc_pmc"]` название и описание на локализованные (индексы 0 и 4) → на сервере `serverInit`; на клиенте ждёт `player` и публичную `ALSPMC_ready`, затем `clientInit`.
2. `serverInit` (один раз, флаг `ALSPMC_serverStarted`): `ALSPMC_ready = false`; читает ключи БД (см. 5); **оборачивает** `ALS_fnc_houseSell` (сохраняя оригинал в `ALSPMC_nativeHouseSell`); `reconcile`, `save`, `terminalInit`, `questInit` (→ `contractInit`); `ALSPMC_ready = true` (публично); PFH `reconcile` каждые **2 с**.
3. `clientInit`: запоминает действующий `ALS_fnc_phoneMsg` как `ALSPMC_nativePhoneMsg` (делегат), загружает `phone.js` и `licensePhoneOnly.js` из PBO (`loadFile`), вешает обработчик публичной `ALSPMC_basesPublic` → `applyValues`, PFH `clientTick` каждые **0,25 с**.

**Таймеры и периоды (реальные секунды, `diag_tickTime`/`time`):**
| что | период |
|---|---|
| `reconcile` (сервер) | 2 с |
| `clientTick` | 0,25 с; внутри — опрос статуса телефона/ПК раз в 1 с, пока приложение/окно открыто |
| повтор создания недостроенного рабочего места | не чаще раза в 30 с на базу (`ALSPMC_terminalRetry`) |
| кэш реестров объектов для контрактов (`contractSites`) | 30 с |
| время жизни доски предложений | `contractPoolSeconds`, 600 с (допустимо 300–3600) |
| таймаут ожидания ответа сервера в UI | 10 с |
| `coopTick` оригинала (вызывает `tick` сценария) | штатный (в разделе 1 аудита оригинала — 3 с) |

## 4. Сеть и права

- `CfgRemoteExec >> Functions` в `config.cpp` разрешает: `ALSPMC_fnc_buyBase` (цель сервер), `phoneDo` (сервер), `desktopDo` (сервер), `message` и `stateSet` (цель 0 — «все», комментарий: LifeSim часто хостится игроком, чей компьютер и есть сервер), без JIP. Режим удалённого вызова миссии не меняется.
- **Проверка вызывающего** (`requestAllowed [юнит]`): сервер, юнит жив и это игрок, и (если вызов удалённый) `remoteExecutedOwner == owner юнита`, и `ALSPMC_ready`. Каждая серверная операция начинается с неё. `message` и `stateSet` на клиенте принимают только вызовы от сервера (`remoteExecutedOwner == 2`); `stateSet` — только два имени переменных.
- **Токены запросов:** клиент нумерует запросы (`sequence`, старт `Date.now() % 900 000 000`), сервер принимает `0…10⁹` целые; `questDo` хранит последние 32 токена игрока и повторный запрос с тем же токеном возвращает прежний результат (идемпотентность), токен `≤ 0` отвергается.
- **Состояние только владельцу:** `phoneSync` собирает состояние игрока и отправляет `stateSet` лично ему (ранее — публичная переменная всем, исправлено в 0.6.3); у игрока на сервере копия в `ALSPMC_phoneState`.
- **Физический доступ к ПК:** `terminalCanUse` — расстояние ≤ 4 м, объект зарегистрирован как рабочее место базы, база принадлежит аддону, `canUse(uid, владелец базы)`; сервер повторяет проверку при каждом действии (`desktopDo`), а при отказе шлёт клиенту `valid = false` → окно закрывается.
- **Серверная проверка денег/лицензии:** покупка базы проверяет наличие лицензии в БД (`lic_<uid>`), а не клиентский флаг; награды не передаются клиентом.

## 5. Сохранения

Все данные — в БД мира/слота LifeSim (`ALS_fnc_dbSet/dbGet`), на диск попадают штатным сохранением. Ключи (форматы с версией; формат с 0.4.0 не менялся):
| ключ | содержимое | проверка при загрузке |
|---|---|---|
| `alspmc_bases_v1` | `[[ключ дома, [основатель, рыночная цена, уплачено]], …]` | типы, основатель непуст, цена ≥ 0, уплачено > 0 |
| `alspmc_names_v1` | `[[uid, байты UTF-8], …]` | байты проходят `normalizeName` без изменений |
| `alspmc_workstations_v1` | `[[ключ, [позиция ASL, направление]], …]` | позиция из 3 чисел, модуль ≤ 10⁶ |
| `alspmc_quests_v1` | `[1, последовательность, [[id, [основатель, статус, награда, поз., состав, начало, конец, причина]], …]]` | схема строки, статус и причина из списка, состав ≤ 4 уникальных uid, основатель в составе, id ≤ последовательности |
| `alspmc_contracts_v1` | `[1, [[id, [тип, уровень, опыт, выплачено]], …], [[uid, опыт], …]]` | тип из каталога, уровень 1–5, опыт ≤ 10 000, выплачено ≤ 10⁶, опыт игрока целый ≤ 10⁸ |
Загрузка защищена `dbLoading` оригинала (запись ключей блокируется, пока подсистема не готова).

**Поведение при повреждённых данных (факт):** каждая подсистема отказывается включаться, оригинальный ключ не затирается, пишется строка в лог.
- `alspmc_bases_v1` повреждён → `serverInit` **завершается досрочно**: `ALSPMC_ready` остаётся `false`, не запускаются `terminalInit`, `questInit` (а с ним контракты) — то есть отключается **всё** аддоновое, хотя сообщение в логе говорит «purchases disabled».
- `alspmc_names_v1` повреждён → отключено только переименование.
- рабочие места / квесты / контракты — отключается только соответствующий блок.

**Когда пишется:** изменения денег/имущества сразу вызывают `ALS_fnc_dbSave` (лицензия, покупка и продажа базы, конец контракта); двери, название, принятие контракта — штатным периодическим автосохранением.
**Перезапуск:** активные контракты помечаются `interrupted` («restart»), ИИ и транспорт не восстанавливаются, повторной выплаты нет. Рабочие места восстанавливаются на прежних местах (`terminalSync`). Журнал: до 20 последних записей на основателя + все активные.

## 6. ЧВК: лицензия, база, название, продажа

- **Лицензия** (`phoneDo "license"`): штатный `licBuy` — требует клерка мэрии в 15 м; запись `lic_<uid>`; затем `dbSave` и сообщение. Клиентская кнопка заблокирована, если клерка нет рядом (`clerkNear`, из `ALS_npcPublic`, роль `clerk`, ≤ 15 м) или не хватает денег.
- **Покупка базы** (`buyBase`), всё в атомарном блоке `isNil {…}`: `reconcile`; лицензия; ключ в `ALS_houses`, запись имеет ≥ 8 полей; вид — из `allowedTypes` (`Industrial`); не `Wrecked`; игрок ≤ 40 м; не в `ALS_reserved`; не в `ALS_owned`; у основателя **нет другой действующей базы**; цена `max(1, basePrice)` оплачивается `moneyPay` → `houseClaim` (если не удался — возврат с тем же разбиением банк/наличные, как у штатной оплаты) → запись `ALSPMC_bases[ключ] = [uid, прежняя рыночная цена, цена]` → `bizGet` (склад по-штатному), `save`, `bizPublish`, рабочее место, `dbSave`, сообщение. Побочный эффект штатного `houseClaim`: записывает `home_ever_<uid> = true` (влияет только на выдачу стартового дома новичку).
- **Цена базы в мире:** `save` и `applyValues` записывают в `ALS_houses[ключ][5]` уплаченную цену (1 €), затем вызывают `housePublish` — чтобы телефон и аренда считали по тестовой цене; при потере базы возвращается прежняя рыночная цена (`reconcile`, `sellHouse`, `applyValues` для убравшихся ключей). Применяется на сервере и всех клиентах (в том числе JIP) по публичной `ALSPMC_basesPublic`.
- **Название** (`setName`): лицензия обязательна и `ALSPMC_namesReady`; клиент присылает **массив байтов UTF-8**, сервер проверяет строго в `normalizeName`: ≤ 320 байт, целые 0…255, схлопывает пробелы, обрезает концевой пробел, декодирует UTF-8 (двух-, трёх-, четырёхбайтные, без «усечённых» и «слишком длинных» форм, без суррогатов), запрещает управляющие (< 32, 127–159), `<`, `>`, разделители строк и абзацев, форматирующие невидимые символы (U+200B…200F, 202A…202E, 2060…206F, 00A0, FEFF); **3–40 символов**. Хранит байты; на странице декодирует `TextDecoder("utf-8", {fatal})`.
- **Продажа** (`sellHouse`): для ключа вне `ALSPMC_bases` — оригинал; для базы — штатная продажа (проверки владельца/компании, переезд склада, мебель), затем возврат рыночной цены, удаление записи и компьютера, сохранение. За тестовое здание штатная формула даёт **0 €** (`round(housePrice·0,7/100)·100`), мебель и товары оплачиваются отдельно.
- **Сверка** (`reconcile`, раз в 2 с): если ключа нет в `ALS_houses` или `canUse(основатель, текущий владелец)` ложно — запись базы снимается, цена возвращается, компьютер удаляется. Покрывает потерю базы внешними путями (продажа, утрата компании).
- **Двери** (`lock/unlock`): штатный `houseLock`, но только если `canUse` и ключ — база аддона.

## 7. Рабочее место на базе (компьютер)

- **Создание** (`terminalEnsure`): четыре объекта ванильных классов из `ALSPMC_Settings` (стол `Land_TableDesk_F`, монитор `Land_PCSet_01_screen_F`, системный блок `…case_F`, клавиатура `…keyboard_F`); `enableSimulationGlobal false`, `allowDamage false`; позиционирование по нижней границе объектов; метки `ALSPMC_workspaceKey` на всех, `ALSPMC_terminalKey` на мониторе. Раскладка (`[позиция ASL, направление]`) сохраняется в `alspmc_workstations_v1`; публичный список `ALSPMC_terminalsPublic` = `[ключ, монитор]`. Если классы недоступны — создание откладывается (лог). Нет раскладки → `terminalFindSpot`.
- **Поиск места** (`terminalFindSpot`): берёт до 24 штатных ходимых точек первого этажа (`houseFloor`), пробует смещения 0/±0,7 м по двум осям и 4 поворота; требует расстояние до выходов > 1,8 м, свободу от штатной мебели (1,7 м), ровный пол (разброс высот < 0,12 м по шести точкам), отсутствие стен по лучам и крышу над точкой того же здания; запасной вариант — ближайшая ходимая точка вне допустимого, иначе первая точка этажа.
- **Синхронизация** (`terminalSync`, из `reconcile`): удаляет рабочие места баз, которых нет; достраивает недостающие (повтор раз в 30 с).
- **Клиент:** `desktopTick` каждые 0,25 с навешивает на каждый зарегистрированный монитор действие (приоритет 2, радиус 3,5 м, условие `terminalCanUse`); открытый экран закрывается сам, если право пропало; состояние, деньги из `ALS_money` подмешиваются на клиенте; опрос `status` раз в секунду.
- **Окно** (`desktopOpen`): `RscDisplayEmpty` поверх экрана 46, веб-контрол `ALS_RscPhoneWeb` (IDC 7410), страница `\alspmc_core\ui\desktop.html`; обработчик JSDialog обслуживает `alspmcDesktop` (`ready`, `close`) и `alspmc` (пересылка в `phoneMsg` с указанием компьютера). Телефон при открытии ПК закрывается. «Осмотреть» с ПК — своя орбитальная камера (`desktopView` заменяет штатный PFH `propView`, закрывается вместе с окном); «Обставить» закрывает окно и открывает штатный `furnOpen`.
- **Одна реализация для двух интерфейсов:** `desktopDo` = проверка физического доступа + тот же `phoneDo`; общее состояние (`phoneSync`) плюс поля `terminalKey`/`valid`.

## 8. Телефон: мост, диспетчеры, состояние

- **Клиент → сервер** (`phoneMsg`): операции `questMap`, `mark`, `furnish`, `view` — **локальные** (открыть карту, поставить маркер базы, камера, мебель); для `mark/furnish/view` ключ должен быть в списке баз состояния игрока. Операции `status, license, name, base, lock, unlock, sell, questStart, questCancel, questReady` отправляются `remoteExecCall` на сервер (`phoneDo` или, с ПК, `desktopDo`). Остальные значения `op` игнорируются.
- **Сервер** (`phoneDo`): токен — целое `0…10⁹`; `switch` по операциям; после любой операции — `phoneSync [юнит, токен, результат]`.
- **Сборка состояния** (`phoneSync`): `licensed`, `name` (байты), `canRename`, `licensePrice`, `clerkNear`, `bases` (только доступные игроку: свои и компании; поля `key, town, grid, pos, name, price, locked, canSell, near`), `hasOwnBase`, `nearby` (до 8 свободных `Industrial` в 40 м из `ALSPMC_industrialKeys`, если собственной базы нет), `basePrice`, `reply`, `ok`, `quests`. **Периодический опрос не затирает подтверждение действия** — при `reply = 0` берутся прежние `reply/ok`.
- **Доставка:** `stateSet` игроку; на клиенте `clientTick` подмешивает актуальные деньги и вызывает `ALSPMCPhone.set(json)` только при изменении JSON. Состояние подмешивается в страницу телефона всегда, пока телефон открыт и мост установлен; а **серверный опрос `status` раз в секунду** выполняется только когда открыто именно приложение «ЧВК» (`ALS_phone.view == "alspmc"`).
- **Сообщения:** `message [ключ STR_ALSPMC_*, аргументы]` → системный чат + `notice` в окне ПК/телефона (байты UTF-8 `toArray`) либо `hint`.

## 9. Интерфейс `phone.js` и `desktop.html`

- Приложение регистрируется штатным `app({id:"alspmc", …})`; разметка и стили инжектируются в страницу; у корня выставлены `data-noi18n`/`data-ru-ignore` — приложение уже русское и обходит переводчики страницы. Те же функции работают в окне ПК (`ALSPMCDesktop`).
- **Запросы:** `request(op, extra)` → `busy = {op, token}`, кнопки блокируются, отправка `{a:"alspmc", op, token, …}`; ответ распознаётся по `next.reply === busy.token`; **таймаут 10 с** → сообщение «Ответ сервера задерживается. Обновите статус перед повторным действием».
- **Подтверждения** (`showConfirm`): лицензия, база, продажа, принятие и отмена контракта показывают карточку с «Подтвердить/Отмена».
- **Название:** поле с черновиком; кнопка доступна при 3–40 символах и изменении; на сервер уходит `Array.from(new TextEncoder().encode(draft))`.
- **Контракты:** вкладки «Доступные / Активный / История»; категории «Государственные/Частные»; для штурма базы — список целей (`targets`: id, название-байты, владелец, квадрат) и «Случайная база»; ключ принятия — `билет` или `билет|id базы`. Подписи типов и причин зашиты в JS на русском (не в `stringtable`).
- **Жёстко заданные в странице числа** (не из конфига): описания «3–5 человек … 15–25 пехотинцев»; «Всего минимум 6 предложений»; «10 реальных минут» охраны; «не более 4 участников».

## 11. Планирование и запуск контракта

**Принятие** (`questDo "questStart"`, сервер, атомарно): токен → кэш идемпотентности; `questState.canStart` (причины отказа: контракты недоступны, нет лицензии, нет базы, не лидер группы, у группы уже есть задание, состав > 4, у кого-то из группы розыск со стрельбой — игрок на стороне `east`, активный контракт уже есть); билет должен быть в личной доске; для старого «eliminate» принимается только при недоступном каталоге; уровень ≥ минимального; **план** (`contractPlan`) — иначе «нет подходящего места».
**Группа:** если у игрока нет группы, создаётся однопользовательская (`ALS_crews`, схема штатного `crewDo`) и помечается `alspmcCreatedCrew` (будет удалена по окончании, если в неё никто не вступил). В группу добавляется предложение, затем **штатный `coopAccept`** создаёт работу, вызывает сценарий `start`.
**Запись в журнале:** `[основатель, "starting"→"active", награда, позиция, состав (онлайн-участники группы), дата начала, [], ""]`.

**План** (`contractPlan`; реальная расстановка — по правилам):
- полевые режимы (`bandits, enemyPatrol, sector, mines`): `questSite` — до 64 попыток: точка на расстоянии `questMinDistance…questMaxDistance` (600–6000) от игрока, ровное место (`flatSpot`), не ближе 2 км + 100 м от базы, без игроков в 250 м и пехоты в 100 м;
- остальные: объект из реестра по правилу категории/режима (см. 10), не ближе 250 м к уже занятому другим контрактом, до 31 кандидата со случайным смещением; для охраны нужна внутренняя точка этажа; для штурма — выбранная база (`assaultBase` + выбор игрока) и её владелец запоминается;
- конвой/VIP: пункт назначения ≥ 1000 м от старта, другой источник; у государственного конвоя назначение — армейский пост или государственный объект; для конвоя дополнительно подбираются дорожные позиции (`warRoadSpot`) и конец маршрута на дороге (`roadNear`, 250 м);
- патруль по точкам: от 3 до 8 точек (по умолчанию 4) на 200–320 м от центра, не ближе 100 м друг к другу и 2 км+ от базы;
- **итоговая проверка:** все итоговые позиции (центр, точки, назначение, точка грузовика, внутренняя) ≥ 2 км от базы, иначе план отвергается.
**Расстояние от базы** (`contractFar [база, поз, запас]`): `distance2D ≥ max(contractMinBaseDistance, 2000) + запас`; база берётся у **основателя** (`contractBase`), а не у принявшего.

## 12. Ход контракта по режимам

Общее (`contractScenario`): `start` проверяет запись журнала («starting», тот же основатель и состав), создаёт реестры задания (`alspmcObjects/Groups/Enemies/Mines/Casualties/Roster`), решает по шансу `contractAttackChance` (0,65), будет ли засада (`alspmcAttackPlanned`), задаёт радиус сектора (мины 75 м, иначе `contractSectorRadius` ≥ 100), длительность охраны; начальное состояние: бой/штурм/патруль-атака — сразу `combat`, остальные — `rendezvous`. `tick` → `contractTick` (раз в тик `coopTick`). `end` — удаляет **только свои** объекты/группы, снимает аренду базы и враждебность.

| режим | старт | условие успеха | условие провала |
|---|---|---|---|
| `bandits` | сразу бой: отряд у цели (`contractAttack`) | убиты все назначенные противники | весь состав мёртв одновременно (`wiped`); потерян объект противника (`site`) |
| `enemyPatrol` | то же, отряд 3–10 с экипажем; пикап/машина с шансом 50 % (вооружённый на уровне ≥ 4) | то же | то же |
| `base` | аренда выбранной базы (`contractGarrison`): штатная охрана удаляется, создаётся гарнизон 15–20 (ур. 4) / 20–25 (ур. 5) | убиты все | `wiped`; смена владельца базы за время операции (`site`) |
| `convoy` | `rendezvous` в пределах `contractReadyRadius` (150 м) от старта; готовность подтверждает основатель; появляются грузовик `C_Truck_02_transport_F` с гражданским водителем и декоративным грузом, едет `aiDrive` 45 км/ч | грузовик в 100 м от пункта назначения | грузовик уничтожен/пропал (`truck`); для государственного — смена владельца поста (`site`) |
| `guard` | `rendezvous` у здания; готовность → гражданин `C_man_1` внутри здания (движение отключено); охрана `contractDutySeconds` (600 с) | прошло время охраны | защищаемый погиб/пропал (`protected`) |
| `vip` | готовность → гражданин (`C_Man_formal_1_F` и др., костюм) вступает в группу Arma лидера; назначение — вторая точка | VIP в 60 м от назначения и участник в 200 м | VIP погиб/пропал |
| `sector` | готовность → маршрут из N точек по порядку | все точки пройдены (радиус 35 м, 10–75) | `wiped` |
| `mines` | `travel` → при входе в 75 м от центра: с шансом 0,8 появляются 3–6 мин `APERSMine` (20–65 м от центра, ≥ 25 м от игроков), обследование ≥ 60 с | нет активных мин и обследование прошло | `wiped`; не удалось разместить (`spawn`) |
- **Засада** (`contractAttack`): отряд создаётся на стороне `east`, класс бойцов — из `ALS_factions["Gangs"]["men"]` (запасной набор бандитов LifeSim), 3–25 человек по уровню; все с `addRating 10000`, `HandleRating → 0`, не captive; `ALS_hitSquad` и `ALS_hostile` (убийство таких ботов не караемо в оригинале, 21.3); если создать не удалось — откат и контракт не принимается/засада пропускается. Условия запуска: охрана — после `alspmcAttackAt` (60–480 с после готовности); патруль — после первой точки; конвой/VIP — через ≥ 30 с и после прохождения ≥ 30 % пути. Точка появления: 160–280 м от цели, ≥ 60 м от игроков, ≥ 2 км от базы.
- **Снаряжение** (`contractEquip`, `contractAssets`): бойцу выдаётся одно оружие и 6 магазинов; пул — установленные классы 3CB (`uk3cb…`) и RHS (`rhs…`) без подствольников и прочих «muzzle» (по ведрам: пистолеты, ПП, винтовки, пулемёты/снайперские), либо ванильные запасные комплекты по уровню (`hgun_ACPC2_F`, `SMG_02_F`, `arifle_MX_F`, `LMG_Mk200_F`, `srifle_EBR_F`, …); навык `0,2 + 0,08·уровень`.
- **Враждебность** (`contractHostility`): противники всегда на **`east`**. На время контракта `east` делается враждебной сторонам участников (`civilian` и `west`, если у участника штатная сторона `west`) — по направленным `setFriend` с запоминанием прежних значений и восстановлением при отсутствии аренды; стороны `resistance` и `east` игроков не затрагиваются. Каждый тик ближайшему живому участнику/цели в 500 м каждому противнику выдаются `reveal/doTarget/doFire`.
- **Мирное зеркало:** `contractMirror` публикует игрокам-участникам `ALS_coopJob` (название, стадия, статус, прогресс, позиция, цель, сектор) и `ALS_sideNav` (цель и назначение); клиентский `questMarker` каждые 0,25 с ставит локальные маркеры цели, пункта назначения и эллипс сектора.

## 13. Завершение и оплата (`contractEnd`)

Вызывается из штатного `coopTick`/`coopEnd`. Для не-контрактов делегирует оригиналу.
1. Атомарный блок; задание из `ALS_coopJobs`, совпадение `alspmcQuestId`, ещё не заканчивается.
2. Причина: результат сценария; если в группе нет подключённых участников — `empty`. Пустая причина — выход (**поддельный результат/доля из чужого вызова не завершит контракт**).
3. Запись журнала должна быть `active`, метаданные на месте.
4. **Выплата:** при `complete` — награда из записи журнала **один раз** (`meta[3] == 0`) в **банк основателя** `moneyAdd [uid, 0, награда]` с проверкой, что банк вырос ровно на сумму; при неудаче платежа окончание откладывается (повторяется в следующем тике). Опыт основателя += опыт типа (≤ 10⁸).
5. Статус записи: `done` / `cancelled` / `interrupted` (причины `site`, `spawn`, `empty`) / `failed`; конец сценария (удаление объектов, снятие аренды, возврат враждебности).
6. Сообщения всем из состава и группы; очистка `ALS_coopJob`/`ALS_sideNav` **только у тех, у кого зеркало принадлежит этому контракту**; удаление работы и сброс `job` группы (`offersAt = -1e9`); удаление одно-членной группы, созданной аддоном; обновление доски основателя (успех — другой тип, провал/отмена — тот же); `crewPublish`; `questSave`; `dbSave`.
Опыт при провале, отмене и техническом прерывании не начисляется; денежных штрафов нет.

## 14. Прежний тестовый контракт «eliminate» (0.4.0)

Остался как запасной вариант. Принимается только пока каталог недоступен (иначе — отказ, чтобы не обходить доску). Один боец `O_G_Soldier_F` на стороне `east`, 600–6000 м от игрока (точка `questSite`), 1800 с, общий фонд `questPay` (1000 €) — **выплачивается штатным `coopEnd`** (делится по правилам оригинала, а при `jobsTo` — в компанию). Зачёт убийства: убил участник состава, остающийся в группе (`outsider` — иначе). Метки цели: `ALS_hitSquad`, `ALS_hostile`, `HandleRating → 0`.

## 16. Наблюдения при чтении (ничего не исправлялось)

Степень уверенности: **В** — следует из чтения кода и оригинала; **С** — подтверждено журналом RPT/игрой в прошлых проверках; **Г** — гипотеза.
| № | Наблюдение | ув. |
|---|---|---|
| A1 | **Токены запросов не переживают число формата float32.** Клиент выбирает токен до 9·10⁸, а числа SQF — 32-битные float (точные целые только до 16 777 216): сервер возвращает округлённый токен в `reply`, строгое сравнение `next.reply === busy.token` не срабатывает, кнопки освобождаются только по таймауту 10 с. Серверная идемпотентность (`questDo`) работает, т. к. сравнивает уже округлённые значения. | В |
| A2 | **Утечка `ALS_sideNav` после выхода из группы.** `crewDo "leave"` + `crewPublish` очищают `ALS_coopJob` у вышедшего, но не `ALS_sideNav`; `contractMirror` обновляет только текущих участников; `contractEnd` очищает `sideNav` лишь при совпадении зеркала `alspmcQuestId`, а у вышедшего оно уже `nil` — навигационные значки остаются, локальные карточные маркеры (`questMarker`) исчезают. `playerCarry` оригинала переносит `ALS_sideNav` на нового юнита после респауна. | В (совпадает с наблюдением игрока при выходе из группы) |
| A3 | **`contractWarBases` возвращает `_out`, равный результату нативной `warBases`; если та ничего не возвращает, последнее выражение читает неопределённую переменную** → ошибка `Undefined variable in expression: _out` в журнале (строка 24 файла). | С |
| A4 | **Убитый водитель конвоя остаётся в кабине, автопилот продолжает «водить».** Тик лишь выставляет `alspmcDriverDead`; труп не убирается и `drvStop` не вызывается до конца контракта; заменить водителя можно только вручную (ACE). | В |

В игре аддон работал без блокировки вызовов оригинала; поведение при отсутствии `mode` в справке Arma не перепроверялось. | Г |
