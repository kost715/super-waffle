# PMC Arsenal 0.3.1 alpha 1

Отдельный мод ограниченного арсенала. Любой объект с инвентарём (ящик, машина)
открывает общее хранилище. Склад ведёт сервер и сохраняет его между рестартами.
Интерфейс взят из Jeroen (Not) Limited Arsenal (Antistasi Ultimate, MIT).

Зависимости: Arma 3 (2.14+) и CBA_A3 (настройки мода). LifeSim и Antistasi не
нужны. ACE, TFAR и ACRE мод находит сам, если они загружены.

## Установка

1. Распакуйте `dist/PMC_Arsenal_0.3.1_alpha1.zip`. Папка `@PMC_Arsenal` нужна и
   на сервере, и у игроков.
2. Если миссия ограничивает удалённый вызов (`CfgRemoteExec`, `mode = 1`),
   добавьте в `description.ext` миссии функции из `config.cpp` мода, раздел
   `CfgRemoteExec`. Список миссии заменяет список мода.

## Как сделать арсенал

**В редакторе Eden.** Выберите объект с инвентарём. В атрибутах объекта откройте
раздел «PMC Arsenal» и впишите «Storage ID», например `base`. Объекты с одинаковым
ID открывают одно и то же хранилище.

**Модулем Eden.** Поставьте модуль «Системы → Модули → PMC Arsenal → Хранилище арсенала», впишите
в нём «Storage ID» и синхронизируйте модуль с ящиками или машинами. Все они станут
арсеналами этого хранилища. Синхронизированные юниты и другие модули пропускаются.

**Скриптом (только на сервере):**

```sqf
[_box, "base", [
    ["items", [["arifle_MX_F", 10], ["30Rnd_65x39_caseless_mag", 40], ["FirstAidKit", -1]]],
    ["categories", ["weapons", "equipment"]],
    ["persistent", true]
]] call PMCA_fnc_registerStorage;
```

- `items` — начальный склад. Применяется только к новому хранилищу; если
  хранилище уже загружено из сохранения, его склад не меняется. Оружие, предметы
  и рюкзаки считаются штуками, магазины — магазинами (внутри хранятся патроны).
  `-1` — без ограничения.
- `categories` — категории, из которых можно брать: `weapons` (оружие, обвесы,
  магазины), `launchers`, `explosives` (гранаты, мины, заряды), `equipment`
  (одежда, разгрузки, рюкзаки, приборы, медицина, инструменты). Пустой список —
  все категории. Вернуть на склад можно любой предмет.
- `persistent` — `false`: хранилище живёт только до конца миссии.

## Настройки CBA

Меню «Настройки» → «Настройки аддонов» → «PMC Arsenal». Действуют значения сервера.

| Настройка | Значения |
|---|---|
| Режим отладки | Выкл. (по умолчанию) / вкл. — см. ниже |
| Бесконечно с количества | Никогда (по умолчанию) / 5 / 20 / 50 |
| Кто может брать | Все, все категории (по умолчанию) / по сторонам |
| Доступ: BLUFOR, OPFOR, INDFOR, Гражданские | Галочки «Оружие, обвесы, магазины», «Гранатомёты», «Гранаты и взрывчатка», «Одежда и снаряжение» (по умолчанию все отмечены) |

- **Бесконечно с количества.** Когда предмета на складе набирается столько штук,
  он становится бесконечным навсегда. Магазины считаются полными магазинами:
  120 патронов к 30-зарядному магазину — это 4 магазина. «Никогда» означает, что
  все предметы конечны, кроме загруженных через отладку. Новое значение сразу
  применяется к уже накопленному складу.
- **По сторонам.** Сторона определяется по группе игрока. Возвращать на склад можно
  всегда. Сторона без отмеченных категорий арсенал не открывает. Права, заданные
  хранилищу (`categories`) и `PMCA_accessHandler`, дополнительно сужают доступ.

## Режим отладки и модуль Зевса

- Новые хранилища создаются пустыми: начальный склад `items` не применяется.
  Склад, сохранённый раньше, загружается, и все изменения сохраняются как обычно.
- Зевс ставит модуль «PMC Arsenal → Загрузить ящик в арсенал (отладка)» на любой
  ящик или машину. Если в 100 м есть арсенал, всё содержимое ящика (включая обвесы,
  форму, разгрузки, рюкзаки и их содержимое) становится бесконечным в ближайшем
  арсенале. Ящик остаётся как был. Зевс получает сообщение, сколько предметов
  загружено и в какое хранилище.
- Ящик можно заполнить чем угодно: например, сложить в него снаряжение,
  набранное в ACE-арсенале, или заполнить редактором инвентаря Zeus Enhanced,
  если он установлен.
- Если режим отладки выключен, модуль ничего не делает и сообщает об этом.

## Инвентарь самого объекта-арсенала

Кроме склада сохраняется обычный инвентарь объектов-арсеналов (как в скриптах
saveBox/loadBox): сервер проверяет его каждые 30 секунд и записывает при
изменениях и в конце миссии (`PMCA_boxes_v1`).

- Сохраняются неполные магазины, оружие с обвесами, форма, разгрузки и рюкзаки
  вместе с содержимым.
- После рестарта инвентарь восстанавливается при старте миссии и заменяет
  содержимое, заданное в редакторе. Если записи ещё нет, остаётся содержимое из
  редактора.
- Запись привязана к ID хранилища и порядку объектов (`base#1`, `base#2`, ...).
  Если добавить или удалить объекты этого хранилища в миссии, порядок может
  сдвинуться.
- Уничтоженный объект сохраняет последнюю запись. Объекты хранилищ с
  `persistent = false` не сохраняются.

## Редактируемый файл склада

Склад можно задать обычным текстовым файлом `pmc_arsenal_stock.txt`. Шаблон с
описанием формата лежит в архиве мода: `@PMC_Arsenal/userconfig/pmc_arsenal_stock.txt`.

**Где сервер его ищет** (берёт первый найденный):
1. `<папка Arma 3>\userconfig\pmc_arsenal_stock.txt`, если сервер запущен с
   параметром `-filePatching`. Это удобнее всего: правите файл на сервере и
   перезапускаете миссию, ничего не перепаковывая.
2. `pmc_arsenal_stock.txt` в корне папки миссии (рядом с `mission.sqm`). Если миссия
   запакована в PBO, после правки её нужно перепаковать.

**Формат:**

```
// Комментарии через // можно писать где угодно
[
    ["base", [
        ["arifle_MX_F", 10],                      // штук
        ["30Rnd_65x39_caseless_mag", 40],         // магазинов
        ["30Rnd_65x39_caseless_mag", 2, 17],      // 2 магазина и ещё 17 патронов
        ["FirstAidKit", -1]                       // бесконечно
    ]],
    ["depot", [
        ["launch_RPG32_F", 2]
    ]]
]
```

**Как применяется:**
- После рестарта миссии сервер применяет файл, если его изменили с прошлого
  применения. Каждое хранилище из файла получает ровно этот склад, хранилища, которых
  в файле нет, не меняются.
- Неизменённый файл повторно не применяется: всё, что игроки взяли и сдали,
  сохраняется в профиль как обычно. Чтобы снова выставить склад из файла, измените в
  нём что-нибудь (хотя бы комментарий).
- Если в файле ошибка, он не применяется, склад не меняется, а причина пишется в
  RPT сервера. Строки с неизвестным классом или неверным количеством пропускаются
  (тоже с записью в RPT).
- Файл не обновляется сам: Arma не умеет записывать файлы. Текущий склад сервер в
  конце каждой миссии пишет в RPT в формате файла, между строками
  `stock file begins` и `stock file ends`. Его можно скопировать в файл и править
  дальше. Выгрузить склад в любой момент: `call PMCA_fnc_exportStock` в консоли
  отладки (Server Exec). У хостящего из игры текст сразу попадает в буфер обмена.

## Функции для сервера

| Функция | Что делает |
|---|---|
| `[id, [[class, amount], ...]] call PMCA_fnc_storageAdd` | Добавляет на склад. Возвращает число принятых строк. Неизвестные классы и дробные количества пропускаются. |
| `[id] call PMCA_fnc_storageItems` | Склад как `[[class, amount], ...]`. Магазины в патронах, `-1` — без ограничения. |
| `call PMCA_fnc_save` | Сохраняет немедленно (обычно не нужно). |

Права игроков задаёт переменная на сервере:

```sqf
PMCA_accessHandler = {
    params ["_unit", "_storageID"];
    // Вернуть список категорий или false (арсенал не откроется)
    if (_storageID == "base" && {rank _unit == "PRIVATE"}) exitWith {["equipment"]};
    ["weapons", "launchers", "explosives", "equipment"]
};
```

Итоговые права — пересечение категорий хранилища и ответа обработчика.

## Как играть

- **Арсенал** (действие на объекте, до 5 м): обычный Virtual Arsenal. Видно
  только то, что есть на складе. Изменения склада применяются при закрытии.
- **Кнопка «Из ящика»** (на месте «Случайно») перекладывает на склад всё, что
  лежит в инвентаре самого объекта-арсенала.
- **Арсенал для ящика или машины**: действие на объекте, затем наведите прицел на
  контейнер в пределах 50 м. Пока он открыт, инвентарь контейнера заблокирован
  для всех.
- Если склада не хватило, игрок получает сообщение, а снаряжение (или
  содержимое контейнера) возвращается к моменту открытия.

## Как сервер защищает склад

- Сервер запоминает, что видит сам при открытии: снаряжение игрока
  (`getUnitLoadout`) или содержимое контейнера.
- При закрытии он сравнивает это со своим текущим видом и с тем, что прислал
  клиент. Для каждого предмета считается большее из двух: клиент может только
  увеличить списание или уменьшить возврат. Ложный «возврат» склад не пополняет.
  Предмет, выброшенный до того, как сервер его увидел, всё равно списывается.
- Чужие клиенты видят выбор сразу, но это только отображение. При закрытии сервер
  поправляет счётчики у всех.
- При выходе игрока его взятое списывается по виду сервера. Открытый контейнер
  возвращается в исходное состояние.
- Сохранение: `PMCA_storages_v1` (склад) и `PMCA_boxes_v1` (инвентарь объектов)
  в профиле сервера, каждые 30 секунд при изменениях и в конце миссии.
  Повреждённые данные не загружаются и не перезаписываются, а сохранение в этой
  сессии отключается (см. RPT сервера).

## Ограничения alpha 1

- **В Arma не запускался.** Логика сервера проверена в SQF-VM (`tools/check_arsenal.py`,
  110 проверок), но интерфейс, сеть, инвентарь движка, CBA и модули там подменены.
- Оружие с обвесами из контейнера при откате возвращается без обвесов: обвесы
  кладутся отдельными предметами.
- Предметы мода, который больше не загружен, остаются в сохранении, но в
  арсенале не показываются.
- Гаража нет. Его код (лицензия APL-ND) не используется, пока нет разрешения
  автора.

## Сборка и проверка

```
python3 tools/check_arsenal.py --vm /путь/к/sqfvm
python3 tools/build.py
```

Нужен SQF-VM (github.com/SQFvm/runtime). Сборка использует только стандартную
библиотеку Python. Готовый архив появится в `dist/`.
