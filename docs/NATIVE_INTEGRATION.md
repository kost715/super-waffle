# Дополнение 0.7.1: исправления совместимости

- **`ALS_fnc_careerRestart`.** Обёрнута так же, как `ALS_fnc_houseSell`: записи ЧВК
  очищаются, затем без изменений вызывается оригинал.
- **`ALS_npcSpots`.** Аддон только сокращает `deadAt` у постов, чьих NPC убили
  противники контракта; возрождение выполняет `fn_npcLoop` LifeSim.
- **NPC-заложники.** Сдаются через `ace_captives_fnc_setSurrendered`, как это делает
  сам LifeSim; без ACE — `setCaptive`. Затрагиваются только юниты с `ALS_npc`,
  которых LifeSim не держит пленными.
- **Защитники баз.** Отряды EAST с `ALS_defender` (`fn_warArms.sqf`) на время
  контракта переходят на RESISTANCE с теми же отношениями (`fn_lawInit.sqf`).
- **Новые необязательные ключи БД.** `alspmc_quest_companies_v1` и
  `alspmc_player_names_v1`.

# Интеграция с LifeSim 0.13.0 / 0.10.1

Аддон не включает исходный код или ресурсы LifeSim/A3M и не заменяет их PBO.
Обязательная зависимость конфигурации: `CfgPatches/als_main`.

| Этап | Штатный механизм |
|---|---|
| Регистрация лицензии | Дополнение `ALS_Licenses`; штатные `licInit`, `licPush` |
| Покупка лицензии | Приложение вызывает штатные `licBuy`, `moneyPay`, `licGrant` у клерка |
| Выбор базы | Ближайшие `ALS_houses`, тип `Industrial`, `ALS_reserved`, радиус 40 м |
| Проверка оплаты | `moneyGet`, `moneyPay`, при отказе `moneyAdd` |
| Регистрация собственника | `houseClaim`, `housePublish`, `ALS_owned` |
| Склад | `bizGet` с обычным назначением `Warehouse`, `bizPublish` |
| Хранение назначения базы | `dbGet`, `dbSet`, `dbLoading`, `dbSave` |
| Продажа | Обёртка вызывает сохранённую оригинальную `houseSell` |
| Телефон | Штатный JS-реестр `app`, один диспетчер `JSDialog` с передачей нативных сообщений исходному `phoneMsg` |
| ПК на базе | Отдельный веб-контрол; тот же `phoneDo` через `desktopDo` с проверкой доступа к терминалу |
| Название ЧВК | Отдельный ключ `alspmc_names_v1` в той же БД, массивы UTF-8 байтов |
| Контракты | Исходные `crewOf`, `crewPublish`, `coopAccept`, `coopTick`; собственный сценарий `alspmc_contract` |
| Цели и результат | Серверный `EntityKilled`, штатные признаки враждебности, реальное время, узкая обёртка `coopEnd` |
| Места и движение | `ALS_war`, `ALS_warGar`, `ALS_houses`, `ALS_map`, `houseFloor`, `warRoadSpot`, `roadNear`, `aiDrive`, `drvStop` |
| Выплата | Штатный `moneyAdd` в личный банк основателя, без деления и `company.jobsTo` |
| Журнал и рейтинг | `alspmc_quests_v1`, `alspmc_contracts_v1` текущего мира/слота, без изменения версии БД |
| Смерть, смена тела | Приложение подключается к каждому новому экземпляру телефона |
| Переподключение | JIP-переменные и штатные лицензии/собственность игрока |

Лицензия добавляется одной новой записью `alspmc_pmc`, без изменений существующих.
`covers` пуст: она не выдаёт право на покупку оружия или военной техники.
Поддельные лицензии не считаются разрешением на открытие ЧВК.

Таблица `ALSPMC_bases` имеет вид `propertyKey -> [founderUID, marketValue, pricePaid]`.
Для сохранения используются обычные массивы пар, понятные сериализации LifeSim.
Новый ключ `alspmc_bases_v1` не меняет версию исходной БД. Сначала загружается
штатная БД, затем база аддона. Неизвестные ключи LifeSim сохраняет при отключённом
аддоне. При некорректной записи покупки блокируются, прежняя запись на диске
защищается штатным `dbLoading`.

Покупка базы исполняется на сервере в `isNil { ... }`, без переключения планировщика.
Клиент передаёт объект своего персонажа и ключ здания. Сервер сам получает UID,
проверяет отправителя, действительную лицензию, тип, расстояние, запрет продажи,
свободное владение, уже имеющуюся базу и баланс. При неудачной регистрации
собственности деньги возвращаются с тем же разделением на наличные и банк.

Для тестовой цены стоимость только зарегистрированных баз в `ALS_houses` заменяется
на фактически уплаченную. Это согласует штатный телефон, аренду и продажу. В
`ALSPMC_bases` остаётся исходная стоимость. Обёртка `houseSell` выполняет исходную
функцию, а при успехе атомарно снимает назначение и восстанавливает стоимость.
Продажи обычных объектов целиком передаются оригиналу. Периодическая сверка
снимает запись, если внешняя система удалила собственность.

Изменяются собственный класс лицензии, стоимость конкретной приобретённой
базы и указатели узких серверных обёрток продажи/завершения операции в текущем запуске. Действующий завод или
магазин другого игрока не переклассифицируется. Оригинальные файлы не редактируются.

Лицензионный браузер получает узкую обёртку `lic.set`, которая скрывает только
`alspmc_pmc`: оформление перенесено в приложение телефона. Остальные записи,
команды `buy`, стоимость и наличие лицензий не меняются.

Файлы исходного телефона не заменяются. На готовой странице вызывается исходный
`app({...})`, добавляется один значок и экран. Начиная с 0.3.1, первый штатный
`JSDialog`-обработчик контрола (ID 0 в LifeSim 0.10.1) заменяется одним диспетчером:
он принимает `a: alspmc`, а все остальные исходные сообщения передаёт сохранённой
функции `phoneMsg`. Её указатель остаётся прежним; остальные обработчики не удаляются.
Сервер `phoneDo` проверяет владельца запроса
и передаёт операции исходным функциям; клиентские названия, цена или владение
не используются как доказательство права на покупку/управление.

Состояние `ALSPMC_phoneState` содержит числовые массивы UTF-8 для имён и населённых
пунктов. Входящее название проверяется на сервере, включая длину в символах,
корректность UTF-8, управляющие и невидимые символы. Оно принадлежит UID отправителя;
клиент не передаёт UID другого основателя. Названия не изменяют исходный формат
`alspmc_bases_v1`. Отсутствующий ключ названий в прежнем сохранении означает пустую
таблицу, без миграции или повторной покупки базы.

Сборщик превращает не-ASCII символы JS в Unicode-escape. Названия выводятся через
`textContent`, пользовательский ввод не вставляется в HTML. Экран помечен
`data-ru-ignore`, чтобы переводчик RU beta 3 не менял пользовательское название,
например английское `Legacy`. Фоновые обновления меняют существующие поля и
сохраняют фокус и черновик названия. Последнее подтверждение команды хранится
при фоновом опросе, чтобы быстрые ответы сервера не терялись между кадрами клиента.

В 0.6.0 обновлены [десять контрактов](CONTRACTS_RU.md). `coopAccept`, `coopTick`
и `ALS_fnList` не заменяются. Регистрируется серверный указатель
`ALS_fnc_coopJob_alspmc_contract`; исходный тикер вызывает его по `kind`.
Старый `alspmc_eliminate` оставлен для совместимости, но скрыт из нового каталога.
Отсутствие новых записей в `ALS_fnList` сохраняет штатные предложения и их минимум
в два игрока; только предложение ЧВК допускает одного.

У новых контрактов вся награда принадлежит основателю. Поэтому `coopEnd` обёрнут
через сохранённую `ALSPMC_nativeCoopEnd`: остальные виды заданий, включая старый
тест, получают прежнюю функцию с теми же аргументами и возвращаемым значением.
Только задание с меткой `alspmcContract` закрывается собственным `contractEnd`.
Он заново находит каноническую запись сервера по временному ID и постоянному qID,
проверяет незакрытый журнал, квитанцию и серверный результат. Входящий `share`
не является доказательством успеха. Выплата выполняется через native `moneyAdd`
с `cash=0` и `bank=reward` для UID основателя, независимо от убийцы и `jobsTo`.
Повторное завершение защищено состоянием и блокировкой `alspmcEnding`.
Кошелёк, очки, квитанция и журнал сохраняются одним вызовом `dbSave`; поверх
этого не вызывается нативная выплата и не платится второй раз.

Одиночная группа регистрируется тем же форматом и счётчиком, что в `crewDo`.
После контракта она остаётся штатной группой: можно пригласить игроков или выйти
через обычное приложение. При неудачном запуске удаляется только созданная для
этого запроса группа, возвращаются её исходные предложения. Действующая группа
пользователя никогда автоматически не расформировывается.

Клиент передаёт только имя операции, ключ контракта/экземпляра и токен. Позицию,
награду, доступ, состав, таймер и факт убийства определяет сервер. Недавние
токены действий запоминаются; повторный пакет не создаёт операцию заново.
Готовность сверяет расстояние, стадию, лидерство, исходный состав и живой объект
игрока. Отдельная операция VIP возвращает существующего НПС в новую реальную
группу возродившегося лидера поблизости, без повторного спавна. Пакеты телефона
и физически авторизованного ПК попадают в один контроллер.

Серверный `EntityKilled` фиксирует гибель назначенных целей до удаления тела,
а также факт одновременной гибели всего состава до возможного быстрого respawn.
При `contractPermanentCasualties=0` новый живой объект участника снова учитывается.
Новые зачистки не требуют, чтобы последний выстрел сделал конкретный член группы.
Для старого теста прежняя проверка убийцы остаётся без изменений.

Дежурство и обследование используют `diag_tickTime`, даты истории — `date`.
У конвоя водитель может погибнуть: условие поражения проверяет грузовик. Охрана
и VIP проверяют своего защищаемого НПС. Маршрут учитывает очередную точку,
посещённую живым участником. Бой/маршрут/мины проверяют гибель состава.
Штатный тикер продолжает прерывать задания опустевших групп.

Каталог мест читает реестры оригинала. Здания не резервируются/перепродаются.
Рейд может выбрать Military или Opfor из настоящих `ALS_war.bases`, кроме Players;
включённая война больше не обязательна. Выбор ID проверяется серверным планировщиком.

`contractGarrison` арендует только выбранный ID, удаляет охрану из его `ALS_warGar.grp`
и создаёт собственный масштабированный отряд без `ALS_army`. Это не вызывает
нативную выдачу преступлений/QRF за контрактные цели. Узкая обёртка `warBases`
вызывает сохранённую оригинальную функцию с теми же аргументами, временно исключив
арендованные ID из списка баз внутри несменяемого `isNil`-блока. Затем полный
реестр возвращается и публикуется; остальные базы и возвращаемое значение прежние.
После исхода только свои объекты удаляются, аренда снимается, генератор оригинала
снова получает базу. Владение, supply и постоянные данные командиров не переписываются.

Собственные бойцы имеют положительный рейтинг и `HandleRating -> 0` вместо
`addRating -100000`. Явное `joinSilent` нормализует сторону модовых классов.
Hostility выбирает боевую сторону, отличную от сторон подключённых игроков,
и отслеживает изменение стороны через штатный розыск/respawn. Переносятся только
собственные боевые группы, не группа игрока/VIP. `getFriend/setFriend` направлены
от выбранной стороны к сторонам игроков; значения сохраняются с общими ссылками
на использующие их операции и восстанавливаются после последней.
Так как отношения в Arma общие для стороны, их действие распространяется и на
других ИИ этой стороны на время аренды; это требует проверки реакции мировых НПС.
Обратные отношения, рейтинги, captive и розыск игроков не меняются.

`contractAssets` читает `ALS_factions.Gangs.men`, как штатный `gangTick`;
ключ кэша зависит от набора классов. Классы противников не выбираются независимо
по префиксу 3CB. Оружие/магазины по уровню обнаруживаются в конфиге 3CB/RHS,
с исключением GL/launchers и ванильным запасным набором. VIP получает костюм.

`contractBase` получает позицию принадлежащей основателю недвижимости.
`contractFar` проверяет минимум 2000 м. `contractSites` фильтрует копию общего
кэша по вызывающему основателю. Планировщик проверяет конечные дорожные,
внутренние и маршрутные позиции; динамический спавн проверяет свои точки отдельно.
Положение базы фиксируется в плане принятой операции.

`contractOffers` держит минимум шесть серверных билетов на UID основателя.
Срок — `diag_tickTime + 600` по умолчанию. Принятый билет заменяется резервным
того же типа; RPC новой операции заблокирован существующим заданием. Резервный
билет сохранён только у серверного job. При завершении он заменяется новым:
случайный тип за успех, прежний тип за остальные исходы. Остальные билеты и срок
не меняются. Истёкший пул обновляется обычным способом; завершение не добавляет
лишний седьмой слот. Поддельный/старый билет и повтор расчёта результата отвергаются.

Штатный renderer приложения Rivals получает узкую защиту строк: некорректные
строки исключаются, пары ключ/значение преобразуются для отрисовки. После вызова
восстанавливаются исходные ссылки состояния; `phone.set`, DOM-диспетчер кликов,
`rivalMark` и `rivalHire` остаются оригинальными. Это защита от проверенного
класса сбоев входных данных, а не подтверждение причины конкретного пользовательского сбоя.

Маршрутный патруль сохраняет ключ `gov_sector`, но использует массив сухих
контрольных позиций и серверный индекс. За один тик учитывается только следующая
точка, посещённая живым участником. Время/выход из прежней области не определяют
результат; метка и штатная навигация следуют за очередной точкой.

Журнал сериализуется как `[1, sequence, [[instanceID, record], ...]]`, где запись —
`[founderUID, status, pay, position, teamUIDs, startDate, endDate, reason]`.
Хранятся последние 20 записей на основателя, в интерфейсе — последние 10
доступных игроку результатов. При запуске сохранённый `active` превращается
в `interrupted`: ссылки на объекты и временные ID групп/миссий не восстанавливаются.
Повреждённый ключ защищается `dbLoading` и блокирует только контракты.

Новый ключ `alspmc_contracts_v1` сериализуется как
`[1, [[qID,[type,level,xpAward,paidAmount]], ...], [[founderUID,totalXP], ...]]`.
Отсутствующий ключ означает чистый рейтинг первого уровня. Метаданные сохраняются
для тех же последних 20 записей основателя. Неизвестная/повреждённая новая схема
блокирует только новые контракты и защищает ключ штатным `dbLoading`; база,
лицензия, имя и ПК не зависят от его успешной загрузки. Живые миссии не возобновляются.

Текст собственного приложения остаётся русским и проходит как ASCII-escaped JS.
Для штатного зеркала `ALS_coopJob`, заголовка и квитанции исходной групповой
системы используются английские ASCII-подписи: оригинальный `phonePush` передаёт
сырой JSON в ExecJS, и изменение его сериализации затронуло бы все приложения.
Указатель HUD и маркер используют локализованное название цели.

Первоначальное обсуждение архитектуры сохранено как исторический документ:
[PMC_QUESTS_DESIGN_RU.md](PMC_QUESTS_DESIGN_RU.md). Актуальное поведение — в
[CONTRACTS_RU.md](CONTRACTS_RU.md).
