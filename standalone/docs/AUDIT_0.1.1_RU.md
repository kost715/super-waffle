# Аудит S1 и исправления 0.1.1 alpha 1

Дата: 26 октября 2026 года. Аудит выполнил Claude по запросу пользователя.
Предмет: технический стенд **S1 0.1.0 alpha 1** из `standalone/`, то есть мод
`pmcs_core`, сборщик `tools/build.py`, три тестовые миссии и тесты.
Результат: версия **0.1.1 S1 alpha 1** с исправлениями ниже.

## Как проверялось

- Прочитан весь код мода: `config.cpp`, `ui.hpp`, 18 функций, `stringtable.xml`,
  оба файла каждой из трёх миссий, сборщик и тесты.
- Исходники в репозитории сверены с присланным `PMC_Standalone_0.1.0_s1_alpha1.zip`:
  содержимое PBO мода и миссий совпадает побайтно.
- Сверены ключи строк, регистрация функций, баланс скобок SQF, корректность XML.
- Запущены `tools/check_repository.py` и `python3 -m unittest` в `standalone/`.
- **Не выполнено:** SQF-VM в среде аудита недоступна, поэтому `tools/check_sqf.py`
  (синтаксис и 69 утверждений транзакций) для 0.1.1 не перезапускался.
  `docs/CHECK_RESULTS.json` относится к 0.1.0. Arma 3 не запускалась.

## Исправлено

### 1. Игроков телепортировало к лагерям при каждом входе в идущую игру — высокая

**Где:** `tools/build.py` генерировал для каждого из 16 слотов поле
`init="this setPosATL [x,y,0]"`.

**Почему ошибка:** поле init объекта выполняется на **каждой** машине, в том числе
у каждого игрока, подключившегося позже (JIP). `setPosATL` действует глобально,
поэтому вход нового игрока перемещал всех уже играющих на их стартовые точки,
где бы они ни находились.

**Как исправлено:**
- Поле стало `init="if (local this) then {this setPosATL [x,y,0]}"`: позицию
  меняет только машина, которой принадлежит юнит.
- `fn_clientInit.sqf`: один раз при запуске клиента, если собственный юнит
  игрока стоит не на земле (высота по ATL больше 0,5 м) и не в технике, он ставится
  на землю. Это страховка для только что вошедшего игрока, если в момент его init
  юнит ещё не был локальным. Чужие юниты не трогаются.
- Тест `test_missions_slots_and_isolation` теперь требует защищённую форму во всех
  16 слотах и запрещает прежнюю.

**Проверить в игре:** пункт 1 игрового чек-листа — один игрок уходит от лагеря,
второй подключается; первый остаётся на месте.

### 2. Сборщик стирал хеши прежних релизов — средняя

**Где:** `tools/build.py` перезаписывал `dist/SHA256SUMS.txt` строками только
текущей версии.

**Почему ошибка:** архивы 0.1.0 остаются в `dist/` как история, но после сборки
новой версии их хеши исчезли бы из списка, и `tools/check_repository.py` перестал бы
их проверять.

**Как исправлено:** сборщик читает существующий список, сохраняет строки файлов,
которые есть в `dist/`, заменяет только строки текущей версии и пишет список
в алфавитном порядке. Хеши 0.1.0 остались прежними.

### 3. Список отношений в консоли перерисовывался каждую секунду — низкая

**Где:** `fn_renderConsole.sqf`. Пока консоль открыта, сервер присылает состояние
раз в секунду, и список очищался и заполнялся заново на каждом ответе: мерцание и
сброс прокрутки.

**Как исправлено:** строки списка запоминаются на окне; список перестраивается
только при изменении данных. Выпадающие списки компаний так уже работали.

### 4. Сторона погибшего тестового бойца в RPT — низкая, укрепление

**Где:** `fn_serverInit.sqf`, обработчик `EntityKilled` писал `side group` убитого.

**Почему:** группа мёртвого юнита может смениться, и тогда в RPT попала бы
неверная сторона. Для разбора стрельбы это основной источник данных.

**Как исправлено:** `fn_resetActors.sqf` при создании бойца записывает его сторону
в `PMCS_actorSide`; лог берёт её. Если переменной нет, используется прежнее значение.

## Проверено, ошибок нет

- Права и подлинность запросов: сервер сверяет отправителя (`remoteExecutedOwner`)
  с владельцем юнита, права администратора, зарегистрированный ПК и расстояние.
- Повтор запроса возвращает прежний результат; изменение со старой ревизией
  отклоняется; идентификаторы запросов строковые, поэтому округление float32
  (ошибка прежнего аддона 0.6.3) здесь невозможно.
- Отношения сторон задаются на сервере в обе стороны; мирные жители всегда
  дружественны; противник мира создаётся только при свободной боевой стороне.
- Сброс удаляет только собственных тестовых НПС и их группы, игроков не трогает.
- Все функции зарегистрированы, все ключи строк определены, XML корректен.
